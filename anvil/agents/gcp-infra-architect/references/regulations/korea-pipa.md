# 한국 개인정보보호법 (PIPA) + 의료기관 가이드라인 — GCP 매핑

> 참조 일자: 2026-04-21 (최신 확인 시 WebSearch 재실행 필수)

---

## 개요

한국의 개인정보 보호 규제는 다층 구조:
- **개인정보보호법(PIPA)** — 일반법, 개인정보보호위원회(PIPC) 관장
- **의료법** — 의료정보 특수 조항
- **의료기관 개인정보보호 가이드라인** — 행안부·복지부 공동 (2020.12 기준, 2026 개정 진행 중)
- **K-HISA (병원정보보안협회)** — 실무 보안 표준
- **2024-2026 개인정보 보호 기본계획** — 클라우드 권한·책임 명확화 가이드 준비 중

헬스케어 데이터는 **민감정보(sensitive information)**로 분류되어 일반 개인정보보다 **엄격한 보호 기준** 적용.

## 주요 법적 요구사항

### 1. 동의 및 수집 목적 제한
- 민감정보 수집 시 **별도 동의** 필수
- 수집 목적 범위 내에서만 처리
- 제3자 제공 시 재동의 원칙

### 2. 국외 이전 (Cross-Border Transfer)
- 개인정보 국외 이전 시 **정보주체 동의** 필수 (개보법 §28)
- **의료정보의 경우 더 엄격** — 사실상 한국 내 저장이 실무 표준
- 국외 이전 시 이전 대상국의 보호 수준·이전 받는 자의 조치 사항을 **사전 고지**

### 3. 안전성 확보 조치 (개보법 시행령)
- 접근 권한 관리 + 접근 통제 시스템
- 비밀번호 관리 + 암호화
- 접속 기록 보관 (1~3년)
- 악성프로그램 방지
- 물리적 접근 통제
- **재해·재난 대비 안전 조치** (백업·복구)

### 4. 정보주체 권리
- 열람, 정정·삭제, 처리정지 요구권
- **개인정보 이동권(데이터 이동권)** — 2024 개정으로 강화

## GCP 매핑

| PIPA 요구 | GCP 구현 |
|-----------|---------|
| 한국 내 데이터 저장 (민감정보) | `asia-northeast3` (서울 리전) 사용 |
| 암호화 at-rest | 기본 암호화 + **CMEK** (Cloud KMS, 서울 리전 키) |
| 암호화 in-transit | TLS 1.2+ + VPC Private Google Access |
| 접근 권한 관리 | IAM + Workforce Identity + **조직 정책** |
| 접속 기록 보관 (1~3년) | **Cloud Audit Logs** + Log Router로 장기 보관 |
| 국외 이전 통제 | **VPC Service Controls** + Organization Policy (리전 제한) |
| 재해·재난 대비 | 동일 국가 내 리전 간 백업 (서울 ↔ 다른 서울 zone, 또는 동일 리전 이중화) |
| 악성프로그램 | Security Command Center + Container Analysis |
| 가명정보 처리 | Cloud DLP API로 익명화·가명화 자동화 |

## 데이터 레지던시 (핵심)

- **의료정보는 한국 내 저장이 사실상 표준** (국외 이전 동의 실무상 어려움)
- GCP 서울 리전(`asia-northeast3`) 사용 권고
- 백업도 서울 리전 내 이중화 (다른 존 활용)
- **PIPC Organization Policy**로 `constraints/gcp.resourceLocations`를 `asia-northeast3`로 강제 설정

### 글로벌 서비스 설계 시 주의

한국 사용자 데이터가 타국 리전으로 흘러가는 **설계 자체를 회피**. 구체적으로:
- 인증 서버는 서울, 사용자 DB는 서울
- 글로벌 애플리케이션 로직은 가능하지만 **민감정보는 리전 분리 저장**
- Spanner 멀티리전 구성 시 한국 데이터가 타국 replica로 갈 수 있는지 확인 필수 → 해당되면 한국만 별도 인스턴스 분리

## 설계 체크리스트 (에이전트 대조용)

### 필수

- [ ] 한국 사용자 **민감정보는 `asia-northeast3` (서울) 저장**
- [ ] **CMEK** (Cloud KMS 서울 리전 키) 적용
- [ ] **Organization Policy**로 리소스 위치 제한
- [ ] **Cloud Audit Logs** 전체 활성화 + 1~3년 보관 정책
- [ ] **VPC Service Controls**로 민감정보 유출 방지
- [ ] 접속 기록 **장기 저장소** (Cloud Storage / BigQuery) 분리
- [ ] 국외 이전 필요 시 **동의 획득 메커니즘** 설계
- [ ] **암호화 전송** (TLS 1.2+)
- [ ] **IAM 최소권한** + 민감정보 접근자 별도 역할
- [ ] **가명정보 처리** 시 Cloud DLP 또는 동등 도구

### 권장

- [ ] K-HISA 권고 12개 항목 반영
- [ ] **재해복구 시나리오** (서울 리전 장애 시 동일 국가 내 fallback)
- [ ] 정기 취약점 진단 + 모의 해킹
- [ ] 개인정보영향평가 (PIA) 수행

## 자주 간과되는 포인트

1. **로그에 민감정보 포함 시** 로그도 동일 보호 대상 → 로그도 서울 리전 + CMEK
2. **분석 파이프라인**이 BigQuery 다리전으로 구성되면 민감정보 해외 유출 위험
3. **개발환경에 운영 데이터 복제** 금지 (가명처리·합성데이터)
4. **GKE Cluster**가 글로벌 이미지 저장소를 쓰면 주의 — Artifact Registry는 리전 지정 필수
