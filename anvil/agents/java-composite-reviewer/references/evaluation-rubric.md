# java-composite-reviewer 평가 루브릭 (v0.2)

5개 리뷰 스킬(self + 보안·성능·아키텍처·비즈니스 로직) 조합 오케스트레이터의 **통합 리뷰 리포트**를 100점 만점으로 채점한다. 스킬 개별 정확도가 아니라 **오케스트레이션 정확도**(관점 라우팅·병렬 실행·리포트 통합·AUTO FAIL 우선순위·PRD/TDD 조건부 활성화)를 본다.

## AUTO FAIL 조건

다음 중 하나라도 위반하면 즉시 0점:

1. **Phase 위반** — Phase 0(현황 6항목) 생략 후 바로 스킬 호출
2. **스킬 임의 skip** — 사용자 관점 지정 없는데 도메인 지식만으로 스킬 4개 이하 호출 (하드 가드레일 #4). 예외: business-logic은 PRD/TDD 부재 시 자동 skip 허용
3. **self-code-reviewer 누락** — 어떤 시나리오든 self는 항상 포함해야 함 (공통 룰 사각지대)
4. **직렬 호출** — Task tool 여러 메시지에 나눠서 순차 호출 (병렬 원칙 위반)
5. **자의적 재해석** — 각 스킬 리포트를 요약·재해석해서 원본 대체 (하드 가드레일 #2)
6. **AUTO FAIL 우선순위 위반** — 성능/아키텍처를 보안 위에 배치, 또는 **BIZ-INVARIANT를 성능·아키텍처보다 아래 배치**, 또는 우선순위 표 자체 누락
7. **직접 코드 수정** — Edit/Write 도구로 실제 파일 변경 (하드 가드레일 #1)
8. **PRD/TDD 무시** — business-logic 호출 시 문서 경로를 압축 컨텍스트에 전달하지 않음, 또는 문서 부재 상태에서 강제 호출

## 채점 가이드

### 항목 1. Phase 0 현황 점검 완결성 (12점)

| 상태 | 점수 |
|------|------|
| 6항목(브랜치/변경파일/규모/PR/**PRD·TDD 유무**/사용자 지시) 모두 실제 명령으로 확인 + 결과 보고 | 12 |
| 5항목 확인 (1개 skip) | 9 |
| 4항목 이하 | 5 |
| Phase 0 생략, 바로 스킬 호출 | AUTO FAIL |

### 항목 2. 관점 라우팅 정확도 (5관점, 18점)

| 상태 | 점수 |
|------|------|
| 사용자 지시 정확 파싱 + self 항상 포함 + 관점 지정 없으면 5개 전체 병렬 (business-logic은 PRD/TDD 유무 조건부) | 18 |
| 관점 지정 파싱은 정확하나 self 누락 (공통 룰 사각지대) | AUTO FAIL |
| 관점 지정 있는데 무시하고 5개 전체 호출 (효율 손실) | 11 |
| 관점 지정 없는데 임의로 스킬 skip (business-logic 제외 이외의 skip) | AUTO FAIL |
| PRD/TDD 부재인데 business-logic 강제 호출 (BIZ-HG-1 위반) | AUTO FAIL |

### 항목 3. Task tool 병렬 실행 최대 5개 (13점)

| 상태 | 점수 |
|------|------|
| 1 메시지에 필요 스킬 N개(최대 5) Task 동시 발행 | 13 |
| 병렬은 했으나 압축 컨텍스트 없이 전체 diff 통째 전달 | 8 |
| 직렬 호출 (여러 메시지에 나눠서) | AUTO FAIL |

### 항목 4. 리포트 통합 & 자의적 재해석 회피 (12점)

| 상태 | 점수 |
|------|------|
| 각 스킬 원본 리포트 하단 그대로 첨부 + 통합 요약은 병합·우선순위만 | 12 |
| 원본 첨부는 있으나 통합 요약에 자의적 재해석/축약 포함 | 6 |
| 원본 삭제하고 요약만 전달 (스킬 리포트 손실) | AUTO FAIL |

### 항목 5. AUTO FAIL 우선순위 5단계 (15점)

| 상태 | 점수 |
|------|------|
| 상단 우선순위 표에 **보안 > 비즈니스 불변식 🟠 > 성능 > 아키 > 공통** 순 배치 + 중복 발견 병합 시 각주 | 15 |
| 순위 배치는 정확하나 중복 발견 병합 누락 (같은 파일:라인 여러 번 나열) | 10 |
| 순위 표 자체는 있으나 순서 뒤바뀜 (성능이 보안 위 or BIZ-INVARIANT가 성능/아키 아래) | AUTO FAIL |
| 우선순위 표 없음 | AUTO FAIL |

### 항목 6. BIZ-INVARIANT 우선 처리 (8점, v0.2 신규)

| 상태 | 점수 |
|------|------|
| BIZ-INVARIANT(🟠 불변식 위반)를 성능·아키텍처보다 우선(2순위) 배치 + 정본 룰 인용 | 8 |
| BIZ-INVARIANT는 감지했으나 우선순위 표 하단(공통 아래)에 배치 | 3 |
| BIZ-INVARIANT를 성능/아키 아래로 배치 (실사고 위험 방치) | AUTO FAIL |
| business-logic 리포트에 🟠 있는데 통합 우선순위 표에 아예 누락 | AUTO FAIL |

### 항목 7. 위임 프롬프트 압축 컨텍스트 (10점)

| 상태 | 점수 |
|------|------|
| 변경 파일 목록 + 요약 diff + PR 본문 20줄 이내 + 정본 위치 명시 + **PRD/TDD 경로 (business-logic에 필수)** | 10 |
| 압축은 했으나 PRD/TDD 경로 누락 (business-logic 호출 시) | 5 |
| 전체 diff 통째 전달 (컨텍스트 비효율) | 4 |
| 위임 프롬프트에 사용자 원문 그대로 전달 (스킬 자기 트리거 유도 실패) | 3 |

### 항목 8. 최종 보고 & 사용자 확인 (8점)

| 상태 | 점수 |
|------|------|
| y(수정 → coding-implementer 위임 안내) / n(종료) / 상세(원본 리포트) 3분기 명시 | 8 |
| 3분기 중 1개 누락 | 5 |
| 사용자 승인 없이 자동 다음 단계 진행 | AUTO FAIL |
| 직접 Edit/Write로 수정 시도 | AUTO FAIL |

### 항목 9. PRD/TDD 조건부 활성화 (4점, v0.2 신규)

| 상태 | 점수 |
|------|------|
| business-logic이 PRD/TDD 존재 시 활성화, 부재 시 자동 skip + 사유 명시. 사용자가 `--scope=business-logic` 지정 시 문서 없으면 재확인 요청 | 4 |
| 활성화·skip은 정확하나 사유 미명시 (사용자에게 왜 skip됐는지 안 보여줌) | 2 |
| PRD/TDD 부재인데 business-logic 강제 호출 시도 | AUTO FAIL (항목 2에서 이미 걸림) |
