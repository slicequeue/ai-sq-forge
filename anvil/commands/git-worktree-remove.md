# /git-worktree-remove

## 용도

사용이 끝난 워크트리를 안전하게 제거하고 관련 메타데이터를 정리한다.

## 인자

| 인자 | 필수 | 설명 | 기본값 |
|------|------|------|--------|
| 워크트리 경로 또는 브랜치명 | △ | 제거할 워크트리 식별자. 생략 시 목록에서 선택 | - |
| `--force` | X | 미커밋 변경사항이 있어도 강제 제거 | false |

## 실행 로직

### 1. 대상 식별

- 인자가 있으면 → 해당 워크트리 특정
- 인자가 없으면 → `git worktree list`로 목록 표시 후 사용자에게 선택 요청
- 브랜치명으로 입력 시 → `git worktree list`에서 해당 브랜치의 경로를 찾아 매칭

### 2. 안전 검사

```bash
# 해당 워크트리로 이동하여 변경사항 확인
git -C {워크트리-경로} status --porcelain
```

- 미커밋 변경사항이 있으면:
  - `--force` 없음 → 변경사항 목록을 보여주고 **중단**
  - `--force` 있음 → 경고 출력 후 진행

- 미푸시 커밋이 있으면:
  - 경고 출력 (강제 중단하지는 않되 사용자에게 알림)

### 3. 제거 실행

```bash
git worktree remove {워크트리-경로}
git worktree prune
```

### 4. 브랜치 정리 확인

- 제거된 워크트리의 브랜치가 원격에 머지 완료된 상태면 → 로컬 브랜치 삭제 제안
- 머지 미완료면 → 브랜치는 유지하고 안내만 출력

## 출력 형식

```
✓ 워크트리 제거 완료
  경로: {삭제된 경로}
  브랜치: {브랜치명} (유지됨 | 삭제됨)

현재 워크트리 목록:
  {git worktree list 결과}
```

**미커밋 변경사항으로 중단 시:**

```
✗ 워크트리 제거 중단: 미커밋 변경사항 존재
  경로: {경로}

변경된 파일:
  {변경 파일 목록}

강제 제거하려면 --force 옵션을 사용하세요.
```

## 가드레일

- 메인 워크트리(원본 저장소)는 제거할 수 없다
- 미커밋 변경사항이 있으면 기본적으로 제거를 차단한다
- 미푸시 커밋이 있으면 경고를 출력한다
- 제거 후 반드시 `git worktree prune`을 실행하여 메타데이터를 정리한다
- 현재 작업 중인 워크트리(cwd가 해당 경로인 경우)에서는 자기 자신을 제거하지 않는다
