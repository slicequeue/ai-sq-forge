## 평가 항목

| # | 항목 | 배점 | 설명 |
|---|------|------|------|
| 1 | **진입점 판단 정확성** | 20 | dev→Branch, 작업브랜치→Commit, 커밋완료→PR 분기 정확 |
| 2 | **논리 분할 품질** | 25 | 변경사항을 의미 있는 단위로 분할, 타입 정확, 과분할/미분할 없음 |
| 3 | **커밋 컨벤션 준수** | 20 | refac:, 한국어, 대괄호 금지, AI 정보 금지, spotless 실행 |
| 4 | **PR 품질** | 20 | dev 대상, 커밋 내용 반영, PR_TEMPLATE 적용 |
| 5 | **흐름 연속성** | 15 | 단계 간 자연스러운 전환, 에러 시 적절한 처리, 중간 보고 |
| | **합계** | **100** | |

## AUTO FAIL 조건

1. **`refactor:` 사용** (refac: 필수)
2. **대괄호 형식 커밋** ([API] 등)
3. **Co-authored-by에 AI 정보 포함**
4. **force push 또는 --no-verify 사용**
5. **빈 커밋 생성** (변경사항 없이 커밋)
6. **파괴적 명령 사용** (reset --hard, checkout --, clean -f)

---

## 합격 기준

| 등급 | 점수 | 설명 |
|------|------|------|
| **EXCELLENT** | 90~100 | 분할 정확, 컨벤션 완벽, 흐름 자연 |
| **PASS** | 75~89 | 핵심 준수, 경미한 미흡 |
| **FAIL** | 0~74 | 분할 부적절 또는 컨벤션 위반 |
