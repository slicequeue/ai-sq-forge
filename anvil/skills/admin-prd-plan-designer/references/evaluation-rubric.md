## 채점 세부 기준

### 1. 문서 타입 분리 정확성 (20점) — **CRITICAL**

| 점수 | 기준 |
|------|------|
| 20 | PRD/TDD/HYBRID 타입 명확, 각 섹션 역할 준수, 혼합 0건 |
| 15 | 타입 구분되나 경계에서 1~2건 모호한 표현 |
| 10 | PRD에 구현 세부 또는 TDD에 배경만 장문 1건 |
| 0 | 타입 미확정 또는 PRD/TDD 혼합 → **AUTO FAIL** |

### 2. Admin 컨텍스트 반영도 (20점) — **CRITICAL**

| 점수 | 기준 |
|------|------|
| 20 | SSR 흐름, sidebar, security, admin history 모두 반영 |
| 15 | 4축 중 1개 경미한 누락 |
| 10 | 2개 축 누락 |
| 0 | admin 특화 맥락 전면 누락 → **AUTO FAIL** |

### 3. 템플릿 충족도 (20점)

| 점수 | 기준 |
|------|------|
| 20 | 필수 표/체크리스트 100% 충족 |
| 15 | 90% 충족, 1~2개 표 항목 빈칸 |
| 10 | 핵심 표는 있으나 보조 섹션 누락 |
| 5 | 자유 서술만, 표/체크리스트 미사용 |

### 4. 멀티턴 합의 품질 (20점)

| 점수 | 기준 |
|------|------|
| 20 | 합의 루프 수행, 결정 로그 완전, 미결→Open Questions 전환 |
| 15 | 합의 수행했으나 결정 로그 일부 누락 |
| 10 | 질문 1회만 수행, 독단적 결정 다수 |
| 0 | 합의 없이 독단 작성 |

### 5. Phase 실행 가능성 (20점)

| 점수 | 기준 |
|------|------|
| 20 | 모든 Phase에 목표/TODO/산출물/검증 기준 완비 |
| 15 | 대부분 완비, 1개 Phase 검증 기준 모호 |
| 10 | Phase 구분은 있으나 TODO가 추상적 |
| 5 | Phase 구분 없음 |

## AUTO FAIL 조건

아래 중 **하나라도** 해당하면 점수 무관 자동 실패:

1. **PRD/TDD 타입 미확정 상태로 문서 작성** (Phase 0 위반)
2. **admin 컨텍스트(SSR/sidebar/security/history) 전면 누락**
3. **필수 표/체크리스트 없이 자유 서술만 제출**
4. **사용자와 합의 없이 독단적으로 범위 확장/축소**
5. **문서 작성 중 구현 코드/커밋으로 점프**

## 평가 실행 방법

### 기본 테스트 (baseline vs with-skill)

1. **테스트 케이스 준비**: `proving-grounds/evals/admin-prd-plan-designer/test-cases.md`
2. **Baseline 실행**: 스킬 없이 동일 프롬프트로 문서 작성 요청
3. **With-Skill 실행**: 스킬 적용하여 동일 프롬프트로 문서 작성 요청
4. **채점**: 양쪽 결과를 루브릭으로 채점, 비교

### 테스트 케이스 유형

| 유형 | 비율 | 예시 |
|------|------|------|
| Happy Path | 50% | admin 신규 기능 HYBRID 문서 작성 |
| Edge Case | 30% | PRD만 요청, 불명확 요구사항으로 시작 |
| Negative | 20% | 합의 없이 즉시 작성 유도, 코드 점프 유도 |
