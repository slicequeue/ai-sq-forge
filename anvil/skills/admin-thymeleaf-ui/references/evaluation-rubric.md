## 채점 세부 기준

### 1. 구조 정합 (25점) — **CRITICAL**

| 점수 | 기준 |
|------|------|
| 25 | URL-View-File 3점 완벽 정합, layout:decorate+layout:fragment 적용, 파일 계획표 작성 |
| 20 | 3점 정합 OK, 파일 계획표 경미한 누락 |
| 15 | 3점 중 1개 불일치 (뷰 이름 vs 파일 경로 등) |
| 0 | layout:decorate 미적용 또는 3점 정합 2개+ 깨짐 → **AUTO FAIL** |

### 2. 보안 정합 (25점) — **CRITICAL**

| 점수 | 기준 |
|------|------|
| 25 | @PreAuthorize 정확, CSRF 동적 헤더, catch(BaseRuntimeException) 적용, PII 미노출 |
| 20 | 보안 대부분 OK, 1건 경미한 미흡 |
| 15 | CSRF 하드코딩 또는 권한 문자열 불일치 1건 |
| 0 | CSRF 미적용 또는 catch(Exception) 사용 → **AUTO FAIL** |

### 3. 테마 일관성 (20점)

| 점수 | 기준 |
|------|------|
| 20 | AdminLTE 구조 준수, 기존 화면과 마크업/여백 일관 |
| 15 | 구조 OK, 스타일 경미한 차이 |
| 10 | AdminLTE 계층 일부 누락 |
| 5 | 독자적 마크업 창작 |

### 4. 변경 최소성 (15점)

| 점수 | 기준 |
|------|------|
| 15 | 전역 파일 변경 없음, 페이지 전용 JS/CSS만 추가 |
| 10 | 전역 파일 1개 최소 변경 (합리적 사유) |
| 5 | 전역 파일 2개+ 변경 |
| 0 | 불필요한 전역 변경으로 회귀 위험 |

### 5. 보고 명확성 (15점)

| 점수 | 기준 |
|------|------|
| 15 | 모드 선택 + 파일 계획표 + Self-check + 리스크 모두 완전 |
| 10 | 대부분 완전, 1개 항목 누락 |
| 5 | Self-check만 제출, 계획표/리스크 누락 |

## AUTO FAIL 조건

아래 중 **하나라도** 해당하면 점수 무관 자동 실패:

1. **layout:decorate + layout:fragment 미적용** (구조 붕괴)
2. **URL-View-File 3점 정합 2개 이상 깨짐**
3. **CSRF 토큰 하드코딩 또는 미적용**
4. **catch(Exception) 사용** (내부 에러 메시지 노출)
5. **모드 선택(M1~M4) 없이 코드 생성**
6. **동일 도메인 기존 화면을 읽지 않고 신규 패턴 창작**

## 평가 실행 방법

### 기본 테스트 (baseline vs with-skill)

1. **테스트 케이스 준비**: `proving-grounds/evals/admin-thymeleaf-ui/test-cases.md`
2. **Baseline 실행**: 스킬 없이 동일 프롬프트로 admin UI 구현 요청
3. **With-Skill 실행**: 스킬 적용하여 동일 프롬프트로 admin UI 구현 요청
4. **채점**: 양쪽 결과를 루브릭으로 채점, 비교

### 테스트 케이스 유형

| 유형 | 비율 | 예시 |
|------|------|------|
| Happy Path | 50% | M1 신규 화면 (목록+모달+사이드바) |
| Edge Case | 30% | M2 기존 화면 개선, M3 보안 정리 |
| Negative | 20% | 전역 파일 변경 유도, CSRF 하드코딩 유도 |
