# 충돌·패턴 분석 + 리포트

부하 프로파일 + cron으로 "언제·어느 자원에 무거운 잡이 몰리는가"를 찾고 재배치를 제안한다.

---

## 1. KST 타임라인 충돌맵

1. 모든 스케줄 잡의 cron을 KST로 환산해 시간순 정렬.
2. **자원별로 행을 나눠** 24시간 축에 배치 (PRIMARY / REPLICA+AGGREGATE / 외부).
3. **같은 시각 × 같은 자원**에 2개 이상 몰린 구간을 표시한다.
4. 고빈도 잡(`*/5`, `*/10`, 매분)은 항상 깔리는 **baseline 부하**로 별도 표기한다 — 정시 대형 잡은 이 baseline 위에서 발생한다.

---

## 2. 충돌 판정 규칙

### CONFLICT

- 동일 시각 + 동일 자원 + 둘 이상 **Heavy**. 특히 **같은 테이블 동시 대량 UPDATE/DELETE = 락 경합 직접 유발**.
- 앞 잡이 LONG이라 다음 잡 시작 전에 끝나지 않음 (간격 < 추정 duration).
- 고빈도 잡이 정시(`:00`)에 정렬되어 정시 대형 잡과 매번 겹침.
- 동일 외부 시스템을 치는 잡이 같은 시간대에 집중 (rate limit·상대 서버 부하).

### CONFLICT 아님

- **다른 자원** 동시각 (예: PRIMARY Heavy + REPLICA Heavy — 읽기 분리됨).
  - 단 **AGGREGATE·REPLICA가 PRIMARY와 동일 호스트면 IO·CPU 합산** → 이때는 충돌로 취급한다. 동일 호스트 여부를 확인하지 않았다면 판정을 보류하고 확인 항목으로 남긴다.

---

## 3. 재배치 제안

**cron만 바꾸면 되는 것 / 코드 수정이 필요한 것**을 분리한다.

변경표 형식: `대상 배치 | 현재 cron(KST) | → 변경 cron(KST) | 이유`. cron은 반드시 구체값으로.

### 분산 기법

| 기법 | 내용 |
|---|---|
| 시각 stagger | 20~30분 간격으로 분산 |
| 고빈도 offset | `*/5` → `2-59/5` 로 정시 회피 |
| 빈도 완화 | 5분 → 15분 등, 도메인 요건 확인 후 |
| 한산 시간대 이동 | 새벽 등. 운영 트래픽 피크(아침 08~10, 저녁 20~22) 회피 |

### 코드 수정 항목

- 무범위 풀스캔 → 청크·페이징
- BULK `saveAll` → bulk update 쿼리
- N+1 → in-clause 일괄 조회
- 푸시 미배치 → 배치 분할 + rate limit 준수

도메인 선후 의존성을 코드만으로 단정할 수 없으면 **"도메인팀 1회 확인"** 단서를 단다.

---

## 4. 리포트 구성 (formal-doc-ko 적용)

`.md` 산출물 권장 구성:

1. 평가 기준(합의) + 근거 데이터 출처
2. 자원 토폴로지 (호스트·용도·사용 잡, **동일 호스트 여부 명시**)
3. KST 24시간 타임라인 충돌맵
4. 충돌 핫스팟 (우선순위순, 각 항목에 잡명·근거·권고)
5. 가장 무거운 단일 잡 Top N (방법론 + file:line 근거)
6. 즉시 조치 권고 (변경표: 반드시 / 권장 / 코드 수정 구분)
7. 운영 점검 필요 (스케줄 누락·구현체 없음 등) + **한계(정적 추정 → 실측 권장)**

작성 규칙은 `formal-doc-ko` 스킬을 함께 호출해 적용한다 (장식 기호 금지, IT 정식 용어, 사실·판단 분리, 대상·날짜·범위 명시, 근거 링크).

---

## 5. 실측 보강 (확정용)

정적 "겹침" 판정을 확정하려면 실측이 필요하다. 리포트에 이 명령을 제시한다.

```bash
# Heavy 잡의 최근 실행 시각·소요시간
gcloud run jobs executions list --job=<JOB> --project=<PROJECT> --region=<REGION> \
  --format="table(metadata.name, status.startTime, status.completionTime)" --limit=10
```

Cloud Logging으로 시작·종료 로그를 떠 실제 duration을 구하고, 타임라인의 "겹침 가능"을 사실로 확정한다. 실측 전에는 **"추정"** 으로 표기한다.
