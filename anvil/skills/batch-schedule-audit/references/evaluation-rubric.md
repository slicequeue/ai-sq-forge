# batch-schedule-audit 평가 루브릭

배치 스케줄 감사 작업을 100점 만점으로 채점한다. 평가 대상은 **스킬이 산출하는 부하 프로파일 + 충돌 판정 근거 + 재배치 변경표 + 리포트 본문 + 사용자 응답 텍스트**다. 실제 `gcloud` 호출은 하지 않고, 하네스가 제공하는 `joined.csv` 시뮬레이션 데이터와 코드 스니펫을 입력으로 삼는다.

## 평가 항목

| # | 항목 | 배점 | 설명 |
|---|------|------|------|
| 1 | **자원별 구분 판정** | 20 | 모든 잡에 read 자원 / write 자원 분리. write 템플릿 실제 확인. 동일 호스트 여부 명시 |
| 2 | **무게 산정 근거** | 20 | A~G 축 산정 + 등급마다 file:line·쿼리·청크 size·리소스 한도 근거. 리소스↔코드 교차검증 |

## AUTO FAIL 조건

다음 중 하나라도 위반하면 즉시 FAIL 처리:

1. **자원 구분 없는 단일 무게 점수** — Heavy/Medium/Light만 붙이고 read/write 자원 표기 없음
2. **근거 없는 무게·충돌 판정** — 등급 또는 CONFLICT에 file:line·쿼리·리소스 한도 등 근거가 하나도 없음
3. **정적 추정 한계 미명시** — 실측 없이 "겹친다"를 사실로 단정, 실측 명령·한계 문구 없음
4. **하드코딩 토폴로지 무검증 인용** — 참조 문서의 호스트·스키마 값을 재확인 없이 리포트에 옮김
5. **다른 자원 동시각을 충돌로 판정** — 읽기 분리된 REPLICA와 PRIMARY 동시각을 락 경합으로 서술 (동일 호스트 근거 없이)
6. **동일 호스트 확인 없이 "자원 분리됨" 단정** — AGGREGATE·REPLICA가 PRIMARY와 같은 호스트인지 확인하지 않고 부하가 분리됐다고 결론
7. **인증 미확인 상태 진행** — gcloud 인증·권한 확인 없이 수집 결과를 추정으로 채움
8. **스케줄 없는 잡 일괄 "폐기" 단정** — 일회성 / 폐기 / 스케줄 누락 구분 없이 처리
9. **프로파일 이름만으로 write 자원 판정** — summary 등 프로파일이 있으니 PRIMARY를 안 건드린다고 결론 (write 템플릿 미확인)
10. **장식 기호 잔존** — 이모지·★·✅ 등 1개 이상

## 채점 가이드

### 항목 1. 자원별 구분 판정 (20점)

| 상태 | 점수 |
|------|------|
| 전 잡 read/write 분리 + write 템플릿 확인 근거 + 동일 호스트 여부 명시 | 20 |
| read/write 분리했으나 동일 호스트 여부 미언급 | 12 |
| 프로파일 유무로만 자원 추정 (write 템플릿 미확인) | AUTO FAIL (#9) |
| 자원 표기 없이 무게 점수만 | AUTO FAIL (#1) |

### 항목 2. 무게 산정 근거 (20점)

| 상태 | 점수 |
|------|------|
| A~G 전 축 + 등급마다 근거 + 리소스↔코드 교차검증(과할당·OOM 리스크 지적) | 20 |
| 축 산정·근거는 있으나 교차검증 없음 | 13 |
| 일부 잡만 근거 있음 | 8 |
| 근거 전무 | AUTO FAIL (#2) |

### 항목 3. cron → KST 환산 + 타임라인 (15점)

| 상태 | 점수 |
|------|------|
| 환산 정확(날짜 넘김 포함) + 자원별 행 분리 + 고빈도 baseline 별도 표기 | 15 |
| 환산 정확, 고빈도 baseline 미분리 | 9 |
| 날짜 넘김 오류 (`0 15 * * *` 를 15:00 KST로 표기 등) | 4 |
| 환산 방향 오류 (+9h를 −9h로) | 2 |

### 항목 4. 충돌 판정 정확도 (15점)

| 상태 | 점수 |
|------|------|
| 같은 자원 한정 + LONG duration 간격 검사 + 정시 정렬 고빈도 겹침 + 동일 외부 시스템 집중 | 15 |
| 같은 자원 한정은 지켰으나 duration 간격·정시 정렬 중 하나 누락 | 9 |
| 다른 자원 동시각을 충돌로 셈 | AUTO FAIL (#5) |
| 동일 호스트 미확인 상태로 "분리됨" 결론 | AUTO FAIL (#6) |

### 항목 5. 재배치 제안 실행 가능성 (10점)

| 상태 | 점수 |
|------|------|
| cron 변경 / 코드 수정 분리 + 변경표에 구체 cron + 이유 + 피크 회피 | 10 |
| 분리했으나 cron이 "새벽으로 이동" 같은 서술형 | 6 |
| 제안이 원칙 수준 (구체 대상 없음) | 3 |

### 항목 6. 한계·미확정 명시 (10점)

| 상태 | 점수 |
|------|------|
| 정적 추정 한계 + 실측 명령 + 얕게 본 범위 + 스케줄 없는 잡 3분류 전부 | 10 |
| 한계 문구는 있으나 실측 명령 없음 | 6 |
| 스케줄 없는 잡을 3분류 없이 처리 | AUTO FAIL (#8) |
| 한계 미명시 | AUTO FAIL (#3) |

### 항목 7. 리포트 구조·서식 (10점)

| 상태 | 점수 |
|------|------|
| 7섹션 전부 + 사실·판단 분리 + 검수 스캔 실행 | 10 |
| 7섹션, 검수 스캔 미실행 | 6 |
| 섹션 2개 이상 누락 (특히 운영 점검 필요·한계) | 3 |
| 장식 기호 잔존 | AUTO FAIL (#10) |
