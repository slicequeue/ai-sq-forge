## AUTO FAIL 조건

1. **개발 내부 용어 노출** — OAuth/토큰/refresh/JPA/repository/service/controller 등이 메시지 본문에 등장
2. **PR 우선순위·내부 관리 표기** — P0/P1/P2, 에픽, 스프린트 번호
3. **내부 문서 경로 노출** — `docs/works/...` 등 레포 내 경로
4. **출처 없는 정책·수치 단정** — "외부 서비스 정책상 N일", "통상 ~분 내" 등 확인 없는 수치
5. **유저 식별자 누락** — 닉네임만 있고 userId 없음 (또는 반대)
6. **두괄식 위반** — 배경·경위·조사 방법부터 시작 (첫 섹션이 "상황"이 아님)
7. **사용자 확인 누락** — 작성 완료 후 사용자에게 확인 요청 없이 종료
8. **섹션 빈 채로 유지** — 불필요한 섹션을 삭제하지 않고 "해당 없음" 등으로 비워둠

## 합격 기준

| 등급 | 점수 | 설명 |
|------|------|------|
| **EXCELLENT** | 90~100 | 6차 수정 없이 한 번에 통과 수준. CS 복붙 품질 완벽 |
| **PASS** | 75~89 | 핵심 구조·언어 준수. 경미한 톤 조정 여지 |
| **FAIL** | 0~74 | 주요 섹션 누락, 개발 용어 혼재, 출처 없는 단정 등 |

---

## 점수 산정 예시

**EXCELLENT 응답 특징**:
- Phase 0 6항목 모두 확인 후 시작 (부족 시 질문)
- 6섹션 고정 순서 유지, 불필요 섹션 삭제
- 유저 표기 전부 `닉네임#ID(userId)` 일관
- 개발 용어 탐지 시 tech-term-replacement 사전 치환
- "사용자 안내 요청" 섹션이 별도 편집 없이 CS가 바로 복붙 가능
- 불확실성은 괄호 유보 문구 ("시스템 상황에 따라 복구가 어려울 수 있음")
- 작성 후 "이 느낌 맞아?" 확인 요청

**FAIL 응답 특징**:
- `removeAuthorizedClient` 같은 메서드명 노출
- P0/P1 우선순위 표기
- "Dexcom 정책상 7일만 복구 가능" 같은 출처 없는 단정
- `userId` 빼먹고 닉네임만 표기
- "저희가 조사를 시작한 배경은…" 식 두괄식 위반
- 사용자 확인 없이 메시지만 출력하고 종료
