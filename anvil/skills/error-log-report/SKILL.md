# error-log-report - 구간 에러 로그 공식 보고서

지정 구간의 애플리케이션 ERROR 로그를 **수집 → 유형 분류 → 신규/기존 판정 → 공식 보고서(딥링크 포함)** 로 만든다.

문서 서식·문장 규칙은 `formal-doc-ko` 스킬을 **함께 호출**해 적용한다 (장식 기호 금지, IT 정식 용어, 팩트/판단 분리, 대상·날짜·범위 명시, 근거 링크 자기설명형).

| 참조 | 용도 |
|------|------|
| `references/gcloud-recipes.md` | gcloud 조회·awk 집계·딥링크 생성 스니펫 |
| `references/noise-catalog-moneyball.md` | 프로젝트별 알려진 노이즈 카탈로그 (moneyball 실전본) |
| `references/evaluation-rubric.md` | 100점 채점 기준 + AUTO FAIL |

## Phase 0. 대상 파라미터 확정 (현황 파악 우선)

**가정으로 시작하지 않는다.** 아래 6개를 확정한 뒤 조회한다. 사용자가 명시하지 않은 항목은 프로젝트 설정 파일·이전 보고서에서 확인하고, 확인 불가 시 사용자에게 묻는다.

| # | 파라미터 | 확인 방법 |
|---|---------|----------|
| 1 | GCP 프로젝트 | `gcloud config get-value project` 또는 사용자 지정 |
| 2 | 리전 | 배포 스펙 / 사용자 지정 |
| 3 | 서비스(리소스) | Cloud Run 서비스명·리소스 타입. 복수면 전부 나열 |
| 4 | **집계 기준 필드** | 앱 레벨(`jsonPayload.level="ERROR"`) vs 인프라 레벨(`severity>=ERROR`). **둘은 결과가 다르다** — 어느 쪽인지 보고서에 명시 |
| 5 | 구간 | 입력 타임존 확인 → UTC 환산 (KST = UTC+9, 즉 **UTC = KST − 9시간**) |
| 6 | 노이즈 카탈로그 | `references/noise-catalog-{project}.md` 존재 여부. 없으면 신규 생성 대상으로 선언 |

### Phase 0.5. 인증 확인

조회 권한이 조직 정책(Context-Aware Access 등)으로 막힐 수 있다. 가벼운 조회 1건으로 먼저 확인한다.

```bash
gcloud logging read 'resource.type="cloud_run_revision"' --project=<PROJECT> --limit=1 --format='value(timestamp)' 2>&1 | tail -3
```

- 성공하면 진행.
- `Access was blocked by Context Aware Access` 또는 인증 오류면 사용자에게 (1) `! gcloud auth login` 실행 후 재시도, 또는 (2) Cloud Shell·콘솔에서 조회해 붙여넣기를 요청한다. **임의로 우회하지 않고, 로그 없이 추정으로 보고서를 쓰지 않는다.**

## 워크플로

### 1. 구간 확정

입력 구간을 UTC로 환산해 `START`, `END`(RFC3339)로 고정한다. 보고서에는 **UTC·KST 병기**.

예: KST 2026-07-14 00:00~08:00 → UTC `2026-07-13T15:00:00Z` ~ `2026-07-13T23:00:00Z`.

### 2. 수집 (파일로 저장)

메시지에 대용량 JSON 페이로드가 섞이므로 **스택트레이스는 제외하고 핵심 필드만** TSV로 저장한다. 컨텍스트에 원본 로그를 통째로 올리지 않는다.

조회 명령은 `references/gcloud-recipes.md` §1 참조. 저장 후 총 건수를 먼저 센다.

### 3. 유형 분류 (집계)

`(logger || exception_class)` 별 건수, message 시그니처(앞 90자) 별 건수, 시간 분포를 각각 집계한다. 명령은 `references/gcloud-recipes.md` §2.

> **로그 건수 ≠ 실패 이벤트 수.** 하나의 실패가 여러 로거에 중복 기록될 수 있다 (예: 핸들러 + AOP Aspect + `AsyncUncaughtExceptionHandler` = 이벤트 1건당 로그 3줄). 집계표에 **"로그 건수" 컬럼과 "실패 이벤트 수" 컬럼을 분리**해 제시하고, 배수 관계의 근거(어느 로거들이 같은 이벤트를 찍는지)를 적는다.

### 4. 신규/기존 판정 (노이즈 카탈로그 대조)

`references/noise-catalog-{project}.md`의 시그니처 표와 집계 결과를 대조한다.

- 카탈로그에 있으면 → 기존(확정/인지). 카탈로그의 기존 판정·조치 상태를 그대로 인용한다.
- 카탈로그에 없으면 → **"신규, 조치 필요"** 로 표시하고 Phase 5 상세 조회 대상에 넣는다.
- 카탈로그가 아직 없는 프로젝트면 → 이번 집계 결과로 카탈로그를 **신규 생성**하고, 전건을 "최초 관측"으로 표기한다(전부 "신규 장애"로 단정하지 않는다).
- 판정을 확정한 새 유형은 **카탈로그에 한 줄 추가**해 다음 회차에 재사용한다.

### 5. 주목 유형 상세 조회

신규이거나 **사용자 대면**(HTTP 예외 처리기 경유, 응답 실패로 이어짐) 유형은 전문·스택을 추가로 본다. 명령은 `references/gcloud-recipes.md` §3.

### 6. Cloud Logging 딥링크 생성

각 유형·근거 자료에 콘솔 딥링크를 붙인다. URL 인코딩은 python으로 처리한다 (`references/gcloud-recipes.md` §4).

링크 텍스트는 **자기설명형**: `[구간 내 유형 N 전체(예외클래스 기준)](URL)`, `[대표 단건 스택(insertId ...)](URL)`. "여기", "링크" 같은 표현 금지.

### 7. 보고서 작성

파일명 `error-log-report-<YYYY-MM-DD>-<HHMM>-<HHMM>.md` (구간이 하루를 넘으면 날짜 범위). 고정 7섹션:

1. **개요** — 대상(서비스/리전/프로젝트/리비전), 구간(UTC·KST 병기), 집계 기준, 작성일, 근거 자료 안내
2. **결론 요약** — 총 건수 + 유형별 집계표(로그 건수 / 실패 이벤트 수 / 예외 클래스 / 판정)
3. **타임라인** — 발생 시각 분포(UTC·KST 병기)
4. **유형별 상세** — 유형마다 "측정값(사실)" 목록 → "판단" 목록 → 로그 링크
5. **영향 분석** — 사용자 대면 여부 / 데이터 정합성 / 자가 회복 여부 구분
6. **후속 조치·권고** — 유형별 조치. 이미 수정 코드가 있으나 미배포인 건은 그 사실을 적는다
7. **근거 자료 안내** — 로그자료 1(대표 단건 + 링크), 로그자료 2(구간 전수 쿼리 + 링크), 참고 문서

### 8. 완료 전 검수

`formal-doc-ko` 검수 스캔을 실행한다 (`references/gcloud-recipes.md` §5). 장식 기호 0건, 비유·구어 표현 0건을 확인한 뒤 보고한다.

## 판정 원칙

| 구분 | 원칙 |
|------|------|
| 원본 유실 vs 후처리 실패 | `AFTER_COMMIT` 후처리 실패는 원본이 이미 커밋된 상태 → **"데이터 정상, 후처리 실패"** 로 기술. "데이터 유실"로 쓰지 않는다 |
| 자가 회복 | 다음 주기 재계산·재시도로 스스로 복구되는 유형은 그 근거(어느 배치·어느 트리거가 복구하는지)와 함께 "자가 회복"으로 분류 |
| 마스킹된 원인 | 재시도 래퍼 예외(`ExhaustedRetryException` 등)가 원인 예외를 가리는 경우, 표면 예외가 아니라 **원인 예외(cause)** 를 유형명으로 쓰고 마스킹 사실을 적는다 |
| 외부 의존성 | 외부 API 4xx/5xx·커넥션 리셋은 "외부 의존성 일시 오류"로 분류하되, **사용자 대면 여부**는 별도 판정 |
| 단발 vs 반복 | 구간 내 1건과 지속 반복을 구분해 긴급도에 반영 |

## 가드레일

### 하드 가드레일 (절대 위반 불가)

1. **로그 없이 보고서 작성 금지** — 인증 실패·권한 부족 시 추정으로 채우지 않고 사용자에게 조회를 요청한다.
2. **집계 기준 미명시 금지** — 앱 레벨(`jsonPayload.level`)인지 인프라 레벨(`severity`)인지 보고서 개요에 반드시 적는다.
3. **UTC·KST 단독 표기 금지** — 모든 시각은 병기한다. 환산 방향을 틀리지 않는다(UTC = KST − 9h).
4. **로그 건수를 실패 이벤트 수로 단정 금지** — 중복 로깅 가능성을 확인하고 두 수를 분리 제시한다.
5. **카탈로그 대조 없이 전건 "신규" 판정 금지** — 카탈로그가 있으면 대조하고, 없으면 "최초 관측"으로 표기한다.
6. **근거 링크 없는 유형 판정 금지** — 유형마다 Cloud Logging 딥링크(또는 재현 쿼리)를 붙인다.
7. **사실·판단 혼재 금지** — 상세 섹션은 "측정값(사실)"과 "판단"을 분리한다. 추정에는 추정임을 명시한다.
   - **집계 버킷 경계를 임의로 세분화하지 않는다.** 입력이 "17:00 이후 15건"으로 묶여 있으면 그대로 묶어 표기한다. 하위 구간을 쪼개 "18:00~22:59는 0건"처럼 단정하는 것은 입력이 뒷받침하지 않는 추론이다. (v0.2 — `--repeat 3`에서 3회 중 1회 발생)
8. **장식 기호·비유 표현 금지** — `formal-doc-ko` 규칙. 이모지·★·✅ 등 0건.
9. **PII 최소 포함** — userId/deviceId는 원인 특정에 필요한 범위에서만, 필요 이유와 함께 적는다. 이메일·전화번호·이름은 보고서에 넣지 않는다.

### 소프트 가드레일

- 보고서는 기본 untracked로 둔다. 커밋·공유는 사용자 지시가 있을 때만.
- 로그 조회는 `--limit` 상한을 두고, 상한에 도달하면 **"절단됨"** 을 보고서에 명시한다.
- 반복 관측되며 조치 불필요한 외부 오류는 로그 레벨 강등(ERROR → WARN)을 권고 항목으로 남긴다.
- 유형이 15개를 넘으면 상세 섹션은 상위 N개 + 나머지 요약표로 나누고, **무엇을 요약으로 돌렸는지 밝힌다**.
