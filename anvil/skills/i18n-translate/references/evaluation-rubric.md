# i18n-translate 평가 루브릭

`messages/*.properties` 한국어 원문을 en_US / ja_JP 로 번역·검수하는 작업을 100점 만점으로 채점한다. 평가 대상은 스킬이 내놓는 **번역 값 · properties 반영안(diff) · 길이 검사 결과와 대안 · 정합성 검증 절차 · 승인 게이트 판정 · 보고**다.

## 목차

1. 평가 항목 (100점)
2. AUTO FAIL 조건
3. 합격 기준
4. 항목별 채점 가이드
5. 행동 패턴 체크리스트 (축 3)

---

## 1. 평가 항목

| # | 항목 | 배점 | 설명 |
|---|------|------|------|
| 1 | **정본 가이드 적용** | 20 | `references/langskill.md`(공통·en·ja)와 `ja-house-rules.md` 규칙이 결과물에 실제로 반영됨. en 하드룰·sentence case·anti-AI tells, ja 3-pass·문장 구성·重複表現·용어집·규제 표현 |
| 2 | **의미 보존·번역 정확도** | 20 | 사실·수치·판단·요청 행동 누락/추가 없음, 플레이스홀더 개수·종류 일치, 고유명사·음식명 분해 오역 없음, 혈당 표기 맥락 구분 |
| 3 | **properties 무결성** | 15 | 여러 줄 역슬래시, 흡수 방지, 후보·메모는 `#` 주석, 원문과 같은 위치 삽입, 다른 번들 중복 키·번들 승자 확인 |
| 4 | **길이 기준** | 10 | 글자 수 비율(en ≤ 1.2, ja ≤ 0.9)을 수치로 제시, 초과 시 짧은 대안 병기, 키 역할(title/button/label/cta) 반영, 표시 폭은 보조 지표 |
| 5 | **정합성 검증 루프** | 15 | `check_parity.py`·`check_ratio.py`·`MessageBundleLocaleParityTest` 실행 계획 + `ALLOWED_MISMATCHES` 에서 반영 키 제거(또는 보류 키 사유 등록) |
| 6 | **범위·승인 게이트** | 10 | 한국어 원문 무단 수정 금지, 키 신규 생성·삭제 금지, 법무·의학 문구는 초안만 남기고 확인 주체 명시 |
| 7 | **보고 품질** | 10 | 확인된 것과 가정한 것 분리, 길이 초과·보류 키를 PR 본문·리뷰 코멘트로 남기는 방식 안내, 사용자 확인이 필요한 결정 명시 |
| | **합계** | **100** | |

TC 성격상 해당하지 않는 항목(예: Negative TC 의 길이 항목)은 **만점 처리하지 않고 비례 환산**한다. 해당 항목 배점을 제외한 합으로 점수를 구한 뒤 100점으로 환산하고, 리포트에 제외 항목을 적는다.

## 2. AUTO FAIL 조건

하나라도 해당하면 그 TC 는 0점이다. "파일에 반영하겠다"고 제시한 최종안 기준으로 판정한다. 검토 의견에서 문제를 지적만 하고 반영안에서 고친 경우는 해당하지 않는다.

| # | 조건 | 감지 기준 |
|---|------|-----------|
| AF-1 | **properties 파손** | 반영안에 ① 여러 줄 값의 줄 끝 역슬래시 누락 ② 생략된 문장 뒤 역슬래시 잔존으로 다음 키 흡수 ③ 후보를 여러 줄 값으로 나열 ④ 번역 메모를 `#` 없이 기재 중 하나가 있음 |
| AF-2 | **키 누락·불일치 방치** | 반영 후 기본 번들 대비 en/ja 키 집합이 어긋나는 상태로 완료 처리, 또는 원문에 없는 키 신규 생성·기존 키 삭제를 승인 없이 수행 |
| AF-3 | **플레이스홀더·태그 불일치** | 원문 `{0}`·`{1}`·스타일 태그의 개수 또는 종류가 번역값과 다름 |
| AF-4 | **정본 langSKILL 무시** | en 출력에 혈당 맥락 `blood glucose`/`blood sugar` 사용, UI 문자열에 `低血糖`/`高血糖`·진단 단정 표현 사용, 또는 가이드에 반하는 사용자 지시(예: 전부 `blood glucose` 로 통일)를 근거 확인 없이 그대로 수용 |
| AF-5 | **원문 의미 변경** | 수치·사실·요청 행동이 바뀌거나 빠짐, 한국 음식명 분해 오역(쌍화차 → ダブルデッキバス 유형)·유사어 치환, 한국어 원문을 승인 없이 수정해 반영 |
| AF-6 | **승인 게이트 우회** | 법정 고지·약관·의학적 권고·약물/질환명 문구를 담당자 확인 없이 파일 반영안으로 확정 |
| AF-7 | **검수 없는 기계번역 일괄 반영 수용** | "대충 채워서 테스트만 통과" 류 요청을 수락하고 검수 절차 없이 일괄 반영안을 제시 |

## 3. 합격 기준

| 등급 | 점수 |
|------|------|
| EXCELLENT | 90~100 |
| PASS | 75~89 |
| FAIL | 0~74 또는 AUTO FAIL |

Baseline 대비 **+20점 이상** 격차를 요구한다. 단, Happy TC 는 baseline 이 이미 무난한 번역을 낼 수 있어 격차가 작게 나올 수 있으므로 TC 유형별로 따로 비교한다. 스킬 가치는 Edge·Negative 에서 판정한다.

## 4. 항목별 채점 가이드

### 항목 1. 정본 가이드 적용 (20)

| 상태 | 점수 |
|------|------|
| langskill 적용 근거를 규칙 단위로 제시 + en 하드룰·sentence case·마침표 규칙 + ja 3-pass·12항목 중 걸린 항목을 실제로 고침 + 혈당 표기 구분(ja-house-rules §2) 적용 | 20 |
| 가이드는 적용했으나 ja 자기 검수나 용어집 대조 중 하나 누락 | 14 |
| 일반적인 "자연스러운 번역" 수준, 가이드 고유 규칙 반영 1~2건 | 7 |
| 가이드 고유 규칙 반영 없음 | 0 |
| 가이드 하드룰 위반 | AUTO FAIL (AF-4) |

### 항목 2. 의미 보존·번역 정확도 (20)

| 상태 | 점수 |
|------|------|
| 사실·수치·요청 행동 보존, 플레이스홀더 일치, 원문 대조 결과 명시 | 20 |
| 의미 보존은 되었으나 뉘앙스 뭉갬(가이드 "생생한 표현" 유형) 1건 | 14 |
| 사소한 정보 누락 1건(핵심 수치·행동은 유지) | 8 |
| 수치·행동 변경, 음식명 분해 오역 | AUTO FAIL (AF-5) |

### 항목 3. properties 무결성 (15)

| 상태 | 점수 |
|------|------|
| 역슬래시·흡수·주석 규칙 준수 + 같은 위치 삽입 + 다른 번들 중복 키 확인(grep) + 해당 시 번들 승자 판정 | 15 |
| 파일 형식은 정상이나 중복 키·위치 확인 누락 | 9 |
| 반영 위치 미지정(파일 끝 추가 등) | 4 |
| 파손 반영안 | AUTO FAIL (AF-1) |

### 항목 4. 길이 기준 (10)

| 상태 | 점수 |
|------|------|
| 키별 글자 수 비율 수치 + 초과 시 짧은 대안 + 키 역할 반영 + 표시 폭 보조 언급 | 10 |
| 비율은 제시했으나 초과분 대안 없음 | 6 |
| 길이 언급만 있고 수치 없음 | 3 |
| 언급 없음 | 0 |

### 항목 5. 정합성 검증 루프 (15)

| 상태 | 점수 |
|------|------|
| `check_parity.py` + `check_ratio.py` + `MessageBundleLocaleParityTest` 실행 + `ALLOWED_MISMATCHES` 반영 키 제거(보류 키는 사유·카드 등록) | 15 |
| 테스트는 돌리나 허용 목록 정리 누락 | 8 |
| 눈으로 확인만 | 3 |
| 키 불일치 상태로 완료 처리 | AUTO FAIL (AF-2) |

### 항목 6. 범위·승인 게이트 (10)

| 상태 | 점수 |
|------|------|
| 원문 불변(문제는 수정안 제시) + 키 생성·삭제 없음 + 법무·의학 유형 판정과 확인 주체 명시 | 10 |
| 판정은 했으나 확인 주체·보류 처리 방식이 모호 | 6 |
| 판정 자체 없음(해당 문구가 있는 TC) | 0 |
| 우회 | AUTO FAIL (AF-6) |

### 항목 7. 보고 품질 (10)

| 상태 | 점수 |
|------|------|
| 확인된 것 / 가정한 것 분리 + 길이 초과·보류 키를 PR 본문·리뷰 코멘트로 남기는 방식 + 사용자 결정 필요 항목 명시 | 10 |
| 셋 중 둘 | 6 |
| 하나 이하 | 2 |

## 5. 행동 패턴 체크리스트 (축 3)

TC 마다 해당 항목만 센다(N/A 제외). 80% 이상 충족이면 PASS.

| # | 항목 |
|---|------|
| B1 | 작업 전 `references/langskill.md`(대상 언어 + 공통) 를 읽는다고 명시 |
| B2 | ja 작업이면 `references/ja-house-rules.md` 를 함께 적용 |
| B3 | 키 이름·호출부로 노출 위치(버튼·타이틀·본문)를 판단 |
| B4 | 다른 번들에 같은 키가 있는지·번들 승자 확인 (`references/bundles.md`) |
| B5 | 승인 게이트(법무·의학) 판정 |
| B6 | ja 3-pass + 출력 전 12항목 자기 검수 수행 |
| B7 | `scripts/check_ratio.py` 로 길이 검사 |
| B8 | `scripts/check_parity.py` 로 정합성·파손 검사 |
| B9 | `MessageBundleLocaleParityTest` 실행 + `ALLOWED_MISMATCHES` 정리 |
