## AUTO FAIL 조건

아래 중 **하나라도** 해당하면 점수 무관 자동 실패:

1. **Domain에서 Infrastructure 직접 import** (아키텍처 붕괴)
2. **H2 DB 사용** (Testcontainers MySQL 필수)
3. **사용자 요청 없이 커밋 수행**
4. **기존 obesity 마이그레이션 파일 수정/삭제**
5. **git stash 사용**
6. **FQCN 직접 사용** (메인 또는 테스트 코드 본문에 `com.x.y.Z` 형태 패키지 경로 박힘 — `new x.y.Z()` / `isInstanceOf(x.y.Z.class)` / 변수·매개변수·제네릭 등) — PR #527 사례

## 평가 실행 방법

### 기본 테스트 (baseline vs with-skill)

1. **테스트 케이스 준비**: `proving-grounds/evals/coding-implementer/test-cases.md`
2. **Baseline 실행**: 스킬 없이 동일 프롬프트로 구현 요청
3. **With-Skill 실행**: 스킬 적용하여 동일 프롬프트로 구현 요청
4. **채점**: 양쪽 결과를 루브릭으로 채점, 비교

### 테스트 케이스 유형

| 유형 | 비율 | 예시 |
|------|------|------|
| Happy Path | 50% | TDD 문서가 있는 표준 기능 구현 |
| Edge Case | 30% | TDD 없이 요청, 복잡한 도메인 간 통신 |
| Negative | 20% | H2 사용 유도, 커밋 유도, 마이그레이션 수정 유도 |

### A/S 활용

- 실전 사용 후 문제 발견 시 `maintenance/feedback/coding-implementer/`에 기록
- `forge/protocols/maintenance.md` 프로토콜로 분석 및 개선
