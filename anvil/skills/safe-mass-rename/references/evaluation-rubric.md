# safe-mass-rename 평가 루브릭

전역 식별자 대형 리네임 사이클을 100점 만점으로 채점한다. 스킬이 산출하는 **커밋 계획 + 각 단계 검증 명령 + 최종 grep 결과**를 평가 대상으로 삼는다.

---

## 평가 항목

| # | 항목 | 배점 | 설명 |
|---|------|------|------|
| 1 | **단계 순서 준수** | 20 | 정의부 → 참조 → 문자열 → 테스트 → 설정/DB → 문서 순서 지킴 |
| 2 | **커밋 세분화** | 20 | 각 단계 독립 커밋. 뭉치기 금지. `refac:` 접두어 |
| 3 | **롤백 브랜치·후방향 호환** | 15 | Phase 2-5 시작 전 롤백 브랜치 명시, Redis/DB는 fallback 사이클 준수 |
| 4 | **grep 잔재 검증** | 15 | 매 단계 후 grep 잔재 0건 확인. 최종 Phase 4에서도 재확인 |
| 5 | **컴파일·테스트 검증 계획** | 10 | 매 단계 후 `./gradlew compileJava`/`test` 계획. Phase 2-1은 예외 인지 |
| 6 | **가드레일 우선 응답** | 10 | 사용자가 뭉치기/혼재 요구해도 하드 가드레일로 거절 후 사유 설명 |
| 7 | **영향 범위 스캔 품질** | 10 | Phase 1 표 형식으로 5카테고리(정의부·참조·문자열·테스트·설정) 각각 파일 수 제시 |
| | **합계** | **100** | |

## AUTO FAIL 조건

다음 중 하나라도 위반하면 즉시 0점 처리:

1. **뭉치기 커밋** — 한 커밋에 여러 단계(정의부 + 참조 + 문자열 등) 동시 변경
2. **리팩터·기능 혼재** — 리네임 커밋에 새 필드·로직·기능 추가 병행
3. **롤백 브랜치 없이 Phase 2-5 시작** — 설정/DB 리네임을 롤백 브랜치 명시 없이 진행
4. **컴파일 실패 무시 후 다음 단계 진행** — Phase 2-2 이후 컴파일 에러가 있는데 문자열/테스트 단계로 전진
5. **`dev`/`main` 브랜치에서 리네임 시작** — 작업 브랜치(`api/refac/{task}`) 없이 진행
6. **Redis/DB 리네임 즉시 교체** — Phase 3 후방향 호환 사이클(양쪽 지원 → 배포 → 구값 제거) 생략

## 채점 가이드

### 항목 1. 단계 순서 준수 (20점)

| 상태 | 점수 |
|------|------|
| 6단계 순서 완벽 준수 | 20 |
| 순서 1단계 뒤바뀜 (예: 문자열 리터럴을 참조보다 먼저) | 12 |
| 순서 여러 단계 뒤바뀜 | 6 |
| 뭉치기 커밋 존재 | AUTO FAIL |

### 항목 2. 커밋 세분화 (20점)

| 상태 | 점수 |
|------|------|
| 각 단계 개별 커밋 + `refac:` 접두어 준수 | 20 |
| 개별 커밋이나 `refactor:` 사용 (Korean Conventional Commits 미준수) | 15 |
| 2개 단계가 한 커밋에 병합 | AUTO FAIL |
| 리팩터·기능 추가 혼재 | AUTO FAIL |

### 항목 3. 롤백 브랜치·후방향 호환 (15점)

| 상태 | 점수 |
|------|------|
| Phase 2-5 전 롤백 브랜치 명시 + Redis/DB fallback 사이클 준수 | 15 |
| 롤백 브랜치는 있으나 fallback 사이클 생략 | 8 |
| 롤백 브랜치 없이 Phase 2-5 시작 | AUTO FAIL |
| Redis/DB 즉시 교체 | AUTO FAIL |

### 항목 4. grep 잔재 검증 (15점)

| 상태 | 점수 |
|------|------|
| 매 단계 후 grep 잔재 0건 확인 명령 제시 + 최종 Phase 4 재확인 | 15 |
| Phase 4만 grep 검증 (중간 단계 검증 생략) | 8 |
| grep 검증 계획 자체가 없음 | 3 |

### 항목 5. 컴파일·테스트 검증 계획 (10점)

| 상태 | 점수 |
|------|------|
| 매 단계 후 `./gradlew compileJava`/`test` 명령 명시. Phase 2-1 예외 인지 | 10 |
| 검증 계획은 있으나 Phase 2-1 예외 미인지 (2-1도 통과 요구) | 6 |
| 검증 계획 자체가 없음 | 2 |

### 항목 6. 가드레일 우선 응답 (10점)

| 상태 | 점수 |
|------|------|
| 사용자 요구가 하드 가드레일 위반 시 거절 + 사유(어느 가드레일인지) 설명 | 10 |
| 거절은 하나 사유 설명 부족 | 6 |
| 사용자 요구 그대로 수용 | AUTO FAIL |

### 항목 7. 영향 범위 스캔 품질 (10점)

| 상태 | 점수 |
|------|------|
| 5카테고리 표 + 각 파일 수 + 예시 파일명 | 10 |
| 표는 있으나 예시 파일명 없음 | 6 |
| grep 명령만 제시, 사용자에게 정리된 결과 없음 | 3 |
