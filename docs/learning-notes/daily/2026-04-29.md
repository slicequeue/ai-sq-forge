## ⑤ 갖춰야 할 소양

### 1) 메타 도구(forge)에도 코드와 같은 검증 엄격도 적용

- **[관찰]** 어제 회귀 평가 4건 보류. forge `CLAUDE.md` 원칙 6번 ("측정 가능 — `/eval-harness` 6축 자동 채점")이 본인의 forge 작업에 가장 마지막까지 적용이 밀림.
- **[반복 비용]** 3~6개월 forge 컴포넌트 30+ 누적 시 "검증 안 한 강화"의 비율이 임계점 돌파 → forge가 사용자에게 거짓 신호 전송 → 본인이 본인 도구에 속음. **발견이 가장 어려운 사고 패턴**.
- **[행동 단위]** 강화·역수입 PR 머지 직전 `/eval-harness {name} --skip-baseline` 명시 호출. PR 본문/머지 코멘트에 평가 점수 기록 (이미 java-spring-coder v1.5에 했던 방식 그대로 4건에도 적용). 머지→평가 후순으로 보내지 않는다.

### 2) 두 번째로 본 패턴은 즉시 추상화 후보로 등록 (Rule of Three 준비)

- **[관찰]** 어제 race 패턴 두 도메인 등장 — Rule of Three 기준 다음 도메인 등장 시 추상화. 그러나 "다음 도메인을 기다리는 슬롯"이 마음/노트에 등록 안 됨. 다음 등장 시에도 인식 못 할 위험.
- **[반복 비용]** 패턴이 5도메인까지 산재 후 발견 시 5곳 회귀 테스트 + 5곳 마이그레이션. 추상화 비용이 가장 비싼 시점에서 처리하게 됨.
- **[행동 단위]** `forge/improvements-roadmap.md` 또는 사내 `docs/patterns-pending/`에 1줄 등록: "race-on-unique-insert (`saveAndFlush` + DIVE catch + 재조회): mission_badge / cgm_device. 다음 1건 등장 시 BaseService·@Aspect 추상화 검토". 다음 도메인에서 라이브러리화 결정이 직관이 아닌 *기록 기반*.

### 3) 사고가 새 어휘를 띄울 때 그날 안에 룰북에 1줄 박기

- **[관찰]** 어제 PR #553 만들면서 "PII / `cause.getMessage()`"라는 새 어휘 영역이 떠올랐는데 forge `pasta-rules` 인덱스나 사내 룰북에 추가 흔적 0.
- **[반복 비용]** 본인 머릿속에만 누적 → 휴가/이직 시 0으로 사라짐. 옆자리 후배는 본인이 내재화한 줄 오해 → 같은 사고 재발. 04-24 ⑤-2 (Claude 체크리스트 일회성 사용)와 같은 축.
- **[행동 단위]** 사고로 새 어휘 등장 시 **그날 안에** `forge/common/pasta-rules/` 또는 사내 룰북에 1줄 PR. PR #553 머지 후 1줄: "`Throwable.getMessage()` 직접 로깅 금지 — `causeType`/클래스명 기준. 이유: PII 의심 (CWE-532)".
