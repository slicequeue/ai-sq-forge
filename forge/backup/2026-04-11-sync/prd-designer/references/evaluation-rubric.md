## 평가 항목 상세

### 1. 기술 용어 격리 (20점) — CRITICAL

PRD에 기술 구현 용어가 포함되지 않았는가?

| 점수 | 기준 |
|------|------|
| 20 | 기술 용어 0건. 기획자가 읽어도 완전히 이해 가능 |
| 10 | 기술 용어 1~2건 포함되었으나 맥락에 영향 없음 |
| 0 | 기술 용어 3건 이상 또는 구현 방법(How)이 포함됨 → **전체 FAIL** |

**검출 대상 용어**: Spring, JPA, Entity, Repository, Controller, Batch, Chunk, API endpoint, DB 컬럼, 클래스명, 패키지 경로, SQL, REST, HTTP

### 2. 요구사항 완성도 (20점)

기능 요구사항이 빈틈 없이 작성되었는가?

| 점수 | 기준 |
|------|------|
| 20 | 모든 기능 요구사항이 번호 체계 + 완전한 문장 + 조건/예외 포함 |
| 15 | 대부분 완전하나 일부 예외 케이스 누락 |
| 10 | 기능 나열은 되었으나 조건/예외가 부족 |
| 5 | 키워드 수준 나열 |
| 0 | 기능 요구사항 섹션 없음 |

### 3. 측정 가능성 (15점)

요구사항과 성공 지표가 측정 가능한 수치로 표현되었는가?

| 점수 | 기준 |
|------|------|
| 15 | 비기능 요구사항 + 성공 지표 모두 구체적 수치 포함 |
| 10 | 일부 항목에 수치, 나머지 "적절히" 류 표현 |
| 5 | 수치가 거의 없음 |
| 0 | "빠르게", "많은", "좋아야 한다" 류만 |

### 4. 사용자 관점 서술 (15점)

사용자 시나리오와 요구사항이 사용자 행동 중심으로 서술되었는가?

| 점수 | 기준 |
|------|------|
| 15 | Who-What-Why 구조 명확, 사용자 행동 → 시스템 반응 흐름 |
| 10 | 사용자 시나리오 있으나 일부 시스템 내부 관점 혼재 |
| 5 | 시스템 내부 관점 위주 |
| 0 | 사용자 시나리오 없음 |

### 5. 구조 준수 (10점)

PRD 문서 구조(9섹션 or 경량 4섹션)를 준수하는가?

| 점수 | 기준 |
|------|------|
| 10 | 복잡도에 맞는 구조를 정확히 준수 |
| 5 | 구조는 따르되 일부 섹션 내용 부실 |
| 0 | 구조 미준수 (자유 형식) |

### 6. 복잡도 적정성 (10점)

기능 복잡도에 맞는 PRD 깊이인가?

| 점수 | 기준 |
|------|------|
| 10 | 복잡도에 딱 맞는 깊이 (경량 기능에 경량 PRD, 복합에 풀 PRD) |
| 5 | 약간의 과설계 또는 과소설계 |
| 0 | 심각한 불일치 (CRUD에 풀 PRD, 복합 기능에 경량 PRD) |

### 7. Open Questions 품질 (10점)

불확실한 부분이 적절히 기록되었는가?

| 점수 | 기준 |
|------|------|
| 10 | 불확실 항목 명시 + 확인 대상자 지정 |
| 5 | 불확실 항목 명시만 (누구에게 확인할지 없음) |
| 0 | Open Questions 섹션 없거나 "없음"으로 처리 (실제로는 불확실한 부분이 있는데) |

## 판정 기준

| 총점 | 판정 | 조치 |
|------|------|------|
| 90~100 | **EXCELLENT** | 실전 배치 가능. 벤치마크로 활용 |
| 75~89 | **PASS** | 실전 배치 가능. 소규모 개선 권장 |
| 60~74 | **CONDITIONAL** | 지적 항목 수정 후 재평가 |
| 0~59 | **FAIL** | 재작성 필요 |
| 항목1 = 0 | **AUTO FAIL** | 기술 용어 격리 실패 → 점수 무관 FAIL |

## 평가 실행 방법

### 테스트 시 (proving-grounds)

1. 테스트 케이스의 기대 결과와 실제 출력물을 대조
2. 위 7개 항목을 각각 채점
3. `proving-grounds/evals/prd-designer/results/` 에 채점 결과 기록

### 실전 A/S 시 (maintenance)

1. 실전 출력물을 이 평가표로 채점
2. 70점 미만 항목을 `maintenance/feedback/prd-designer/` 에 기록
3. 해당 항목 관련 SKILL.md 또는 references 보강

### Baseline 비교 시

동일 프롬프트로:
- **Baseline** (스킬 미사용): 위 기준으로 채점
- **With-Skill**: 위 기준으로 채점
- 점수 차이 + 토큰/시간 비교 → report.md에 기록
