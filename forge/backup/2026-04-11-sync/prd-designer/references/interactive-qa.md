# 인터랙티브 Q&A - 요구사항 끌어내기

사용자가 "~기능 PRD 작성해줘"만 말하고 상세 정보가 부족할 때 사용하는 질문 전략.

## 질문 원칙

1. **한 번에 5개 이하** — 질문이 많으면 사용자가 부담을 느낀다
2. **구체적으로** — "자세히 알려주세요" 대신 "누가 이 기능을 쓰나요?"
3. **선택지 제공** — "알림은 어떤 방식이 좋을까요? (푸시/이메일/인앱 중)"
4. **이미 알고 있는 건 묻지 않는다** — 소스에서 파악한 내용은 확인만
5. **모르겠다는 답도 환영** — Open Questions로 기록하면 됨

## 시나리오별 Q&A 예시

### 시나리오 A: "쿠폰 기능 PRD 작성해줘" (정보 거의 없음)

**1차 질문 (핵심 파악):**

> 쿠폰 기능을 더 구체적으로 이해하고 싶습니다:
> 1. 어떤 문제를 해결하려는 건가요? (예: 신규 유저 유치, 재구매 촉진)
> 2. 쿠폰을 발급하는 주체는 누구인가요? (관리자? 시스템 자동?)
> 3. 사용자가 쿠폰을 쓰는 시나리오를 하나만 설명해주시겠어요?

**사용자 답변 후 2차 질문 (경계 확인):**

> 감사합니다. 범위를 확정하기 위해 몇 가지 더 여쭤봅니다:
> 1. 쿠폰 종류가 여러 개인가요? (정액할인 / 정률할인 / 무료배송 등)
> 2. 이번에 꼭 포함해야 할 것과 다음으로 미뤄도 되는 것이 있나요?
> 3. 쿠폰 만료 정책이 있나요? (발급 후 N일, 특정 날짜 등)

### 시나리오 B: "레이스 자동 완료 기능 PRD 써줘" (어느 정도 맥락 있음)

**1차 질문 (빈틈 확인):**

> 레이스 자동 완료에 대해 대부분 이해했습니다. 확인만 하겠습니다:
> 1. 종료일 기준은 UTC인가요, KST인가요?
> 2. 이미 '취소' 상태인 레이스도 처리 대상에 포함되나요?
> 3. 완료 처리 시 참여자에게 알림을 보내야 하나요?

### 시나리오 C: URL/문서 제공됨

**확인 질문만:**

> 문서를 확인했습니다. 아래 사항만 확인하겠습니다:
> 1. 문서에 없는 내용 중 추가하고 싶은 요구사항이 있나요?
> 2. Out of Scope로 명시하고 싶은 것이 있나요?

## 답변 패턴별 후속 질문

| 사용자 답변 패턴 | 후속 질문 |
|-----------------|-----------|
| "잘 모르겠어요" | → "괜찮습니다. Open Questions로 기록해두겠습니다. 나중에 확인 가능한 사람이 있나요?" |
| 너무 간결함 ("네", "아니요"만) | → 선택지를 제공하여 구체화 유도 |
| 기술 구현 방법을 말함 | → "그 부분은 TDD에서 다루겠습니다. 사용자 입장에서 어떻게 보이면 좋을까요?" |
| 범위가 너무 넓음 | → "전부 중요하겠지만, 이번에 반드시 포함할 핵심 3가지만 고르면?" |
