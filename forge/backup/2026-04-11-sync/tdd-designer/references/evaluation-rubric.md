## 평가 항목 상세

### 1. PRD 소스 명시 (10점) — CRITICAL

TDD가 어떤 PRD/소스를 기반으로 작성되었는지 명시되었는가?

| 점수 | 기준 |
|------|------|
| 10 | PRD 링크 또는 코드 분석 근거가 명확히 명시됨 |
| 5 | 소스가 있으나 링크/근거가 모호 |
| 0 | PRD 소스 미명시 → **전체 FAIL** |

### 2. Phase TODO 구체성 (25점) — 최고 배점

Phase별 TODO가 구현자가 바로 코딩할 수 있을 만큼 구체적인가?

| 점수 | 기준 |
|------|------|
| 25 | 모든 TODO에 패키지 경로 + 클래스명 + 메서드명/역할 명시 |
| 20 | 대부분 구체적, 일부 항목에 클래스명 누락 |
| 15 | 패키지 경로는 있으나 메서드/역할 설명 부족 |
| 10 | 클래스명만 있고 패키지 경로 없음 |
| 5 | "서비스 구현", "레포지토리 구현" 수준 |
| 0 | TODO 없음 또는 의미 없는 나열 |

### 3. 아키텍처 적합성 분석 (15점)

프로젝트 규칙/기존 패턴과의 정합성을 분석했는가?

| 점수 | 기준 |
|------|------|
| 15 | 모듈 + 패턴 + 보안 + 환경변수 + 우려 지점까지 구체적 분석 |
| 10 | 모듈/패턴 분석은 있으나 보안/환경변수 확인 누락 |
| 5 | "기존과 호환" 수준의 근거 없는 분석 |
| 0 | 아키텍처 분석 섹션 없음 |

### 4. 테스트 전략 (15점)

계층별 테스트 계획이 구체적인가?

| 점수 | 기준 |
|------|------|
| 15 | 계층별 테스트 클래스명 + 방식 + 검증 내용 표로 정리 |
| 10 | 계층별 구분은 있으나 테스트 클래스/검증 내용 부족 |
| 5 | "테스트 작성" 수준 |
| 0 | 테스트 전략 없음 |

### 5. 커밋 계획 & 파일 목록 (10점)

Phase별 커밋 메시지와 대상 파일이 명시되었는가?

| 점수 | 기준 |
|------|------|
| 10 | 모든 Phase에 커밋 메시지 + 대상 파일 목록 |
| 7 | 커밋 메시지는 있으나 파일 목록 누락 |
| 3 | 일부 Phase에만 커밋 계획 |
| 0 | 커밋 계획 없음 |

### 6. 다이어그램 품질 (10점)

Mermaid 다이어그램이 적절히 포함되었는가?

| 점수 | 기준 |
|------|------|
| 10 | 복잡도에 맞는 다이어그램 + 한글 Note 주석 |
| 7 | 다이어그램 있으나 Note 주석 없음 |
| 3 | 다이어그램이 있으나 부정확하거나 불완전 |
| 0 | 복합 기능인데 다이어그램 없음 (경량은 없어도 감점 없음) |

### 7. 복잡도 적정성 (5점)

기능 복잡도에 맞는 TDD 깊이인가?

| 점수 | 기준 |
|------|------|
| 5 | 복잡도에 딱 맞는 깊이 |
| 3 | 약간의 과설계/과소설계 |
| 0 | 심각한 불일치 |

### 8. 가드레일 준수 (10점) — CRITICAL

하드 가드레일을 위반하지 않았는가?

| 점수 | 기준 |
|------|------|
| 10 | 모든 가드레일 준수 |
| 5 | 소프트 가드레일 1~2건 미준수 |
| 0 | 하드 가드레일 위반 → **전체 FAIL** |

**하드 가드레일 위반 검출 항목**:
- H2 사용 제안 (Testcontainers 원칙 위반)
- 기존 마이그레이션 파일 수정 제안
- 패키지 경로 없는 TODO를 "완성"으로 처리
- PRD 소스 없이 TDD 작성

## 판정 기준

| 총점 | 판정 | 조치 |
|------|------|------|
| 90~100 | **EXCELLENT** | 실전 배치 가능. 벤치마크로 활용 |
| 75~89 | **PASS** | 실전 배치 가능. 소규모 개선 권장 |
| 60~74 | **CONDITIONAL** | 지적 항목 수정 후 재평가 |
| 0~59 | **FAIL** | 재작성 필요 |
| 항목1 = 0 | **AUTO FAIL** | PRD 소스 미명시 → 점수 무관 FAIL |
| 항목8 = 0 | **AUTO FAIL** | 가드레일 위반 → 점수 무관 FAIL |

## 평가 실행 방법

### 테스트 시 (proving-grounds)

1. 테스트 케이스의 기대 결과와 실제 출력물을 대조
2. 위 8개 항목을 각각 채점
3. `proving-grounds/evals/tdd-designer/results/` 에 채점 결과 기록

### 실전 A/S 시 (maintenance)

1. 실전 출력물을 이 평가표로 채점
2. 70점 미만 항목을 `maintenance/feedback/tdd-designer/` 에 기록
3. 해당 항목 관련 SKILL.md 또는 references 보강

### Baseline 비교 시

동일 프롬프트로:
- **Baseline** (스킬 미사용): 위 기준으로 채점
- **With-Skill**: 위 기준으로 채점
- 점수 차이 + 토큰/시간 비교 → report.md에 기록

### Phase TODO 구체성 빠른 체크 (항목 2번)

모든 TODO 항목에 대해 아래 3가지가 있는지 빠르게 스캔:
1. 패키지 경로 (`src/main/java/...`) — 없으면 즉시 감점
2. 클래스명 (`RaceCompletionService`) — 없으면 감점
3. 역할/메서드 설명 (`completeExpiredRaces() 구현`) — 없으면 소폭 감점
