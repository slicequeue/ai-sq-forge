# PRD Template Guide (Admin)

## 목적
- PRD는 구현 지시서가 아니라 **문제/목표/수용기준 합의 문서**다.
- 개발자뿐 아니라 기획/운영도 바로 이해할 수 있어야 한다.

## 필수 섹션
1. 기능 개요(배경, 목표, 사용자, 성공 조건)
2. 범위(In/Out)
3. 사용자 시나리오(정상/예외/권한 미보유)
4. 기능 요구사항(FR-ID + 우선순위 + 수용 기준)
5. 비기능 요구사항(보안, 성능, 운영성)
6. Open Questions

## 작성 규칙
- “어떤 상태가 되면 완료인가”를 수용 기준으로 명시한다.
- 메뉴 진입 경로와 관리자 역할을 항상 명시한다.
- admin history 기대치(조회/변경 로그)를 요구사항에 포함한다.

## 금지
- 클래스명, 패키지명, SQL, 라이브러리 선택 등 구현 상세 기입 금지.
