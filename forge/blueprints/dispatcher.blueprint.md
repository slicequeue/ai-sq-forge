# Dispatcher Blueprint

디스패처는 사용자 요청을 분석하여 적절한 스킬/체인/에이전트로 라우팅하는 진입점이다.

## 디렉토리 구조

```
anvil/dispatchers/{dispatcher-name}/
├── DISPATCHER.md           # 디스패처 정의 (라우팅 규칙)
└── references/             # 선택
```

## DISPATCHER.md 템플릿

```markdown
---
name: {dispatcher-name}
description: "{한 줄 설명}"
scope: "{이 디스패처가 담당하는 영역}"
---

# {dispatcher-name} - {라우팅 영역}

## 라우팅 매트릭스

| 사용자 요청 패턴 | 키워드/의도 | 라우팅 대상 | 대상 유형 |
|-----------------|------------|------------|-----------|
| "PRD 작성해줘" | PRD, 기획, 요구사항 | prd-plan-designer | skill |
| "코드 리뷰해줘" | 리뷰, 코드 검토 | code-reviewer | skill-chain |
| ... | ... | ... | ... |

## 의도 분석 규칙

### 우선순위
1. **정확 매칭**: 슬래시 커맨드 → 해당 커맨드 직접 실행
2. **키워드 매칭**: 라우팅 매트릭스의 키워드와 일치
3. **의미 매칭**: 키워드 불일치지만 의도가 명확한 경우
4. **불확실**: 사용자에게 확인 질문

### 모호한 요청 처리
- 2개 이상의 대상이 후보일 때 → 사용자에게 선택지 제시
- 어떤 대상에도 매칭되지 않을 때 → 범위 밖 안내 + 가능한 대안 제시

## 가드레일

- 디스패처는 작업을 직접 수행하지 않는다 — 라우팅만 담당
- 라우팅 대상이 존재하는지 확인 후 전달 (없는 스킬로 라우팅 금지)
- 라우팅 결정 근거를 사용자에게 간결히 안내
```

## 설계 원칙

- **라우팅만** — 디스패처가 작업을 직접 수행하면 설계 위반
- **확장 가능** — 새 스킬/체인 추가 시 라우팅 매트릭스에 행 추가만으로 연동
- **투명성** — 왜 이 대상으로 라우팅했는지 사용자가 알 수 있어야 함
