# Planning Before Implementation (구현 전 계획 수립)

AI 도구(Claude Code, Cursor 등)와 협업할 때, **코드 수정 전에 계획을 먼저 제시**하고 승인을 받는다.

## 1. 계획 필수 상황

아래 상황에서는 코드 수정 전에 반드시 계획을 먼저 제시한다:

| 상황 | 예시 |
|------|------|
| **멀티파일 변경** | 3개 이상 파일 수정이 예상되는 작업 |
| **신규 기능 구현** | 새 API, 새 도메인 엔티티, 마이그레이션 포함 |
| **리팩토링** | 패키지 이동, 클래스 분리/병합, 패턴 변경 |
| **TDD 작업** | 테스트 → 구현 → 리팩토링 사이클 시작 전 |
| **아키텍처 변경** | 계층 간 의존성, Client 패턴 도입 |

## 2. 계획 필수 아닌 상황

아래 상황에서는 계획 없이 바로 실행해도 된다:

- 단일 파일의 단순 수정 (오타, 한 줄 수정)
- 사용자가 명시적으로 "바로 해" / "그냥 해" 라고 지시
- 이미 합의된 계획에 따른 후속 작업

## 3. 계획 형식

```markdown
## 작업 계획

### 수정 대상 파일
1. {파일 경로} — {변경 내용 한 줄 요약}
2. ...

### 접근 방식
- {핵심 접근 방식 2~3줄}

### 테스트 전략
- {어떤 테스트를 작성/실행할지}

### 확인 사항
- {전제 조건, 리스크, 사용자에게 확인받을 가정}
```

## 4. 검증 없이 단정 금지

코드나 설정 상태를 **확인하지 않고 단정하지 않는다**:
- "이 설정은 없습니다" → 반드시 grep/find로 확인 후 판단
- "이 클래스는 사용되지 않습니다" → 반드시 사용처 검색 후 판단
- "이 기능은 지원되지 않습니다" → 반드시 문서/코드 확인 후 판단

잘못된 가정에 기반한 구현은 전체 재작업으로 이어진다.
