# Design Protocol - Q&A 기반 컴포넌트 설계

새 컴포넌트를 만들기 전에 반드시 이 프로토콜을 따른다. 즉시 구현하지 말고, 문답을 통해 설계를 확정한다.

---

## Phase 1. 의도 파악 (What & Why)

사용자에게 아래 질문을 통해 핵심을 확정한다. 이미 답변된 항목은 건너뛴다.

### 필수 질문

1. **무엇을 만들고 싶은가?**
   - 어떤 작업을 자동화/지원하려는가?
   - 현재 이 작업을 어떻게 하고 있는가? (현재의 불편함)

2. **어떤 유형이 적합한가?**
   - 사용자가 이미 유형을 지정한 경우 → 확인만
   - 불확실한 경우 → 아래 판단 기준 제시

   | 상황 | 추천 유형 |
   |------|-----------|
   | 단일 작업, 자동 트리거 원함 | Skill |
   | 복잡한 판단이 필요한 전문 영역 | Agent |
   | 빠른 단일 명령 | Command |
   | 여러 단계를 순서대로 | Skill Chain |
   | 요청을 분류해서 분배 | Dispatcher |

3. **트리거 조건은?**
   - 어떤 키워드/상황에서 실행되어야 하는가?
   - 슬래시 커맨드 이름 선호가 있는가?

4. **예상 출력물은?**
   - 파일 생성? 코드 수정? 분석 결과? 의사결정 지원?

### 선택 질문 (필요시)

5. 연동해야 할 외부 도구/MCP가 있는가?
6. 기존 컴포넌트와 조합해야 하는가?
7. 특정 프로젝트에 종속적인가, 범용적인가?

---

## Phase 2. 경계 설정 (Scope & Guardrails)

### 범위 확정

사용자와 함께 아래를 정리한다:

```markdown
## 범위 정의
- **In Scope**: {이 컴포넌트가 하는 것}
- **Out of Scope**: {이 컴포넌트가 하지 않는 것}
- **하드 가드레일**: {절대 위반 불가 규칙}
- **소프트 가드레일**: {권장하지만 상황에 따라 유연}
```

### 판단 기준 확인

- 모호한 입력이 들어왔을 때 어떻게 처리할 것인가?
- 실패 시 어떻게 대응할 것인가? (재시도 / 중단 / 질문)

---

## Phase 3. 레퍼런스 수집

### 기존 자원 확인

1. `anvil/` 내 유사한 기존 컴포넌트가 있는지 확인
2. 참고할 외부 스킬이 있는지 확인 (Anthropic skills repo 등)
3. 사용자가 참고 자료(URL, 문서, 대화 로그)를 제공하는지 확인

### 구조 설계

- SKILL.md/AGENT.md 본문에 넣을 내용 vs references/로 분리할 내용 결정
- 기준: 본문 400줄 이내, 코드 예시 3개 이상이면 분리

---

## Phase 4. 초안 작성 & 확인

1. 해당 유형의 블루프린트(`forge/blueprints/{type}.blueprint.md`) 로드
2. Phase 1~3 결과를 반영하여 초안 작성
3. 사용자에게 초안 제시 → 피드백 수렴
4. 피드백 반영 후 최종 확정

---

## Phase 5. 구현 & 테스트 연결

1. `anvil/{type}/{name}/` 에 컴포넌트 생성
2. `anvil/INDEX.md` 에 등록
3. `forge/protocols/testing.md` 프로토콜로 기본 테스트 진행
