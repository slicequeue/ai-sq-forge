## 문제

저장소에 `.github/PULL_REQUEST_TEMPLATE.md` 가 있는데도 `## Why` / `## 측정` / `## 배포` / `## Test` 라는 자체 제목으로 PR 본문을 작성했다. 사용자 지적 후 전면 재작성.

**주목할 점**: 이 시점에 `pr-feedback-resolver` 스킬이 정상 발동한 상태였다. 스킬이 켜져도 본문에 없는 규칙은 지켜지지 않는다는 근거다.

## 원인 분석

두 스킬 모두 "PULL_REQUEST_TEMPLATE" 언급이 0건이었다. `git-pr` 은 pasta 템플릿과 같은 섹션명을 **하드코딩**해 뒀을 뿐, "저장소 템플릿 파일을 읽어라"는 절차가 없었다. 그래서 선택 섹션(측정 결과·배포)을 추가하는 과정에서 필수 섹션명이 축약돼도 걸러지지 않았다.

당시 교훈은 프로젝트 메모리 `feedback_pr_body_format` 에만 기록되고 forge 로 승격되지 않았다.

## 개선 방안

- `git-pr` Phase 2-0 신설 — 본문 작성 전 템플릿 존재 확인, 있으면 섹션명을 이모지까지 문자 그대로 사용. 선택 섹션은 템플릿 필수 섹션을 모두 채운 뒤 조건부 추가
- 2-3 판단표에 "템플릿이 이 표보다 우선" 명시

- `pr-feedback-resolver` 하드 가드레일에 동일 항목 + 파괴적 쓰기 가드 참조
