## 신설 계기

사용자 초기 재설계 제안(2026-07-09 오후)에서 4가지 관점(아키텍처·비즈니스 로직·보안·성능) 중 **비즈니스 로직**만 유예됐음. 리뷰 스킬 세분화 사이클 3(같은 날 저녁)에서 신설 결정.

**결정 근거**: prd-plan-designer v1.0 (PRD↔TDD)와 층위 다름. 이 스킬은 **문서↔코드** 검증.

## v0.1 정체성

백엔드 Java Spring Boot 코드의 **비즈니스 로직·요건 준수 관점 전용 리뷰**.

## 스코프

- PRD 수용 기준 vs 구현 정합성
- TDD 설계 vs 실제 계층·API·엔티티
- 엣지 케이스 사각지대 (요건에 명시된 예외 경로 누락)
- **도메인 불변식 준수** (예: "결제 완료 후 취소 불가" — MISSION #633 뱃지 중복 발급 관련 패턴)
- 비즈니스 예외 경로 (실패·에러 노출 정확성)

## 하드 가드레일 5건 (AUTO FAIL)

- BIZ-HG-1 문서(PRD/TDD) 없이 진행 금지
- BIZ-HG-2 임의로 요건 해석·확장 금지
- BIZ-HG-3 코드 매칭 근거(파일:라인) 없이 "매핑됨" 판정 금지
- BIZ-HG-4 도메인 불변식 위반 발견 시 반드시 최우선 보고
- BIZ-HG-5 코드 자의적 수정 금지
