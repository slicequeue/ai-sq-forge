## 문제

테스트 코드 mock 셋업과 AssertJ 검증에서 클래스 import 없이 전체 패키지 경로를 직접 사용:

```java
// 패턴 1 — 예외 인스턴스 생성 (mock willThrow)
.willThrow(new org.springframework.dao.DataIntegrityViolationException("duplicate"));

// 패턴 2 — .class 리터럴 (assertThatThrownBy.isInstanceOf)
.isInstanceOf(org.springframework.dao.DataIntegrityViolationException.class)
```

프로젝트 규칙(`forge/common/pasta-rules/07-general-project-convention.md:26`)에 명시된 "Explicit Imports — 전체 패키지 경로 직접 사용 금지"를 위반.

## 수정 내용 (2ef1c767cd)

```diff
+ import org.springframework.dao.DataIntegrityViolationException;
...
- .willThrow(new org.springframework.dao.DataIntegrityViolationException("duplicate"));
+ .willThrow(new DataIntegrityViolationException("duplicate"));

- .isInstanceOf(org.springframework.dao.DataIntegrityViolationException.class)
+ .isInstanceOf(DataIntegrityViolationException.class)
```

## 원인 분석

1. **AI가 자주 저지르는 mock 작성 패턴**: "한 번만 쓰는 예외니까 import 추가 없이 인라인으로 박자" — 테스트 코드 작성 시 import 누적을 미루다 잊는 휴리스틱.
2. **생성 스킬 가드레일 누락**: `java-spring-coder`/`java-layered-unit-testing` 가드레일은 "와일드카드 import 금지"만 있고 "FQCN 직접 사용 금지" 항목 없음. 프로젝트 규칙에는 있으나 스킬에 단단히 못 박혀 있지 않아 가끔 누수.
3. **자체 리뷰 스킬 검출 누락**: `self-code-reviewer/references/review-checklist.md`도 동일 — 와일드카드만 체크. 검출 누락 → 휴먼 리뷰 단계까지 흘러감.
4. **테스트 파일 경시 가능성**: 자체 리뷰가 메인 코드 위주로 보고 테스트 파일 import 검사가 약했을 가능성. 검토 필요.

## 개선 방안

### 1. 생성 스킬 — 하드 가드레일 추가

`java-spring-coder/SKILL.md`, `java-layered-unit-testing/SKILL.md`에:

> **FQCN 직접 사용 금지** — 모든 외부 클래스(예외 인스턴스 생성, `.class` 리터럴, 어노테이션, 제네릭, 매개변수, 변수 선언 모두 포함)는 반드시 `import` 선언 후 단순 클래스명 사용. **메인+테스트 코드 동일 적용**. mock 예외(`new x.y.Z()`)와 `isInstanceOf(x.y.Z.class)` 패턴이 가장 자주 누수되는 지점.

### 2. self-code-reviewer — 체크리스트 + AUTO FAIL

- `review-checklist.md` "7. 일반 규칙"에 항목 추가: `[ ] FQCN 직접 사용 없는가? (변수/매개변수/제네릭/예외 생성/.class 리터럴 — 메인+테스트 모두)`
- SKILL.md에 "FQCN 사용 발견 시 AUTO FAIL 후보로 보고" 명시
- 검출 룰: 정규식 `[a-z][a-z0-9.]+\.[A-Z][A-Za-z0-9_]*` 형태가 import 문이 아닌 코드 본문에 등장하는지 검사 (단, 어노테이션 인자 문자열·SpEL은 제외)

### 3. 하네스 Negative TC 추가

3개 스킬 하네스에 각각:
- 생성 스킬: "FQCN 포함 출력 → AUTO FAIL"
- self-code-reviewer: "입력 코드에 FQCN 포함 → 검출 못하면 FAIL"
