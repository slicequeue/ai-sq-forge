## v1.13 개선 반영

**신규 섹션**: 외부 이벤트 전송 아웃박스(Outbox) 패턴 + 재전송 배치

**패턴**:
1. **아웃박스 테이블**: 외부 이벤트 전송 요청을 DB 아웃박스에 먼저 저장 (트랜잭션 안)
2. **비동기 발행**: 커밋 후 별도 스레드/스케줄러가 아웃박스 → 외부 전송
3. **실패 재시도**: 발행 실패는 아웃박스에 재시도 카운트·다음 시도 시각 갱신
4. **정리 배치**: 성공한 이벤트는 일정 기간 보관 후 정리 (감사 로그 목적)
5. **모니터링**: 재시도 카운트 임계·오래 pending 이벤트 알럿

**연관 v1.11 룰**: 캐시 pub-sub 발행 실패 흡수 원리와 유사 — 커밋 성공 우선, 외부 통신 실패는 자가 치유(아웃박스)

**자기 검증 #41 추가**: 외부 이벤트 전송 로직에 아웃박스·재시도 배치 존재 여부
