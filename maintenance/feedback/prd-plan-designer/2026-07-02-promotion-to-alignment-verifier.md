## 격상 배경

v0.2 시점에 이 에이전트는 3개 PRD 스킬(`prd-designer` / `tdd-designer` / `admin-prd-plan-designer`)과 **본질적으로 같은 영역**(문서 작성)을 다뤘음. 차별 가치는 "PRD + TDD 통합 산출"뿐 — 사용자가 두 스킬을 순차 호출하면 동등한 결과라 본질이 약함.

v0.2 통합 검토 시 3개 옵션 병기:
- **A안**: PRD ↔ TDD Alignment 자동 검증자
- **B안**: PRD-First 사이클 오케스트레이터
- **C안**: 폐기

## A안 선정 사유

### 본질 차별화 명확
- 3개 스킬은 **각자 단일 문서 작성** 담당 — 이 에이전트는 **문서 간 관계 검증** 담당 → 층위 완전 분리
- 문서를 만들지 않고 이미 있는 문서를 감사 → 역할 중복 완전 제거

### coding-implementer v0.4와 결합 가치
- coding-implementer Phase 2 "계획 확인" 단계에서 이 에이전트를 호출해 PRD·TDD 정합성 감사 → 통과 후 Phase 3 구현 사이클 진입 가능
- 구현 사이클 시작 전 "요구사항 누락·불일치가 없다"는 게이트 역할

### B안 대비 우위
- B안(PRD-First 사이클)은 coding-implementer v0.3 격상과 역할 겹침 위험 있었음
- A안은 오케스트레이터(coding-implementer)와 감사자(이 에이전트)로 역할 분리 → 각자 본질 강화

### C안 대비 우위
- 폐기하면 실전 pasta-japan-server에서 역수입된 노력이 소실
- 검증자 역할은 forge에 부재하던 영역이라 신설 가치 있음

## v1.0 격상 내용

### 정체성 재정의
- 기존: "PRD + TDD 통합 산출자"
- 신규: **"PRD ↔ TDD 정합성 감사자 — 매핑 표 자동 생성 + 누락 지적"**

### 본문 재구성 (395줄 → ~230줄)
- 기존 v0.2의 PRD/TDD 작성 본문(Part A, Part B)은 각 스킬 위임으로 일원화 — 중복 정의 제거
- Phase 0~4 워크플로 신설:
  - Phase 0: 현황 점검 (두 문서 위치 확인)
  - Phase 1: 매핑 표 생성 (3열, 4상태 분류)
  - Phase 2: 정합성 검증 (커버리지 + 정당성 + 용어 일관성 3검사)
  - Phase 3: 지적 보고서 작성 (누락·오버 스코프·불일치 각각 재호출 지시)
  - Phase 4: 정본화 (사용자 승인 후)

### 하드 가드레일 5건
1. PRD·TDD 없이 진행 금지
2. 임의 수정 금지 (오직 지적만)
3. 근거 불명확한 "매핑됨" 표기 금지
4. 사용자 정본 판정 없이 자동 결정 금지
5. 문서만 보고 코드 추측 금지

### 자기 검증 10항목 신설

### 상태 4분류
- ✅ 매핑됨 / ⚠️ 누락 / 🔴 오버 스코프 / 🟡 용어 불일치

## 개선 효과 예상

| 사용자 요청 | 이전 (v0.2) | 격상 후 (v1.0) |
|------------|-------------|---------------|
| "PRD랑 TDD 정합성 확인" | 스킬 부재 → 사용자 수동 감사 | 이 에이전트가 매핑 표 + 지적 보고서 자동 생성 |
| "TDD가 PRD 다 반영했는지" | 사람이 대조 | Phase 2 검사 A 자동 |
| "PRD + TDD 둘 다 한 번에" | 이 에이전트로 통합 산출 | `prd-designer` → `tdd-designer` 순차 (권장) |

## 잠재 리스크

1. **문서 형식 의존**: PRD·TDD가 forge 표준 구조(prd-designer v1.2 / tdd-designer v1.4)를 따르지 않으면 매핑 표 생성이 어려워짐 → Phase 0에서 표준 준수 확인
2. **코드 검증 필요성**: TDD 항목이 실제 코드로 구현됐는지까지 감사하려면 코드 스캔 필요 — v1.0에서는 문서 대조에만 한정 (하드 가드레일 5번). 코드 검증은 self-code-reviewer 등 다른 스킬 몫
3. **정본화 파일 위치**: `docs/alignment/*` 신규 경로 도입 — pasta-rules에 반영 필요할 수 있음
