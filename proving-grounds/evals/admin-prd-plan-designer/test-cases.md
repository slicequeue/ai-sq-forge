# admin-prd-plan-designer 테스트 케이스

## TC-1: Happy Path — 충분한 맥락이 주어진 admin 기능 HYBRID 문서 요청

- **입력 프롬프트**: "admin 모듈에 새로운 일괄 쿠폰 발급 관리 기능을 추가하려 합니다. 현재 운영팀이 DB를 직접 조작해서 쿠폰을 발급하고 있어요. 관리자가 대상 사용자를 선택하고 쿠폰 종류/수량을 지정해서 일괄 발급할 수 있는 화면이 필요합니다. 발급 이력도 조회 가능해야 합니다. HYBRID 문서로 작성해주세요."
- **기대 결과**: HYBRID 타입 문서, admin 컨텍스트 반영, 멀티턴 합의 수행, Alignment 매핑 표 포함
- **검증 기준**:
  - [ ] HYBRID 타입으로 문서 작성 (PRD + TDD 통합)
  - [ ] admin 컨텍스트 반영 (SSR/sidebar/security/history 중 해당 항목 포함)
  - [ ] 멀티턴 합의 루프 수행 (범위·우선순위 질문)
  - [ ] Alignment 매핑 표 포함 (기능 요구사항 ↔ 기술 설계 매핑)
  - [ ] Phase 체크리스트 포함 (개발자 착수 가능 수준)
  - [ ] 결정 로그 또는 Decision Log 기록
  - [ ] Open Questions 섹션 존재
- **유형**: happy-path

## TC-2: Edge Case — 정보가 부족한 모호한 admin 기능 요청

- **입력 프롬프트**: "admin 기능 하나 기획해줘"
- **기대 결과**: 바로 작성하지 않고 멀티턴 합의 루프 진입, 문서 타입·기능 범위 질문
- **검증 기준**:
  - [ ] 즉시 문서를 작성하지 않음 (정보 부족 인지)
  - [ ] 문서 타입 확인 질문 (PRD/TDD/HYBRID 중 어떤 문서가 필요한지)
  - [ ] 기능 범위 확인 질문 (어떤 admin 기능을 기획할지)
  - [ ] 질문이 구체적임 ("자세히 알려주세요" 류가 아님)
  - [ ] 사용자와 합의 없이 독단적으로 범위를 결정하지 않음
- **유형**: edge-case

## TC-3: Negative — 문서보다 코드 우선 작성 요청

- **입력 프롬프트**: "admin 쿠폰 발급 화면의 Spring Controller 코드랑 Template HTML을 먼저 작성하고, 그걸 기반으로 PRD를 작성해줘"
- **기대 결과**: 코드 먼저 작성 거부, 문서 우선 원칙 안내, PRD/TDD 스킬로 안내
- **검증 기준**:
  - [ ] 코드(Controller, Template HTML)를 먼저 작성하지 않음
  - [ ] 문서 우선 원칙을 안내 (문서 → 코드 순서)
  - [ ] PRD 또는 TDD 문서를 먼저 작성할 것을 제안
  - [ ] 구현 코드/커밋으로 점프하지 않음 (AUTO FAIL #5 준수)
- **유형**: negative
