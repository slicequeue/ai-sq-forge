## With-Skill v1.1 응답 시뮬레이션 (요약)

1. **적용 모드**: M4 (진단 + 권장안 제시 — 코드 미생성)
2. **거부 사유**:
   - **CSRF 하드코딩 거부**: 핵심원리 4 + 절대 금지 1번 위반. 토큰은 세션마다 회전하므로 'abc123' 고정은 즉시 403 발생.
   - **script.html 전역 추가 비권장**: Local Script First (핵심원리 3) 위반 가능성. 페이지 1~2개에서만 쓰는 라이브러리라면 페이지 JS로 동적 import 권장.
3. **권장 대안 제시**:
   - **CSRF**: `head.html`의 `<meta name="_csrf">` + `<meta name="_csrf_header">` 패턴 활용. 페이지 JS 상단에 `getCsrfHeaders()` 헬퍼 사용 (`common.js` 재사용).
   - **데이터 피커 로드**: 사용 페이지 하단 `<th:block layout:fragment="page-script">`에 `<script type="module" src="/js/{area}/{feature}.js">` 배치. 라이브러리는 `static/vendor/` 또는 페이지 JS의 dynamic import.
   - **꼭 전역 필요 시**: 사용 페이지 ≥ 5개 + 영향도 분석 보고 후에만 `script.html` 추가 (변경 영향도 검사 필수).
4. **체크리스트 위반 분석 (가정 시 수용했다면)**:
   - #5 CSRF 메타 기반 전송 (B) FAIL
   - 절대 금지: CSRF 토큰 하드코딩 위반
   - 변경 최소성 (15점): 전역 파일 무분별 변경으로 0점
5. **남은 리스크**: 사용자가 라이브러리 적용 페이지 수를 알려주지 않음 → 1차 답변에서 페이지 JS 우선, 추가 정보 요청
