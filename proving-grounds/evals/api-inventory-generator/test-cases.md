# api-inventory-generator 테스트 케이스

## TC-1: Happy Path — 표준 프로젝트에서 API 스캔

- **입력 프롬프트**: "프로젝트의 전체 API 목록을 생성해줘. 모듈별, 인증 유형별로 정리해서 문서화해줘."
- **기대 결과**: 스크립트 실행, 문서 생성, 통계 보고
- **검증 기준**:
  - [ ] scan-apis.py 또는 scan-apis.sh 스크립트를 실행
  - [ ] 출력 파일 경로를 보고
  - [ ] 총 컨트롤러 수와 엔드포인트 수를 보고
  - [ ] 인증별 통계(Bearer/Dashboard/없음/미분류)를 보고
  - [ ] 수작업으로 목록을 직접 작성하지 않음
  - [ ] build/, .gradle/ 등 빌드 산출물 미포함
- **유형**: happy-path

---

## TC-2: Edge Case — 커스텀 출력 경로 + 미분류 항목 설명

- **입력 프롬프트**: "API 목록을 docs/reports/ 디렉토리에 생성해줘. 인증 유형이 '?'로 나오는 항목은 왜 그런지도 설명해줘."
- **기대 결과**: 커스텀 경로로 출력, 미분류 항목 원인 설명 (base_path 누락 등)
- **검증 기준**:
  - [ ] 스크립트에 커스텀 출력 경로 인자 전달
  - [ ] '?' 미분류 항목에 대한 원인 설명 (base_path 미정의 등)
  - [ ] 프로젝트 루트 위치 사전 확인
- **유형**: edge-case

---

## TC-3: Negative — 수작업 목록 작성 유도

- **입력 프롬프트**: "스크립트 없이 프로젝트의 Controller를 직접 읽어서 API 목록을 표로 정리해줘"
- **기대 결과**: 수작업 거부, 스크립트 실행 안내
- **검증 기준**:
  - [ ] 수작업 API 목록 직접 작성을 거부
  - [ ] scan-apis.py/sh 스크립트 실행을 안내
  - [ ] 스크립트의 장점(정확성, 일관성) 설명
- **유형**: negative
