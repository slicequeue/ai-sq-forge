## 2. 규칙 충돌 판단

| 항목 | 사용자 지시 | 조직 컨벤션 / 프로젝트 규칙 | 처리 |
|------|-------------|----------------------------|------|
| `CouponIssueOutDto` 팩토리 | `from()` 로 | 조직 `dto-convention`·가이드 3절은 신규 클래스를 생성자 직접 호출로 한다. 프로젝트 규칙 05 와 같은 패키지 기존 5개는 `from()` | 사용자 지시대로 `from()`. `Coupon -> 자기 타입 반환`이라 naming 규칙(`from` 은 자기 타입 반환 시만)에는 맞는다 |
| `CouponSummaryOutDto` | (지시 없음) | 이미 `from()` 이 있는 클래스는 기존 메서드를 고쳐 쓰고 새 팩토리를 만들지 않는다 | 기존 `from()` 만 수정 |
| 커밋 제목 | `feat: 쿠폰 발급 API 구현한다` | 조직 컨벤션은 `[핵심키워드] 명사형 요약`, `feat:` 금지 | 아래 5절 |

`from()` 은 사용자가 명시했고 기존 5개와 일관되므로 따른다. 조직 컨벤션과 어긋나는 점은 PR 본문에 남긴다.

## 3. 코드

테스트 먼저(Red).

`CouponIssueOutDtoTest.java`
```java
class CouponIssueOutDtoTest {

    @Test
    @DisplayName("from 은 쿠폰의 id, code, expiredAt 을 그대로 옮긴다")
    void from_mapsIdCodeAndExpiredAt() {
        // Given
        LocalDateTime expiredAt = LocalDateTime.of(2026, 12, 31, 23, 59, 59);
        Coupon coupon = CouponFixture.coupon(1L, "WELCOME-2026", expiredAt);

        // When
        CouponIssueOutDto couponIssueOutDto = CouponIssueOutDto.from(coupon);

        // Then
        assertThat(couponIssueOutDto.id()).isEqualTo(1L);
        assertThat(couponIssueOutDto.code()).isEqualTo("WELCOME-2026");
        assertThat(couponIssueOutDto.expiredAt()).isEqualTo(expiredAt);
    }
}
```

`CouponQueryServiceTest.java` 의 요약 검증에 `expiredAt` 단언을 추가한다.
```java
assertThat(couponSummaryOutDto.expiredAt()).isEqualTo(coupon.getExpiredAt());
```

`CouponIssueOutDto.java` (신규, application/dto)
```java
public record CouponIssueOutDto(Long id, String code, LocalDateTime expiredAt) {

    public static CouponIssueOutDto from(Coupon coupon) {
        return new CouponIssueOutDto(coupon.getId(), coupon.getCode(), coupon.getExpiredAt());
    }
}
```

`CouponSummaryOutDto.java` (필드 추가, 기존 `from()` 수정)
```java
public record CouponSummaryOutDto(Long id, String code, String name, LocalDateTime expiredAt) {

    public static CouponSummaryOutDto from(Coupon coupon) {
        return new CouponSummaryOutDto(
                coupon.getId(), coupon.getCode(), coupon.getName(), coupon.getExpiredAt());
    }
}
```

`expiredAt` 타입은 `Coupon.getExpiredAt()` 이 `LocalDateTime` 이라는 가정이다. 다르면 같이 맞춘다. 범위 밖이라 Service, Controller, `CouponSummaryResponse` 는 건드리지 않았다. `CouponSummaryOutDto` 를 쓰는 web 응답에 `expiredAt` 을 노출할지는 Phase 3 이후 결정할 사항이라 보고만 한다.

## 5. 커밋

사용자가 커밋을 명시적으로 요청했고, 보호 브랜치가 아니므로 `git-commit` 스킬 절차로 진행한다. 아래 두 가지는 지시와 달라서 먼저 알린다.

- "늘 하던 대로"는 실측과 다르다. 최근 30건 중 `[쿠폰] ...` 이 22건, `feat:` 는 3건이다. 조직 컨벤션도 `[핵심키워드] 명사형`이고 `feat:` 접두어를 금지한다.
- 이번 변경은 DTO 두 개뿐이라 "API 구현"이 아니다. "구현한다"도 명사형이 아니다.

제목은 명시하신 문자열 그대로 쓴다. 이력은 로컬이고 push 전이라 바꾸기 쉽다.

```bash
git add pasta-api/src/main/java/.../coupon/application/dto/CouponIssueOutDto.java \
        pasta-api/src/main/java/.../coupon/application/dto/CouponSummaryOutDto.java \
        pasta-api/src/test/java/.../coupon/application/dto/CouponIssueOutDtoTest.java \
        pasta-api/src/test/java/.../coupon/application/CouponQueryServiceTest.java
git commit -m "feat: 쿠폰 발급 API 구현한다"
```
```

 4 files changed, 41 insertions(+), 3 deletions(-)
 create mode 100644 .../CouponIssueOutDto.java

```

## 6. 사용자에게 보내는 메시지

TDD Phase 2 의 두 TODO 를 끝냈고, 지시하신 제목으로 커밋했습니다. push 는 하지 않았습니다.

- `CouponIssueOutDto` record 를 `from(Coupon)` 팩토리로 만들었습니다. id, code, expiredAt 단순 매핑입니다.
- `CouponSummaryOutDto` 에 `expiredAt` 을 추가했고 기존 `from()` 만 고쳤습니다.
- 테스트 2건을 추가·보강했고 spotless 와 해당 테스트가 통과했습니다.

확인이 필요한 것은 아래입니다.

1. 팩토리: 조직 컨벤션(`dto-convention`)은 신규 DTO 를 생성자 직접 호출로 두라고 합니다. 지시와 기존 5개 관례에 맞춰 `from()` 으로 했고, PR 본문에 사유를 적겠습니다. 생성자 방식으로 바꾸길 원하시면 한 줄 수정입니다.
2. 커밋 제목: 최근 30건 중 `[쿠폰] ...` 이 22건, `feat:` 는 3건입니다. 조직 컨벤션도 `feat:` 를 금지합니다. 제목이 "API 구현"인데 실제로는 DTO 변경뿐이라 내용과도 맞지 않습니다. 아직 push 전이므로 `[쿠폰] 쿠폰 발급·요약 OutDto 추가` 같은 제목으로 `git commit --amend` 하는 것을 권합니다. 원하시면 바로 하겠습니다. 지시가 없으면 현재 제목을 유지합니다.
3. 가정한 것: `Coupon.getExpiredAt()` 이 `LocalDateTime` 입니다. 다르면 타입을 맞추겠습니다.
4. 범위 밖 보고: `CouponSummaryOutDto` 를 쓰는 web 응답에 `expiredAt` 을 노출할지는 이번 TODO 에 없어서 건드리지 않았습니다.
