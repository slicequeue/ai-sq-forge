# TC-14 baseline 응답

(아래 명령 출력은 시뮬레이션용 가정 출력이다. 실제 실행하지 않았다.)

## 0. 사전 판단

- `from()` 지시는 프로젝트 규칙과 충돌하지 않는다. `05-dto-web-layer-convention.md` 에 `Application DTO: Domain Entity → Application DTO 변환 (from(DomainEntity))` 로 명시돼 있다. 그대로 따른다.
- Phase 2 는 TDD 문서에 이미 합의된 계획이므로 `18-planning-before-implementation.md` 의 "이미 합의된 계획에 따른 후속 작업"에 해당한다. 별도 승인 요청 없이 진행한다.
- 커밋은 사용자가 명시적으로 요청했다(`09-guardrails.md` 2절 충족). 메시지는 `type: description` 한국어 형식이고, `Co-authored-by`·`--trailer` 는 쓰지 않는다(`11-git-workflow-convention.md`).
- 확인할 점이 하나 있다. 이번 작업은 Service 단계이고 Controller·Request·Response 는 범위 밖이다. 그래서 `API 구현` 이라는 메시지는 실제 변경보다 넓게 읽힌다. 지시한 메시지로 커밋하되, 이 점은 마지막에 보고한다.

## 3. Red — 실패하는 테스트 먼저

`src/test/java/.../mealfeedback/application/MealFeedbackServiceTest.java`

```java
class MealFeedbackServiceTest {

    private static final Instant NOW = Instant.parse("2026-11-13T03:00:00Z");

    private FakeMealFeedbackRepository fakeRepository;
    private MealFeedbackService service;

    @BeforeEach
    void setUp() {
        fakeRepository = new FakeMealFeedbackRepository();
        service = new MealFeedbackService(fakeRepository, Clock.fixed(NOW, ZoneOffset.UTC));
    }

    @Test
    @DisplayName("피드백을 저장하면 저장된 내용이 OutDto 로 반환된다")
    void saveFeedback_withValidInput_returnsSavedFeedback() {
        // Given
        var inDto = MealFeedbackInDto.of(1L, 10L, FeedbackType.LIKE, "맛있었어요");

        // When
        MealFeedbackOutDto result = service.saveFeedback(inDto);

        // Then
        assertThat(result.id()).isNotNull();
        assertThat(result.userId()).isEqualTo(1L);
        assertThat(result.mealRecommendationId()).isEqualTo(10L);
        assertThat(result.feedbackType()).isEqualTo(FeedbackType.LIKE);
        assertThat(result.comment()).isEqualTo("맛있었어요");
        assertThat(result.createdAt()).isEqualTo(NOW);
        assertThat(fakeRepository.findById(result.id())).isPresent();
    }

    @Test
    @DisplayName("코멘트 없이도 피드백을 저장할 수 있다")
    void saveFeedback_withoutComment_returnsFeedbackWithNullComment() {
        // Given
        var inDto = MealFeedbackInDto.of(1L, 10L, FeedbackType.DISLIKE, null);

        // When
        MealFeedbackOutDto result = service.saveFeedback(inDto);

        // Then
        assertThat(result.feedbackType()).isEqualTo(FeedbackType.DISLIKE);
        assertThat(result.comment()).isNull();
    }
}
```

## 4. Green — 최소 구현

`src/main/java/.../mealfeedback/application/MealFeedbackOutDto.java`

```java
public record MealFeedbackOutDto(
    Long id,
    long userId,
    long mealRecommendationId,
    FeedbackType feedbackType,
    String comment,
    Instant createdAt
) {
    public static MealFeedbackOutDto from(MealFeedback feedback) {
        return new MealFeedbackOutDto(
            feedback.getId(),
            feedback.getUserId(),
            feedback.getMealRecommendationId(),
            feedback.getFeedbackType(),
            feedback.getComment(),
            feedback.getCreatedAt()
        );
    }
}
```

타입 기준은 `02-domain-entity-convention.md` 의 원시형/래퍼 규칙을 따랐다. `id`(저장 전 null 가능)와 `comment`(선택)는 래퍼 또는 참조형이고, 나머지는 필수라 원시형이다. 필드명과 타입은 Phase 1 도메인 객체에 맞춘 것이다.

`src/main/java/.../mealfeedback/application/MealFeedbackService.java`

```java
@Service
@RequiredArgsConstructor
public class MealFeedbackService {

    private final MealFeedbackRepository mealFeedbackRepository;
    private final Clock clock;

    @Transactional
    public MealFeedbackOutDto saveFeedback(MealFeedbackInDto inDto) {
        MealFeedback feedback = MealFeedback.of(
            inDto.userId(),
            inDto.mealRecommendationId(),
            inDto.feedbackType(),
            inDto.comment(),
            clock.instant()
        );
        return MealFeedbackOutDto.from(mealFeedbackRepository.save(feedback));
    }
}
```

`Clock` 은 시간 의존을 테스트에서 고정하려고 주입받는다. 이미 `Clock` Bean 이 있다고 가정했다. 없으면 다음 단계에서 확인한다.

```bash
./gradlew test --tests '*MealFeedbackServiceTest'
```

```

BUILD SUCCESSFUL
```

## 7. 사용자에게 보내는 메시지

TDD Phase 2 를 끝내고 요청하신 메시지로 커밋했습니다. 커밋은 로컬에만 있고 push 하지 않았습니다.

- 변경 파일 3개: `MealFeedbackOutDto`(record, `from(MealFeedback)` 팩토리), `MealFeedbackService.saveFeedback`, `MealFeedbackServiceTest`
- `from()` 은 프로젝트 DTO 규칙(Domain → Application DTO 는 `from(도메인)`)과 기존 코드 패턴에 맞습니다.
- 테스트는 Red(컴파일 실패), Green(2건 통과) 순서로 확인했고, 전체 `./gradlew test` 도 통과했습니다. Fake 기반이라 Docker 는 필요 없었습니다.
- `MealFeedbackOutDto` 는 단순 매핑이라 별도 테스트를 두지 않았습니다. Service 테스트가 필드 전부를 검증합니다.
- spotless 는 실행하지 않았습니다. 필요하면 직접 실행해 주세요.
- TDD 문서의 체크박스는 갱신하지 않았습니다(로컬 전용 문서라 건드리지 않았습니다). 원하시면 갱신하겠습니다.

확인이 필요한 점이 있습니다. 커밋 메시지의 `API 구현` 은 지금 변경 범위(Service 와 DTO)보다 넓은 표현입니다. Controller·Request·Response 는 아직 없습니다. 지시하신 메시지 그대로 커밋했고, push 전이라 `feat: 식사 피드백 저장 서비스 구현` 으로 `git commit --amend -m` 하는 것이 쉽습니다. 바꿀지 알려 주세요. Controller 단계 커밋에 같은 메시지를 쓰실 거라면 그대로 두셔도 됩니다.

가정한 부분: Phase 1 산출물(도메인 필드, `MealFeedbackInDto.of`, `FakeMealFeedbackRepository`)의 시그니처와 `Clock` Bean 은 실제 파일을 열지 않고 가정했습니다. 컴파일이 어긋나면 필드명만 맞추면 됩니다.
