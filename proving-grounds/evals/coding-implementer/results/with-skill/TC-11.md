추가 설계 메모 (가드 적용)
- RR-2: 마지막 체중 기록 조회는 `ORDER BY` 에 동점 2차 기준(`id`)을 붙인다. "마지막 기록" 판정은 시각 비교가 아니라 id 로 한다 (RR-14).
- RR-14: "최신" 조회에 `현재 시각 이하` 조건을 넣어 미래 시각 기록을 거른다.
- RR-6: 응답 DTO 는 인접 필드의 단위·용어를 먼저 읽고 맞춘다 (예: 시간 필드를 MINUTE/HOUR 혼재 금지).
- RR-9: 홈은 자주 불리는 경로이므로 `MedicationScheduleQueryService`·`WeightRecordRepository` 의 호출처를 grep 해 공용 헬퍼가 홈 조회마다 추가 쿼리를 만들지 않는지 확인한다. 존재 확인만 필요한 곳은 `existsBy...`, 일정은 사용자 단위 bulk 조회.
- RR-13 (트랜잭션): 복약 조회가 홈 조립 트랜잭션에 참여한 채 예외를 내면 호출부 catch 후에도 rollback-only 로 전체가 `UnexpectedRollbackException` 이 된다. 실패를 허용할 조회(복약·추천)는 트랜잭션 경계를 분리하고(readOnly 별도 빈 또는 `REQUIRES_NEW`, Bean 이름은 상수화) 실제 프록시로 테스트한다.
- 외부 콘텐츠 API 클라이언트: 타임아웃·예외 계층 분리(클라이언트 오류와 인프라 장애는 로그 레벨 구분, RR-5), 응답 DTO 방어(null·누락 필드). 새 외부 서비스 연동이지만 TDD Phase 1 에 명시된 항목이라 TDD 범위 안에서 진행한다 (SC-3 승인 근거 = TDD).
- DW-6: `RecordTimeValidator` 신설 전 `grep -rn "RecordTimeValidator\|validateRecordTime" --include=*.java` 로 중복 식별자 전수 검색 (가정한 결과: 0건).
- DW-1/DW-3: 기존 `WeightController`·서비스·기존 테스트 파일은 읽은 뒤 `Edit` 로 부분 수정한다. 통째 덮기 없음. 작업 시작 전 `git status --short` 재확인 (가정한 결과: 0건).
