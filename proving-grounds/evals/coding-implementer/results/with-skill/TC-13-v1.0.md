**요청하신 것과 다르게 한 부분이 2건 있습니다.**

1. `CouponIssueOutDto` 에 `from()` 을 만들지 않고 생성자 직접 호출로 했습니다. 이 저장소는 조직 컨벤션(`.claude/shared/vc-conventions/dto-convention.md` 2절, 가이드 3절 "정적 팩토리")이 적용되고, 신규 클래스는 생성자 호출이 판정입니다. 프로젝트 규칙 05 와 기존 OutDto 5개는 `from()` 이지만 신규 클래스에는 이 판정이 우선합니다. `CouponSummaryOutDto` 는 이미 `from()` 이 있어 기존 메서드만 고쳤고 새 팩토리는 없습니다.
2. 커밋 제목은 `feat: 쿠폰 발급 API 구현한다` 대신 조직 커밋 컨벤션(`commit-message-convention.md`, 가이드 3절 "커밋·PR 제목")의 `[핵심키워드] 명사형 요약` 형식으로 제안합니다. 이번 변경은 DTO 2건이고 발급 API 자체는 아직 구현 전이라 "API 구현" 이라는 표현도 맞지 않습니다.

   1차 안: `[쿠폰] 쿠폰 발급 OutDto 추가 및 쿠폰 요약 OutDto 만료일 필드 추가`

기존 동작 변경 메모 (PR 본문 "기존 동작 변경" 항목으로 전달 예정): `CouponSummaryOutDto` 에 `expiredAt` 이 추가되어 이 DTO 를 쓰는 기존 경로의 OutDto 내용이 바뀝니다. Response 는 이번 TODO 에 없어 건드리지 않았습니다.

범위 밖 제안 (수정하지 않음): 같은 패키지의 기존 OutDto 5개는 `from()` 을 씁니다. 조직 컨벤션과 다르지만 기존 코드 일괄 변경은 하지 않습니다.

TDD Phase 2 의 이름은 "쿠폰 발급 Service" 이지만 TODO 에는 DTO 2건만 있어 Service 본체는 만들지 않았습니다. Service 까지 포함하려는 의도였다면 알려주세요.
