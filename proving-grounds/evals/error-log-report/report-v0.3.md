| 관찰 | 원인 | 수정 | 효과 |

| 초기 with-skill 공유본에 보고서 파일명이 없음 | 템플릿에 파일명 줄이 없고, 본문 안내는 "마지막 불릿 또는 부탁 줄 아래"로 선택지였다 | 템플릿 마지막 불릿을 `- 상세: {보고서 파일명}` 으로 고정, 안내 문장을 "마지막 불릿은 보고서 파일명"으로 바꿈 | 95 → 98 |

## 5. 확인된 것 vs 가정한 것

| 구분 | 내용 |
|------|------|
| 확인 | share-lint 판정은 응답 원문에서 두 산출물을 떼어 각각 `--grade B`·A 로 실제 실행한 출력이다 |
| 확인 | 결론 블록 첫 줄 예시 `2026-07-26 00:00~08:00 KST(07-25 15:00~23:00 UTC) 에러 로그 분석 완료 (코드 변경 없음)` 은 share-lint A·B 모두 통과한다 |
| 가정 | 7섹션 본문 앞에 결론 블록을 붙여도 기존 TC-1~5 의 채점(특히 "2. 결론 요약" 섹션과의 중복)에 영향이 없다고 보고 재실행하지 않았다 |
| 미확인 | 본문에 "신규 유형: 없음" 같은 표 칸이 남는지(share-lint 는 표 칸 "없음"을 `[확인]` 으로만 낸다)는 전체 보고서 TC 로 봐야 한다 |

## 6. 공용 변경 제안

- `share-lint.py`: `•` 불릿 인식 (이번 baseline 실측 누락 3줄)
- `share-lint.py`: "- 특이사항: 신규 유형 없음. ..." 처럼 값이 "없음"으로 끝나지 않는 서술형 빈 칸은 못 잡는다. 키 이름(특이사항·이슈·요청)과 "없음" 이 같은 줄에 있으면 `[확인]` 으로 내는 규칙을 검토한다
