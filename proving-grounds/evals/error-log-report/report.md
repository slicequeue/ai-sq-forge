## 하네스 자체 결함 (발견·수정)

TC-1의 시뮬레이션 데이터에 산술 모순이 있었다. 로거별 집계 합(36+12+12+12+8=80)이 헤더 총건수(68줄)와 불일치했다. **baseline·with-skill 양쪽이 독립적으로 이 모순을 검출**했고, with-skill은 §1에 정합성 확인 섹션을 만들고 후속 조치 1순위로 재집계를 권고했다.

데이터를 수정(3로거 × 12이벤트 = 36 + 12 + 8 = 56, 시간 분포 22/19/15)하고 TC-1을 재실행했다. 1차 실행분은 `results/with-skill/TC-1-old-data.md`에 참고 보존했다.

의도하지 않은 부수 효과로 **입력 데이터 모순 검출 능력**이 확인됐다. 이를 정식 Edge Case TC로 승격할 것을 권고한다(하네스 v0.2 과제).

## 축5 일관성 상세 (TC-1 `--repeat 3`)

전문: `results/with-skill/repeat/CONSISTENCY.md`

핵심 판정값 9개 지표가 **3회 완전 일치**했다. UTC 환산, 로그 56 / 실패 이벤트 32, 배수 36÷3=12, 카탈로그 신규 0건, 유형 2의 원인 예외 명명, 후처리 실패 구분, 딥링크, 절단 여부 명시, 파일명 규약.

편차 2점은 타임라인 처리 1건에서만 발생했다. run3가 입력 "17:0x 이후 15건"을 17:xx 한정으로 읽고 "18:00~22:59 = 0건"을 추가해 "KST 03~07시대에 ERROR 없음"으로 단정했다. 입력이 뒷받침하지 않는 추론이다. → **스킬 v0.2에서 하드 가드레일 7에 "집계 버킷 경계 임의 세분화 금지" 추가로 대응.**

부수 발견: run2가 TC 프롬프트의 2차 결함을 검출했다. "어제(2026-07-26)"인데 작성일 기준 어제는 07-28이다. run2는 로그 타임스탬프로 의도 구간을 채택하되 재확인 트리거로 등록했다.

## 커버리지 갭 + 개선 권고

### 하네스 v0.2 과제

1. **TC-1 프롬프트에서 "어제" 표현 제거** — 작성일과 3일 차이라 내부 모순. 날짜만 지정하도록 수정.
2. **입력 데이터 모순 검출 TC 신설** — 위 결함 발견 경위를 정식 Edge Case로 승격.
3. **타임라인 검증 불가** — TC-1·TC-2 입력에 유형별 시간 분포가 없어 타임라인 섹션이 실질 공란이 된다. 유형×시각 교차 데이터를 TC에 추가해야 항목 6을 온전히 채점할 수 있다.
4. 미커버 항목: `--limit` 절단 케이스, 유형 15개 초과 요약 분할, 인프라 레벨(`severity`) 집계 기준 선택, 카탈로그 파일 실제 수정.

### 스킬 v0.2 과제

1. **카탈로그 갱신이 제안에 머문다** — TC-2에서 신규 유형을 정확히 식별하고 등재 문구까지 만들었지만 파일 수정은 하지 않았다(시뮬레이션 제약이기도 하다). SKILL.md에 "보고서 제출과 같은 회차에 카탈로그 파일을 실제로 수정한다"를 자기 검증 항목으로 승격 권고.
2. **`event-storm-transaction-strategies.md` 의존** — `noise-catalog-moneyball.md`가 moneyball 레포 루트 문서를 참조한다. with-skill이 부재를 인지하고 인용을 생략한 것은 규칙대로지만, 유형 A~D 분류 체계 자체는 유용하므로 forge에 흡수하거나 카탈로그 안에 요약 이식을 검토할 것.
3. TC-3에서 "전건 최초 관측 표기" 방침 안내가 부분 충족(−3)이었다. Phase 0 6번 항목에 문구를 명시하면 해소된다.
