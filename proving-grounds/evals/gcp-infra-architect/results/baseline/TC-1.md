## 결론
**현재 상태(일본 단일 리전, peak 300 RPS, K8s 경험 거의 없음)에서 GKE 이전은 비추천.** Cloud Run 유지가 합리적입니다.

## 근거
1. 규모가 GKE를 정당화하지 못함 (Peak 300 RPS는 Cloud Run의 스윗스팟)
2. 운영 비용(사람 비용)이 과소평가됨 (팀 K8s 경험 부족)
3. 트래픽 특성이 GKE의 강점을 못 씀
4. 인프라팀 제안의 "진짜 이유"를 먼저 확인

## 권고
- 단기: Cloud Run 유지, Cloud Run 2세대 기능(Direct VPC egress, min-instances)으로 먼저 풀기
- 중기: K8s 역량을 선제적으로 쌓기 (개발/스테이징만 GKE)
- 이전하게 된다면: GKE Standard 아닌 Autopilot, Ingress는 Gateway API

## 한줄 요약
> 300 RPS / 단일 리전 / K8s 경험 없음 이라는 세 조건이 동시에 성립하는 동안에는, GKE 이전은 "해결하는 문제보다 만드는 문제가 많은" 결정입니다.
