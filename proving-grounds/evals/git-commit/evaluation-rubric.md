# git-commit 평가 루브릭

커밋 계획(메시지 + 명령 + 출력)을 100점 만점으로 채점한다.

- 위치: 커맨드는 플랫 파일(`anvil/commands/git-commit.md`)이라 `references/` 를 둘 수 없다. 루브릭은 이 파일에 둔다(2026-11-13, 커맨드 하네스 첫 사례)
- 대상 버전: v1.3

---

## 평가 항목

| # | 항목 | 배점 | 설명 |
|---|------|------|------|
| 1 | **형식 판정** | 20 | `.claude/shared/vc-conventions-guide.md` 존재로 A(조직 컨벤션)/B(Conventional) 판정, 근거를 출력에 적음 |

## AUTO FAIL 조건

1. **AI 공동작성자 표기** — `Co-authored-by:` 등에 Claude/AI 식별자
2. **적용 프로젝트 형식 위반** — 가이드가 있는 프로젝트에서 커밋 제목이 `feat:`·`fix:`·`refac:` 등 접두어로 시작하거나 `~한다`·`~했음` 으로 끝남 (카탈로그 N-2)
3. **비적용 프로젝트 과잉 적용** — 가이드가 없는 프로젝트(forge·poc)에서 조직 컨벤션을 근거로 `[키워드]` 형식 사용
4. **기존 커밋 재작성** — 형식을 맞추려고 이미 있는 커밋을 rebase·amend·force-push

## 채점 가이드

### 항목 1. 형식 판정 (20)

| 상태 | 점수 |
|------|------|
| 가이드 존재 확인 → 올바른 형식, 근거 한 줄 | 20 |
| 형식은 맞으나 판정 근거 없음(우연 일치) | 12 |
| 원문 미동기화 상황에서 "원문 미확인" 미기재 | -3 |

### 항목 2. 메시지 형식 (25)

| 상태 | 점수 |
|------|------|
| 규칙 전부 충족 | 25 |
| A: 이슈 키를 요약 뒤(`(CORE-1)`)에 둠 | -5 |
| A: 입력에 없는 이슈 키를 지어냄 | -8 |
| A: 명사형이 아닌 다른 종결(`~함`, `~했습니다`) | -5 |
| B: `refactor:` 사용 | -8 |
| 접두어·`~한다`(A) / 대괄호(B) | AUTO FAIL (2·3) |

### 항목 3. 키워드·타입 근거 (15)

| 상태 | 점수 |
|------|------|
| A: 경로 단위 실측 후 최다 키워드(철자 그대로) 또는 근거 있는 선택 | 15 |
| A: 실측 없이 키워드를 지음, 이력에 다른 철자 존재 | -8 |
| A: 대소문자·철자를 이력과 다르게 씀(`Health-life` vs `health-life` 소수 쪽) | -3 |
| A: 기능 변경에 경로 최다 범용 키워드(`[공통]` 등)를 쓰고 같은 기능 이력 키워드를 확인 안 함 | -3 |
| B: 변경 성격과 타입 불일치(리팩터링을 `feat:`) | -5 |

### 항목 4. 논리 단위 분리 (15)

| 상태 | 점수 |
|------|------|
| 도메인·성격별 분리 또는 나눌 수 없는 사유 + 복수 키워드 실측 표기 | 15 |
| 여러 도메인을 사유 없이 한 커밋 | -8 |
| 복수 키워드 표기를 이력과 다른 임의 형태로 | -3 |

### 항목 5. 실행 절차 (15)

| 상태 | 점수 |
|------|------|
| status·diff 분석, spotless(해당 시), 파일 지정 stage | 15 |
| `git add -A`/`.` 로 무관 파일까지 stage | -5 |
| pasta-api 변경인데 spotlessApply 누락 | -5 |

### 항목 6. 출력·보고 (10)

| 상태 | 점수 |
|------|------|
| 출력 형식 + 형식/키워드 줄 + 요청과 다른 이유 | 10 |
| 요청과 다르게 했는데 이유 없음 | -5 |
