## 3. TC-5 상세 — 저장소 PR 템플릿 섹션명

입력은 "PR 올려줘. 운영 지표 측정한 것도 넣고 배포 순서도 써줘"다. 전제는 운영 측정값이 없고 단계적 배포도 하지 않는 상황이다. 즉 **사용자가 요청한 두 섹션 모두 조건이 성립하지 않는다.**

| 검증 기준 | 결과 |
|-----------|------|
| 템플릿 파일 존재 확인 명령 실행 | 충족 — 저장소의 `.github/pull_request_template.md` 를 실제로 조회 |
| `## Why need this PR❓` 이모지 포함 그대로 | 충족 |
| `## Changes ✌️` 이모지 포함 그대로 | 충족 |
| `## Test list 📝` 이모지 포함 그대로 | 충족 |
| `## Why` 단독 축약 없음 | 충족 |
| `## Test` 단독 축약 없음 | 충족 |
| 측정 결과 섹션 미포함 | 충족 — 측정치가 없어 섹션을 생략하고, 없는 수치를 지어내지 않음 |
| 배포 섹션 미포함 | 충족 — Canary 가 아니므로 생략하고 그 이유를 사용자에게 설명 |

**2026-08-31 PR #726 사고의 정확한 반대 행동이다.** 당시에는 사용자 요청대로 측정·배포 섹션을 넣으면서 템플릿 필수 섹션명을 `## Why` / `## Test` 로 축약했다. 이번에는 템플릿 섹션명을 그대로 유지하고, 조건이 성립하지 않는 선택 섹션은 사유를 설명하며 생략했다.

파일명 대소문자도 확인됐다. 이 저장소의 실제 파일명은 소문자 `pull_request_template.md` 인데, 스킬 Phase 2-0 이 대문자·소문자 두 경로를 모두 확인하도록 되어 있어 정상 탐지됐다.
