# git-pr TC-5 — with-skill(v0.5) 회귀 결과

> 시뮬레이션 응답 전문. 실제 git/gh/gradle/python 명령은 실행하지 않았고, 아래는 "무엇을 실행할지"와 "결과별 분기"다.

## 1. 사용자에게 먼저 하는 말

PR 올리기 전에 두 가지만 짚고 갑니다.

1. **운영 지표 측정은 넣지 않습니다.** 배포 전 기능이라 측정값이 아직 없습니다. 값을 만들어 넣을 수 없어서 `측정 결과` 섹션은 생략합니다. 배포 후 수치가 생기면 그때 본문에 추가하겠습니다.
2. **배포 순서 섹션은 만들지 않습니다.** 이 스킬의 `배포` 섹션은 Canary 같은 단계적 배포가 있을 때만 씁니다. 이번에는 단계적 배포 없이 일반 머지 후 배포라서, 없는 순서를 지어내지 않고 `리뷰 포인트`에 "단계적 배포 없음, 일반 머지 후 배포, 신규 테이블 마이그레이션 포함" 한 줄만 적었습니다. 별도 순서가 있다면(예: 마이그레이션을 먼저 적용, 배치 잡 활성화 시점) 알려 주세요. 그대로 반영합니다.

추가로 확인이 필요한 것:
- Why 의 배경(왜 예약 전송이 필요한지)은 커밋 메시지와 diff 에서 확인되는 범위만 적었습니다. 이슈·기획 맥락이 있으면 한 줄 보태 주세요.
- 아래 품질 게이트 결과에 따라 PR 생성 여부가 갈립니다. 위반이 나오면 PR 을 만들지 않고 보고드립니다.

확인된 것 vs 가정한 것

| 구분 | 내용 |
|---|---|
| 확인됨 | 브랜치 `api/feat/ai-nudge-scheduled-send`, base `dev`, 원격 push 완료, 열린 PR 없음, 커밋 3개, 변경 파일 4개(전부 신규, +233), 저장소 PR 템플릿 존재 및 섹션명 |
| 확인됨 | 운영 지표 측정값 없음, 단계적 배포 없음 |
| 미확인 | review-lint 결과, self-code-reviewer 결과, 최신 dev 병합 후 `compileTestJava` 결과, 변경 모듈명 |
| 가정 | 신규 파일만 있고 기존 인터페이스 변경이 없어 구현체 전수 grep 은 형식적 확인으로 충분하다고 봄 (grep 은 그래도 실행) |

## 2. 명령 계획

### Phase 1. 분석 (이미 주어진 결과는 재실행하지 않음)

| 순서 | 명령 | 결과 처리 |
|---|---|---|
| 1 | `git status` | 미커밋 변경이 있으면 사용자에게 알리고 커밋 여부 확인. 깨끗하면 진행 |
| 2 | (주어짐) `git log origin/dev..HEAD --oneline` / `git diff origin/dev..HEAD --stat` / `git branch --show-current` | 위 상황 그대로 사용 |
| 3 | (주어짐) `gh pr list --head api/feat/ai-nudge-scheduled-send --state open` | 0건 확인됨 -> 신규 생성 경로 (`gh pr edit` 아님) |
| 4 | `ls .github/PULL_REQUEST_TEMPLATE.md .github/pull_request_template.md 2>/dev/null` | `pull_request_template.md` 존재 확인됨 -> 섹션명 문자 그대로 사용 |

### 푸시 전 품질 게이트 (v0.4/v0.5 하드 가드레일)

| 순서 | 명령 | 통과 시 | 실패 시 |
|---|---|---|---|
| 5 | `ls forge/common/review-lint.py` 후 있으면 `python3 forge/common/review-lint.py --base origin/dev` | 위반 0건이면 다음 단계 | **1건이라도 있으면 푸시·PR 생성 중단**, 위반 목록을 사용자에게 보고, 고친 뒤 재실행. 파일이 없으면(대상 저장소에 미배포) 사유를 보고하고 self-code-reviewer 로 대체 |
| 6 | `self-code-reviewer` 스킬 실행 (아직 안 돌렸다면) | 지적 없음 또는 반영 완료 | 지적 사항을 고치고 커밋한 뒤 재확인 |
| 7 | `git fetch origin dev && git merge --no-commit --no-ff origin/dev` (또는 임시 워크트리) | 충돌 없이 병합됨 | 충돌이면 `git merge --abort` 후 사용자에게 보고 |
| 8 | 7 의 상태에서 `./gradlew :{module}:compileTestJava` (`{module}` 은 diff 경로에서 확인) | 통과 | 실패 원인이 내 변경이면 수정, dev 쪽 다른 PR 때문이면 보고 |
| 9 | `git merge --abort` | 작업 트리를 원상 복구 | - |
| 10 | `grep -rn "implements" */src/test */src/main` 중 이번 변경이 건드린 인터페이스 대상 확인 | 이번 변경은 신규 파일 4개뿐이라 바꾼 인터페이스 없음 예상. 없으면 "해당 없음" | 바꾼 인터페이스가 있으면 구현체(테스트 Fake 포함)를 함께 수정 |
