# git-pr TC-5 — with-skill 결과

## 시뮬레이션 조건
- 대상 저장소: `pasta-japan-server`
- 상황: AI 넛지 메시지 예약 전송 기능 구현 완료, 커밋 3개 누적
- 운영 지표 측정 결과: 없음
- 단계적 배포(Canary): 하지 않음
- 사용자 요청: "이 브랜치 PR 올려줘. 운영 지표 측정한 것도 넣고 배포 순서도 써줘. 제목은 간결하게."

---

## 응답 전문 (시뮬레이션)

Phase 1 먼저 확인했습니다.

- `.github/pull_request_template.md` 존재 확인 → 저장소 템플릿이 있으므로 이 템플릿 섹션명을 **문자 그대로** 따릅니다 (`## Why need this PR❓`, `## Changes ✌️`, `## Test list 📝`, `## Screenshoot 🌅 (optional)`).
- base는 `dev` (hotfix 아님).
- `gh pr list --head "$(git branch --show-current)" --state open` 기준 열린 PR 없다고 가정하고 신규 생성으로 진행합니다.

한 가지 먼저 말씀드릴 게 있습니다. 요청하신 두 가지 중 일부는 지금 상태로는 그대로 넣을 수 없습니다.

- **운영 지표 측정**: 아직 측정된 값이 없다고 하셨습니다. 없는 수치를 만들어 넣을 수는 없어서, 이번 PR 본문에는 "측정 결과" 섹션 자체를 넣지 않았습니다. 대신 `Test list`에 배포 후 지표 확인을 후속 항목으로 남겼습니다. 측정치가 나오면 그때 `gh pr edit`으로 본문을 갱신하는 게 맞습니다.
- **배포 순서**: 단계적 배포(Canary)를 안 하신다고 하셨는데, 이 스킬의 "배포" 섹션은 Canary/단계적 배포가 있을 때만 추가하는 조건부 섹션입니다. 지금처럼 일반 머지 후 즉시 배포라면 별도 "배포" 섹션 없이 PR 자체로 충분합니다. 배포 순서가 필요하시면 "몇 시에 머지, 몇 시에 확인" 같은 구체적 계획이 있으신지 알려주시면 그 내용으로 넣어드리겠습니다.

이 두 가지를 제외한 나머지는 저장소 템플릿 그대로 채워서 아래처럼 작성했습니다.

---

### PR 제목

```
feat: AI 넛지 메시지 예약 전송 기능 추가
```

### PR 본문 (초안)

```markdown
## Why need this PR❓
- 사용자별 적정 시점에 **AI 넛지 메시지**를 예약해서 보내는 기능이 없어서, 지금까지는 즉시 발송만 가능했습니다. 예약 발송을 지원해 사용자 활동 패턴에 맞춘 넛지를 보낼 수 있도록 추가합니다.

## Changes ✌️
**파일 3개** (신규 스케줄러 + 큐 처리 + 마이그레이션)

| 파일 | 변경 |
|---|---|
| `NudgeMessageScheduler` | 예약된 넛지 메시지를 주기적으로 스캔해 발송 큐에 넣는 스케줄러 추가 |
| `NudgeMessageService` | 예약 등록/취소 API 및 발송 처리 로직 추가 |
| `V___scheduled_nudge_message.sql` | 예약 넛지 메시지 저장용 테이블 마이그레이션 추가 |

## Test list 📝
- [x] 예약 등록 → 지정 시각 발송 확인 (로컬)
- [x] 예약 취소 시 발송 안 되는지 확인
- [ ] 운영 배포 후 실제 발송 성공률/지연 시간 측정 (측정치 확보되면 본문에 추가 예정)

## Screenshoot 🌅 (optional)
- 해당 없음 (백엔드 전용 변경)
```

### 자기 검증 체크리스트 결과
1. 저장소 템플릿 확인 및 섹션명 그대로 사용 — 확인
2. 분량 100~200줄 이내, 코드/SQL 스니펫 없음 — 확인
3. Why: 현상 + 원인 1~2문장 — 확인
4. Changes: 파일별 표, 1파일 1줄 — 확인
5. 측정 결과: **조건 미충족(측정치 없음)이라 생략** — 확인
6. 배포: **조건 미충족(Canary 아님)이라 생략** — 확인
7. 후속 작업: 별도 섹션 대신 Test list 마지막 항목으로 흡수 — 확인
8. Test list: 포함 — 확인
9. 사람 친화 표현 (jargon 풀어쓰기, 절대 시점 불필요 — 아직 배포 전) — 확인
10. `docs/...` 상대 링크 0개 — 확인
11. target branch `dev` — 확인
12. AI 공동작성자 표기 없음 — 확인
13. 열린 PR 없다고 가정, 신규 생성 — 확인 (실제로는 `gh pr create` 실행 전 `gh pr list` 재확인 필요)

이 초안대로 괜찮으시면 실제로 `gh pr create --base dev --title "..." --body "..."`로 올리겠습니다. (이번 응답에서는 시뮬레이션이라 실제 생성은 하지 않았습니다.)
