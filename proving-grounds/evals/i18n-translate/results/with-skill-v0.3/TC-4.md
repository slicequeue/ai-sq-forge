# message-pghd 신규 문구 ja_JP 번역 — 반영 계획

## 결론 먼저

4건 중 **2건만 바로 반영**하고, **2건은 초안만 만들어 승인을 받은 뒤 반영**합니다.

| 키 | 처리 | 이유 |
|---|---|---|
| `food.recommend.tea.title` | 반영 | 일반 UI 문구. 한국 고유 음식명 표기만 주의 |
| `food.recommend.side.body` | 반영 | 일반 UI 문구. 한국 고유 음식명 표기만 주의 |
| `exercise.pregnancy.high.body` | **보류 (초안만)** | 임신부 혈당 구간별 운동 권고 = 의학적 권고 → 의학 검수 필요 |
| `privacy.thirdparty.notice` | **보류 (초안만)** | 개인정보 제3자 제공 안내 = 법정 고지 → 법무·개인정보보호 검토 필요 |

"바로 반영" 요청이지만 아래 두 건은 스킬 승인 게이트 대상이라 파일에 넣지 않았습니다. 잘못된 의학·법률 문구가 배포되는 것이 번역이 늦는 것보다 나쁩니다. 두 건은 허용 목록(`ALLOWED_MISMATCHES`)에 사유와 함께 등록해 테스트를 통과시키고, 승인 후 반영하면서 허용 항목을 지웁니다.

## 1. 반영 전 확인 (실행할 명령)

저장소가 가상이라 아래 결과는 시뮬레이션입니다. 실제 반영 시 꼭 실행해 주세요.

```bash
# (1) 기본 번들에 4개 키가 이미 있는지 — 키는 코드가 정한다. 없으면 이번 작업 범위 밖
grep -nE "^(food\.recommend\.tea\.title|food\.recommend\.side\.body|exercise\.pregnancy\.high\.body|privacy\.thirdparty\.notice)=" \
  pghd/src/main/resources/messages/message-pghd.properties

# (2) 다른 번들에 같은 키가 있는지 — basename 순서상 앞쪽 번들이 이기면 pghd 번역은 도달하지 못한다
grep -rnE "^(food\.recommend\.tea\.title|food\.recommend\.side\.body|exercise\.pregnancy\.high\.body|privacy\.thirdparty\.notice)=" \
  --include="*.properties" .

# (3) 허용 목록에 이 키들이 이미 등록돼 있는지
grep -rn "food.recommend\|exercise.pregnancy.high\|privacy.thirdparty" \
  --include="MessageBundleLocaleParityTest*.java" .
```

| 확인 | 시뮬레이션 결과(가정) | 실제와 다르면 |
|---|---|---|
| (1) 기본 번들 키 존재 | 4건 모두 존재 | 없는 키는 번역을 넣지 않고 보고만 한다 (키 신규 생성은 코드 변경 동반) |
| (2) 타 번들 중복 | 없음 | 특히 `privacy.thirdparty.notice` 가 `message-hospital` 등 앞쪽 번들에 있으면 그쪽이 이긴다. 넣을 번들부터 다시 정한다 |
| (3) 허용 목록 | ja_JP·en_US 4건씩 등록돼 있다고 가정 | 미등록이면 현재 이미 테스트가 실패 중인 상태. 아래 4절 참고 |

## 2. 반영할 값 (2건)

### `food.recommend.tea.title`

| | 값 |
|---|---|
| ko | `오늘의 추천 차: 쌍화차` |
| **ja (반영)** | `今日のおすすめ：双和茶` |
| 더 짧은 대안 | `おすすめ茶：双和茶` (0.69) |

- **쌍화차는 이름 전체가 하나의 고유명사**입니다. 쌍(double) + 화차(freight car) 로 쪼개 `ダブルデッキバス` 가 된 오역이 실제로 났던 단어라, 의미 단위로 나누지 않고 일본에서 통용되는 한자 표기 `双和茶` 를 썼습니다.
- 원문 "추천 차"의 "차"는 `双和茶` 에 이미 들어 있어 빼서 0.9배 기준에 맞췄습니다. `今日のおすすめ茶：双和茶` 는 0.92배로 초과합니다.
- 키에 `title` 이 있어 폭 고정 자리로 보고 엄격하게 봤습니다. 콜론은 전각 `：`, 마침표는 붙이지 않습니다.
- 확인 필요: 일본 사용자에게 `双和茶` 가 낯설 수 있습니다. 읽기 `双和茶（サンファチャ）` 를 붙이면 뜻은 잘 전달되지만 타이틀 길이를 넘습니다. 붙일지는 기획·디자인이 결정할 일이라 이번에는 넣지 않았습니다.

### `food.recommend.side.body`

| | 값 |
|---|---|
| ko | `깍두기와 신선로를 곁들이면 더 든든해요.` |
| **ja (반영)** | `カクテキと神仙炉を添えると、満足感が増します。` |
| 더 짧은 대안 | `カクテキと神仙炉を添えて満足感アップ。` (0.86, 카피체라 본문 톤에서는 차선) |

- `깍두기` → `カクテキ`. 일본에서 정착된 표기입니다. 기계번역에서 `キムチ` 로 뭉개지는 사례가 있었는데, 깍두기는 김치 중 한 종류일 뿐이므로 상위어로 바꾸지 않습니다.
- `신선로` → `神仙炉`. 신선(fresh) + 로(road) 로 쪼갠 `フレッシュロード` 오역 사례가 있던 단어라, 하나의 고유명사로 보고 일본에서 쓰는 한자 표기를 그대로 썼습니다.
- "든든해요"는 포만·만족을 뜻해서 `満足感が増します` 로 옮겼습니다. 건강 효과로 읽힐 수 있는 표현(`腹持ちがよくなります` 등)은 원문에 없는 주장을 더하게 되어 쓰지 않았습니다.
- 길이 1.05배로 ja 기준 0.9배를 넘습니다. 다만 `body` 안내문이라 느슨하게 적용하는 자리입니다. **PR 본문에 길이 초과 키로 남기고**, 화면 잘림이 확인되면 위의 짧은 대안으로 바꿉니다.
- 확인 필요: `神仙炉` 도 일본 사용자에게 생소할 수 있습니다. 읽기 `（シンソルロ）` 를 붙일지는 tea.title 과 같이 결정해 주세요. 일본 DB 에는 한국 고유 음식이 없어 대조로 확정할 수 없었습니다.

## 3. 보류 2건 — 초안 (파일에 넣지 않음)

PR 본문이나 카드 코멘트에 아래 초안을 올리고 담당자 확인을 받은 뒤 반영합니다.

### `exercise.pregnancy.high.body` — 의학 검수

| | 값 |
|---|---|
| ko | `임신 중 혈당이 140mg/dL 이상이면 식후 15분 걷기를 권장해요. 통증이 있으면 즉시 중단하세요.` |
| ja 초안 | `妊娠中にグルコース値が140mg/dL以上のときは、食後15分のウォーキングがおすすめです。痛みがあれば、すぐに中止してください。` |
| 짧은 대안 | `妊娠中でグルコース値が140mg/dL以上なら、食後に15分歩きましょう。痛みがあればすぐ中止してください。` (0.95) |

초안 길이는 1.14배로 기준을 넘습니다. 짧은 대안도 0.95배라 기준 밖이며, 안내문이라 느슨하게 적용할 자리이지만 의학 검수에서 문장이 바뀔 가능성이 커서 길이는 승인 후 다시 봅니다.

검수자에게 전달할 판단 지점:

1. **혈당 표기 `グルコース値` 선택**: 140mg/dL 은 CGM 이 측정한 값에 걸린 임계치라 측정값 자리로 보고 `グルコース値` 를 썼습니다. 같은 번들의 인접 운동 권고 키가 `血糖値` 를 쓰고 있다면 맞춰야 합니다.
2. **`高血糖` 은 쓰지 않았습니다.** 웰니스 앱 범위상 진단 용어를 피했습니다.
3. **경고 문장은 완곡하게 바꾸지 않았습니다.** "통증이 있으면 즉시 중단"은 위험 안내라 `すぐに中止してください` 로 분명하게 남겼습니다.
4. **한국어 원문 검수 의견 (원문은 고치지 않음, 제안만)**
   - 140mg/dL 기준과 "식후 15분 걷기"의 근거(가이드라인 출처)가 문구에 없습니다. 가이드 `## ko` 의 "근거 없는 건강 일반화에는 출처·면책 명시"에 해당하므로 출처나 "참고용" 면책 문구를 붙일지 의학 검수에서 판단해 주세요.
   - 임신부 대상 운동 권고 자체가 웰니스 앱 범위 안인지도 함께 확인이 필요합니다.

### `privacy.thirdparty.notice` — 법무·개인정보보호

| | 값 |
|---|---|
| ko | `수집한 혈당 기록은 제휴 병원에 제공될 수 있어요.` |
| ja 초안 | `収集した血糖値の記録は、提携病院に提供される場合があります。` |

검수자에게 전달할 판단 지점:

1. **혈당 표기 `血糖値`**: 여기서는 측정값이 아니라 데이터 유형 이름이라 `血糖値` 를 썼습니다.
2. **격식 수준**: 고지·면책 문구라 캐주얼한 표현 대신 격식체(`〜場合があります`)를 썼습니다.
3. **"제휴 병원"의 일본 쪽 표기**: 일본에서 `病院` 은 병상 20개 이상 기관만 가리킵니다. 제공 대상에 클리닉이 포함되면 `提携医療機関` 이 맞습니다. 대상 범위는 법무가 정할 사항이라 원문 그대로 `提携病院` 으로 두었습니다.
4. **한국어 원문 검수 의견 (제안만)**: 제3자 제공 고지로서 제공받는 자, 목적, 항목, 보유 기간, 동의 거부권이 이 한 줄에 없습니다. 이 문구가 동의 화면 본문인지 보조 안내인지에 따라 요건이 달라지므로 법무 확인이 필요합니다. 일본 출시분은 일본 개인정보보호법상 제3자 제공 동의 요건도 따로 확인해야 합니다.

## 4. diff

### `pghd/src/main/resources/messages/message-pghd_ja_JP.properties`

기본 번들(`message-pghd.properties`)에서 해당 키가 있는 **같은 위치**에 넣습니다. 파일 끝에 붙이지 않습니다. 넣기 전에 바로 위 줄이 역슬래시로 끝나지 않는지 확인합니다. 역슬래시로 끝나면 새 키가 앞 값에 흡수됩니다.

```diff
 # (기본 번들의 food.recommend.* 위치와 동일하게)
+food.recommend.tea.title=今日のおすすめ：双和茶
+food.recommend.side.body=カクテキと神仙炉を添えると、満足感が増します。
```

- 값은 각각 한 줄이라 줄 끝 역슬래시가 없습니다.
- 플레이스홀더·스타일 태그는 원문에 없습니다.
- 보류 2건은 ja_JP 파일에 **넣지 않습니다**. 주석으로 초안을 남기는 것도 하지 않습니다. 초안은 PR 본문과 카드에만 둡니다.

### `MessageBundleLocaleParityTest` — `ALLOWED_MISMATCHES`

번역을 넣은 키는 허용 목록에서 빼야 테스트가 통과합니다. 남겨 두면 죽은 항목으로 실패합니다. 실제 자료구조 형식은 테스트 코드에 맞춰 주세요.

```diff
 // message-pghd / ja_JP
-"messages/message-pghd|ja_JP|food.recommend.tea.title",
-"messages/message-pghd|ja_JP|food.recommend.side.body",
-"messages/message-pghd|ja_JP|exercise.pregnancy.high.body",
-"messages/message-pghd|ja_JP|privacy.thirdparty.notice",
+// 의학 검수 대기 — 임신부 혈당 구간별 운동 권고. 담당 카드: <카드 번호>
+"messages/message-pghd|ja_JP|exercise.pregnancy.high.body",
+// 법무·개인정보보호 검토 대기 — 제3자 제공 고지. 담당 카드: <카드 번호>
+"messages/message-pghd|ja_JP|privacy.thirdparty.notice",
```

(1)절 (3)번 확인 결과 허용 목록에 아직 없다면 `-` 줄은 없고 `+` 두 줄만 추가합니다. 이 경우 현재 dev 의 테스트가 이미 실패 중이라는 뜻이므로 같이 보고해 주세요.

### en_US 에 관하여

요청 범위가 ja_JP 라 en_US 는 건드리지 않았습니다. 기본 번들에 4개 키가 추가돼 있으니 en_US 에도 4건이 비어 있을 것입니다.

- 허용 목록에 en_US 4건이 등록돼 있으면 그대로 두면 됩니다.
- 등록돼 있지 않으면 테스트가 실패합니다. **en 번역을 같이 진행**할지, **허용 목록에 사유를 적어 등록**할지 정해 주세요. 보류 2건은 en 도 같은 승인 게이트에 걸립니다.

## 7. PR 본문에 남길 내용 (붙여넣기용)

```
## message-pghd ja_JP 번역

### 반영
- food.recommend.tea.title = 今日のおすすめ：双和茶
- food.recommend.side.body = カクテキと神仙炉を添えると、満足感が増します。
  - 길이 1.05배 (ja 기준 0.9배 초과, 안내문). 잘리면 대안: カクテキと神仙炉を添えて満足感アップ。

### 보류 (승인 대기, ALLOWED_MISMATCHES 등록)
- exercise.pregnancy.high.body — 의학 검수. 초안: 妊娠中にグルコース値が140mg/dL以上のときは、食後15分のウォーキングがおすすめです。痛みがあれば、すぐに中止してください。
- privacy.thirdparty.notice — 법무·개인정보보호. 초안: 収集した血糖値の記録は、提携病院に提供される場合があります。

### 확인 요청
```
