# message-cgm 혈당 표기 일괄 치환 요청 — 반영 보류 및 대안

## 결론

요청하신 세 가지 모두 **이번에는 파일에 반영하지 않았습니다.** 세 가지 모두 번역팀 가이드(langSKILL)의 확정 규칙과 정면으로 충돌하고, 저혈당 경고는 의학 검수를 먼저 받아야 하는 문구입니다. 대신 실제로 고쳐야 할 곳을 찾는 점검 명령과, 의학 검수에 올릴 경고 문구 초안을 아래에 정리했습니다.

| 요청 | 판정 | 근거 |
|---|---|---|
| en: 전부 `blood glucose` 로 | 반영 안 함 | langSKILL `## en` 하드룰(예외 없음): `blood glucose` / `blood sugar` 는 반드시 `glucose` 로 |
| ja: `グルコース値` 를 빼고 `血糖値` 로 통일 | 반영 안 함 | 두 표기는 섞어 쓴 게 아니라 의도적으로 구분한 것(ja-house-rules §2). 한쪽으로 통일하지 않는 것이 규칙 |
| 저혈당 경고를 `Hypoglycemia detected` / `低血糖です` 로 | 반영 안 함, 초안만 작성 | 공통 규칙(웰니스 앱 스코프: 진단하듯 단정하는 표현 금지), `## ja` 규제 대응 표현. 의학 검수 승인 대상 |
| message-cgm 전체 일괄 치환 | 반영 안 함 | 검수 없는 일괄 반영은 금지 사항. 맥락마다 표기가 달라지므로 치환으로 처리할 수 없음 |

## 1. 왜 "의학적으로 정확하게"가 오히려 반대 방향인가

이 앱의 값은 **CGM이 측정한 값**입니다. CGM은 혈액이 아니라 간질액의 포도당을 잽니다. 그래서 CGM 측정값을 `blood glucose` / `血糖値` 라고 부르면 오히려 사실과 어긋납니다.

- **en**: `glucose` 단독 표기는 톤 때문만이 아니라, 측정 대상 면에서도 더 정확합니다. 가이드는 이 규칙을 "예외 없음"으로 못 박았고, 비의료·웰니스 포지셔닝(의료기기가 아님)이 이유로 명시돼 있습니다.
- **ja**: 일본 CGM 제품과 일본 서비스(pasta-japan-server)는 다음처럼 나눠 씁니다.

| 표기 | 쓰는 자리 |
|---|---|
| `グルコース値` | CGM 측정값 자체, 측정값 그래프, 센서 보정, 측정 진행 상태 |
| `血糖値` | 생리학적 개념 설명, 건강 효과 서술, 혈당 스파이크, CGM 데이터가 없는 상태의 안내, 데이터 유형명, 예측 결과 |

  일본 서비스에서 혈당 표기가 들어간 227건 중 215건(94.7%)이 moneyball 과 같은 표기를 씁니다. `home.glucose.card.cgm_inactive` / `manual_only` / `no_data` 처럼 측정값이 없는 맥락만 `血糖` 입니다. 전부 `血糖値` 로 바꾸면 이 구분이 무너지고, 일본 서비스와도 어긋납니다.

  참고로 가이드 `## ja` 의 "血糖値는 회피 없이 표준 용어로 그대로 사용"은 **血糖値를 일부러 피하지 말라**는 뜻이지, グルコース値를 없애라는 뜻이 아닙니다. 두 문서는 충돌하지 않습니다(ja-house-rules §6 "가이드와 어긋나는 지점: 현재 없음").

## 2. 저혈당 경고 — 위험은 분명하게, 진단은 하지 않게

요청하신 의도(위험을 흐리지 말고 확실하게 알리자)는 가이드와 같습니다. 가이드 `## ko` 의 "건강 정보는 명확성이 우선" 예외도 **위험 신호는 위험하다고 분명하게 전달하라**고 합니다. 문제는 "확실하게"를 **진단 선언**으로 표현한 데 있습니다.

| 문구 | 문제 |
|---|---|
| `Hypoglycemia detected` | "detected"는 기기가 질환 상태를 판정했다는 단정. 의료기기의 진단 기능처럼 읽힘(공통 규칙 스코프 위반). 용어집이 `hypoglycemia` 라는 단어 자체는 허용하지만, 그 단어로 진단을 선언해도 된다는 뜻은 아님 |
| `低血糖です` | `## ja` 에 직접 금지로 적혀 있음: 「低血糖」→「目標範囲より低い」, 단정형 대신 「〜の傾向があります」 등. 게다가 CGM 측정값 맥락이므로 표기는 `グルコース値` 쪽 |

경고 문구는 SKILL 승인 게이트의 **의학적 권고·증상** 유형이므로 파일에는 넣지 않고 아래 초안을 의학 검수 카드나 PR 본문에 올립니다. 대응 행동 문장은 한국어 원문 키 값을 확인한 뒤 원문 내용 그대로 옮겨야 하므로 자리만 표시해 두었습니다(원문을 아직 확인하지 못했습니다).

```
# [의학 검수 요청 초안 — 파일 미반영]
# en (알림/경고 — 핵심을 첫 단어에, glucose 단독, 단정 진단 없음)
Your glucose is below your target range. <원문의 대응 행동 문장>
#   짧은 대안(타이틀 자리일 때): Glucose below target range
# ja (CGM 측정값 → グルコース値, 「目標範囲より低い」, 結論を先に)
グルコース値が目標範囲より低くなっています。<원문의 대응 행동 문장>
#   짧은 대안(타이틀 자리일 때): グルコース値が目標範囲より低い状態です
```

- 첫 문장은 위험을 모호하게 말하지 않습니다("낮아질 수 있어요" 같은 완충형은 쓰지 않음). 단정하는 범위는 **측정값이 목표 범위 아래**라는 사실까지이며, 질환명을 선언하지 않습니다.
- 대응 행동(예: 당 섭취, 재측정)은 의학적 권고이므로 원문 내용 그대로만 옮기고 새로 지어내지 않습니다.
- 길이 비율(en 1.2배, ja 0.9배)은 원문을 확인한 뒤 `check_ratio.py` 로 잽니다. 키 이름에 `title` 이 들어가면 짧은 대안을 기본으로 씁니다.

## 3. 대신 할 수 있는 것 — 실제 위반만 골라 고치기

일괄 치환 대신, 가이드를 어기는 곳만 찾아 키 단위로 고치는 방법을 제안합니다. 아래는 실행할 명령입니다(이번 응답에서는 실행하지 않음 — 결과는 아직 없습니다).

```bash
# 경로는 bundles.md 기준 cgm 모듈. 정확한 하위 경로는 가정
B=cgm/src/main/resources/messages

# (1) en: 하드룰 위반 — blood glucose / blood sugar 가 남아 있는 값 → glucose 로 수정 대상
grep -n -i -E "blood (glucose|sugar)" $B/message-cgm_en_US.properties

# (2) ja: 표기 구분 점검 — 키별로 맥락(측정값 vs 개념·데이터 없음)과 표기가 맞는지 사람이 대조
grep -n -E "血糖|グルコース" $B/message-cgm_ja_JP.properties

# (3) 진단성 단정 표현 — 공통 규칙 스코프 위반 후보
grep -n -E "低血糖|高血糖" $B/message-cgm_ja_JP.properties
grep -n -i -E "hypo|hyper|detected" $B/message-cgm_en_US.properties

# (4) 일본 서비스의 같은 키 표기 대조 (ja-house-rules §1)
JP=/Users/kakao/workplace-kakao/global/pasta-japan/server/pasta-japan-server
grep -n "^<키 이름>=" $JP/shared/src/main/resources/messages/message-shared_ja_JP.properties

# (5) 같은 키가 다른 번들에 있는지 — 앞쪽 번들이 이기므로 cgm 을 고쳐도 무효일 수 있음
grep -rn "^<키 이름>=" --include="*.properties" .
```

(1)에서 나온 키는 `glucose` 로 고치는 diff를 바로 드릴 수 있습니다. (2)·(3)은 키마다 맥락을 판단해야 하므로 목록을 받아 표(키 / 현재 값 / 맥락 / 판정 / 수정안)로 정리한 뒤 승인받는 순서로 진행합니다.

수정 후 검사 순서는 다음과 같습니다.

```bash
python3 scripts/check_ratio.py --bundle message-cgm
python3 scripts/check_parity.py --bundle message-cgm
./gradlew :pasta-api:test --tests "*MessageBundleLocaleParityTest*"   # JDK 21
```

경고 키가 지금 en/ja 값이 **없는** 상태라면, 의학 검수가 끝날 때까지 `ALLOWED_MISMATCHES` 에 사유와 담당 카드를 적어 등록합니다(예: `// 저혈당 경고 문구 의학 검수 대기 — <카드 번호>`). 이미 값이 있는 상태라면 기존 값을 그대로 두고 허용 목록은 건드리지 않습니다. 이번에는 어떤 키도 추가·삭제하지 않았으므로 정합성 테스트 상태는 바뀌지 않습니다.

## 4. 그래도 표기 방침을 바꾸고 싶다면

`blood glucose` 하드룰과 ja 표기 구분은 이 저장소에서 정할 수 있는 사항이 아닙니다. 제품의 규제 포지션(의료기기가 아닌 웰니스 앱)과 묶여 있어서, 바꾸려면 다음 경로를 거쳐야 합니다.

1. 번역팀 가이드 정본(사내 GitLab 의 `langSKILL.md`) 개정 요청. 이 저장소의 `references/langskill.md` 사본을 직접 고치지 않습니다
2. 규제·의학 검수 담당자의 포지셔닝 판단(진단 표현을 허용하면 의료기기 해당 여부 판단이 달라질 수 있음)
3. 일본 서비스(pasta-japan-server)와 표기 정합성 재합의

개정이 확정되면 그 기준으로 message-cgm 을 키 단위로 다시 반영하겠습니다.

## 확인된 것과 가정한 것

| 구분 | 내용 |
|---|---|
| 확인됨 | langSKILL `## en` 하드룰(`glucose` 단독, 예외 없음), 공통 규칙 웰니스 스코프, `## ja` 규제 대응 표현(「目標範囲より低い」·단정 회피), ja-house-rules §2 표기 구분과 일본 서비스 실측 수치, SKILL 승인 게이트(의학 검수), 일괄 기계 반영 금지 |
| 확인 못 함 | message-cgm 의 실제 키 목록·현재 값, 저혈당 경고 키 이름과 한국어 원문, 노출 위치(알림 타이틀인지 본문인지), 다른 번들의 중복 키 여부 |
| 가정 | cgm 번들 파일 경로(`cgm/src/main/resources/messages/`). 경고 문구가 CGM 측정값을 근거로 뜨는 알림이라는 점(그래서 ja 초안에 `グルコース値` 를 씀) |

원문 키 목록이나 위 (1)~(3) 명령 결과를 주시면, 키별 판정표와 실제 반영 diff로 이어서 진행하겠습니다.
