**AUTO FAIL 1건: 4-Tier 의존 방향 역행**
- `MealFeedbackService`(application)가 `web.dto.MealFeedbackRequest` 를 import 하고 `save(MealFeedbackRequest req)` 로 받습니다. 01 규칙상 Application 은 Domain 만 참조하고, Web 이 Application DTO 로 변환해서 넘겨야 합니다.
- Controller 가 `Request` 를 그대로 넘기는 것도 같은 문제의 반대편입니다. 05 규칙 예시처럼 Controller 에서 `Request → InDto` 로 변환해 `save(MealFeedbackInDto)` 로 호출하도록 고치면 두 곳이 함께 해결됩니다.

**권장 개선**
- `@RequestBody` 에 `@Valid` 가 없습니다(05 Validation).
- Controller 에 Swagger `@Tag`/`@Operation` 이 없습니다(05, 낮은 우선순위).

**통과**
- `MealFeedbackOutDto.from()` 과 `MealFeedbackResponse.from()` 은 05 의 정적 팩토리 규칙과 일치하므로 그대로 두면 됩니다. 변수명 `req`/`dto` 도 이 프로젝트 규칙에는 제한이 없어 지적하지 않았습니다.
- Service 반환 타입, FQCN, `@Entity` 배치, Bean 관련 항목은 문제가 없습니다.

**확인하지 못한 것**: `MealFeedbackRepository` 선언부와 `MealFeedbackRequest` 의 변환 메서드는 diff 에 없어서 확인하지 못했습니다. 코드 수정은 하지 않았고 보고만 했습니다.
