# PGHDActivityWorkoutRecordGlucoseMapStatisticsRepositoryTest 테스트 추가 + Testcontainers 전환

시뮬레이션이라 파일 수정, git, gradle 은 실행하지 않았다. 아래는 적용할 변경안과 실행할 명령이다. 실행 결과는 아직 없다.

## 1. 확인된 것과 가정한 것

확인된 것 (과제 입력 기준)
- 이 클래스는 `@ActiveProfiles` 가 없어서 `src/test/resources/application.yml` 의 H2(`MODE=MySQL`)로 돈다.
- `test` 프로필은 `application-test.yml` 의 `jdbc:tc:mysql:8.0.23:///` 이다. 옆 `MealGlucoseStatisticsRepositoryTest` 등 4개가 이 프로필을 쓴다.
- 쿼리의 `cgmDeviceId` 조건은 값이 있으면 `(cgm_device_id = ? OR cgm_device_id IS NULL)` 이다. 그래서 cgmDeviceId 가 NULL 인 행은 "다른 행"이 아니라 조회 대상에 포함된다.
- 쿼리는 `fetchOne()` 을 쓴다. 조건에 걸리는 행이 2건 이상이면 `NonUniqueResultException` 이 난다.

가정한 것 (저장소를 직접 못 봐서 확인 필요)
- 엔티티에 `getId()` 가 있다 (Lombok `@Getter` 가정). 기존 테스트가 `getUserId()`, `getCgmDeviceId()` 를 쓰므로 가능성은 높다.
- `application-test.yml` 의 DDL 설정은 옆 4개 테스트가 이미 통과하는 설정이라서 이 클래스에도 그대로 동작한다고 가정한다.
- `.claude/shared/vc-conventions/testcode-convention.md` 와 `.claude/rules/08` 은 읽지 못했다. 메서드 네이밍, 주석(Given/when/then 대소문자 혼용), 섹션 구분 규칙은 기존 테스트 형태를 따랐다. 적용 전에 컨벤션 문서와 대조해 달라.

### 2-2. 추가 테스트 3건

기존 테스트 뒤에 추가한다. 헬퍼 메서드도 같이 둔다.

```java
  @Test
  @DisplayName("운동 기록 - 혈당 매핑 통계 테이블 조회 성공 - 다른 사용자 데이터가 섞여 있어도 해당 사용자 데이터만 조회")
  void searchWorkoutRecordGlucoseMapTest_successOnlyRequestedUser() {
    // Given
    final Long requestedUserId = 1L;
    final Long otherUserId = 2L;
    final Integer cgmDeviceOrdinalNumber = 1;
    WorkoutRecordGlucoseMapStatistics requestedUserStatistics =
        saveStatistics(requestedUserId, null, cgmDeviceOrdinalNumber);
    saveStatistics(otherUserId, null, cgmDeviceOrdinalNumber);
    testEntityManager.flush();
    testEntityManager.clear();

    // when
    WorkoutRecordGlucoseMapStatistics actualWorkoutRecordGlucoseMap =
        workoutRecordGlucoseMapStatisticsRepository.findWithOrdinalNumberByUserIdAndCgmDeviceInfos(
            requestedUserId, null, null, cgmDeviceOrdinalNumber);

    // then
    Assertions.assertThat(actualWorkoutRecordGlucoseMap).isNotNull();
    Assertions.assertThat(actualWorkoutRecordGlucoseMap.getId()).isEqualTo(requestedUserStatistics.getId());
    Assertions.assertThat(actualWorkoutRecordGlucoseMap.getUserId()).isEqualTo(requestedUserId);
  }

  @Test
  @DisplayName("운동 기록 - 혈당 매핑 통계 테이블 조회 성공 - cgmDeviceId 가 다른 행은 제외")
  void searchWorkoutRecordGlucoseMapTest_successExcludesDifferentCgmDeviceId() {
    // Given
    final Long userId = 1L;
    final Long requestedCgmDeviceId = 10L;
    final Long otherCgmDeviceId = 20L;
    WorkoutRecordGlucoseMapStatistics requestedDeviceStatistics =
        saveStatistics(userId, requestedCgmDeviceId, 1);
    saveStatistics(userId, otherCgmDeviceId, 2);
    testEntityManager.flush();
    testEntityManager.clear();

    // when
    WorkoutRecordGlucoseMapStatistics actualWorkoutRecordGlucoseMap =
        workoutRecordGlucoseMapStatisticsRepository.findWithOrdinalNumberByUserIdAndCgmDeviceInfos(
            userId, requestedCgmDeviceId, null, null);

    // then
    Assertions.assertThat(actualWorkoutRecordGlucoseMap).isNotNull();
    Assertions.assertThat(actualWorkoutRecordGlucoseMap.getId()).isEqualTo(requestedDeviceStatistics.getId());
    Assertions.assertThat(actualWorkoutRecordGlucoseMap.getCgmDeviceId()).isEqualTo(requestedCgmDeviceId);
  }

  @Test
  @DisplayName("운동 기록 - 혈당 매핑 통계 테이블 조회 성공 - 일치하는 cgmDeviceId 행이 없으면 null")
  void searchWorkoutRecordGlucoseMapTest_successNullWhenOnlyDifferentCgmDeviceId() {
    // Given
    final Long userId = 1L;
    saveStatistics(userId, 20L, 1);
    testEntityManager.flush();
    testEntityManager.clear();

    // when
    WorkoutRecordGlucoseMapStatistics actualWorkoutRecordGlucoseMap =
        workoutRecordGlucoseMapStatisticsRepository.findWithOrdinalNumberByUserIdAndCgmDeviceInfos(
            userId, 10L, null, null);

    // then
    Assertions.assertThat(actualWorkoutRecordGlucoseMap).isNull();
  }

  private WorkoutRecordGlucoseMapStatistics saveStatistics(
      Long userId, Long cgmDeviceId, Integer cgmDeviceOrdinalNumber) {
    return workoutRecordGlucoseMapStatisticsRepository.save(
        WorkoutRecordGlucoseMapStatistics.builder()
            .userId(userId)
            .cgmDeviceId(cgmDeviceId)
            .cgmDeviceCompanyName(null)
            .cgmDeviceOrdinalNumber(cgmDeviceOrdinalNumber)
            .avgGlucoseValueOnStartedAt(100.0f)
            .avgGlucoseValueOnEndedAt(null)
            .build());
  }
```

설계 이유
- 두 케이스 모두 단일 조건이 빠지면 `fetchOne()` 이 2건을 만나 예외가 나도록 데이터를 짰다. `userId` 조건이나 `cgmDeviceId` 조건이 사라지면 테스트가 실패한다. 즉 필터를 실제로 검증한다.
- 저장 후 `flush()` + `clear()` 를 했다. 이걸 안 하면 1차 캐시의 같은 인스턴스가 돌아와서 DB 조회 결과를 검증하지 못한다.
- 행마다 `cgmDeviceOrdinalNumber` 를 다르게 줬다. 유니크 제약이 있어도 충돌하지 않도록 한 것이다. 제약 존재 여부는 확인하지 못했다.
- 세 번째 테스트(일치 행 없음 → null)는 요청에 없었지만, "다른 행은 빠진다"의 반대편 경계라서 같이 넣었다. 필요 없으면 빼도 된다.
- `@DataJpaTest` 가 테스트마다 롤백하므로 별도 정리 코드는 넣지 않았다.

### 2-3. 새 테스트에 `@Order` 를 붙이지 않은 이유

클래스가 `@TestMethodOrder(MethodOrderer.DisplayName.class)` 라서 `@Order` 는 실행 순서에 영향이 없다. 기존 테스트의 `@Order(1~7)` 는 사실상 장식이다. 새 테스트는 순서에 의존하지 않도록 만들었고, 기존 테스트의 `@Order` 는 건드리지 않았다. 정리 여부는 별개 작업으로 남긴다.

## 3. 프로필 전환 영향 (사용자 확인 필요)

`@ActiveProfiles("test")` 는 새 테스트 3건만이 아니라 이 클래스의 기존 7건 전부를 H2 에서 MySQL 8.0.23 컨테이너로 옮긴다. 아래는 가능성이지 확인된 사실이 아니다.

- Docker 가 있어야 한다. 로컬과 CI 에서 Docker 데몬이 없으면 이 클래스는 컨텍스트 로딩 단계에서 실패한다.
- 기존 7건이 MySQL 에서도 통과하는지 모른다. 특히 조회 4건은 `fetchOne()` 을 쓰고, 테스트 간 데이터 오염은 롤백에 기대고 있다. H2 의 `MODE=MySQL` 과 실제 MySQL 은 NULL 정렬, float 비교, 제약 에러 메시지 등에서 다를 수 있다.
- 같은 패키지의 `PGHDActivityWorkoutRecordGlucoseMap*` 3개 클래스 중 이 클래스만 바뀌고 나머지는 H2 로 남는다. 일관성 문제가 생기면 별도로 정리해야 한다. 나는 이번 요청 범위 밖이라 건드리지 않았다.
- 테스트 시간이 늘어난다. 컨테이너는 같은 JVM 에서 이미 다른 테스트가 띄운 것을 재사용하는지 여부를 확인하지 못했다.

만약 전환 후 기존 테스트 일부가 깨지면, 원인을 확인하지 않고 테스트를 고치거나 프로필을 되돌리지 않고 먼저 알려 달라고 하겠다.

## 4. 실행할 명령 (아직 실행하지 않음)

1. 변경 전 기준선 확인 (H2, 기존 상태)
   ```
   ./gradlew :analysis:test --tests "*PGHDActivityWorkoutRecordGlucoseMapStatisticsRepositoryTest"
   ```
2. 변경 적용 후 같은 명령 재실행. 기존 7건과 신규 3건이 모두 통과해야 한다. Docker 가 떠 있어야 한다.
3. 기존 테스트가 MySQL 에서 깨지면 그 건을 분리해서 보고한다.
4. 회귀 확인: 같은 패키지 Repository 테스트 전체
   ```
   ./gradlew :analysis:test --tests "com.kakaohealthcare.moneyball.analysis.repository.*"
   ```
5. 신규 테스트의 변이 확인(선택): `Impl` 의 `q.userId.eq(userId)` 를 임시로 지우면 1번 신규 테스트가, `eqCgmDeviceId` 를 지우면 2번 신규 테스트가 실패하는지 본다. 확인 후 반드시 원복한다.

커밋은 요청이 없어서 하지 않는다.

## 5. 완료 보고

- 변경 대상: `analysis/src/test/java/com/kakaohealthcare/moneyball/analysis/repository/PGHDActivityWorkoutRecordGlucoseMapStatisticsRepositoryTest.java` 한 파일. 운영 코드는 건드리지 않는다.
- 내용: `@ActiveProfiles("test")` 추가, 테스트 3건과 헬퍼 1개 추가.
- 상태: 코드는 작성했지만 컴파일, 실행, 통과 여부는 검증하지 않았다. `getId()` 존재, 유니크 제약 여부, MySQL 에서 기존 7건 통과 여부가 미확인이다.

  1. `cgmDeviceId` 가 NULL 인 행은 쿼리 설계상 조회에 포함된다. 요청의 "다른 행은 빠지는지"는 NULL 이 아닌 다른 값 기준으로 해석해 테스트했다. NULL 행 포함까지 고정하는 테스트가 필요한지 알려 달라.
  2. 프로필 전환이 클래스 전체에 적용되므로, 위 3절의 영향을 감수할지 확인해 달라.
