# MealRecommendationQueryService 단위 테스트 + MealCandidateJpaRepository 쿼리 테스트

시뮬레이션이라 파일을 만들거나 gradle 을 실행하지 않았다. 아래는 저장소에 넣을 코드와 실행할 명령이며, 실행 결과는 없다.

## 0. 컨벤션 질문에 대한 답

- `.claude/shared/vc-conventions-guide.md` 와 `.claude/shared/vc-conventions/` 가 이 저장소에 없다. 그래서 조직 전용 컨벤션은 확인할 수 없고, 적용 여부를 판단할 근거도 없다. 조직 컨벤션을 이 저장소에 강제할 필요는 없다.
- `.claude/rules/08-test-code-convention.md` 와 `09-guardrails.md` 는 이 저장소에 있다. 이 둘은 저장소 안에서 확인되는 규칙이라 그대로 따랐다.
  - 메서드명 영어 `[Method]_[Scenario]_[ExpectedResult]`, `@DisplayName` 한글, AssertJ 만 사용.
  - 서비스 단위 테스트는 Spring 없이 생성자 주입. 상태를 가진 Repository 는 Fake, 반환값만 중요한 협력 객체는 Stub.
  - 테스트 DB 는 Testcontainers MySQL. 운영이 MySQL 8 이므로 H2 로 바꾸지 않는다.
- 조직 컨벤션 문서가 따로 있다면 경로를 알려 달라. 그러면 아래 코드와 대조해서 다른 점만 고친다.

## 1. 확인된 것과 가정한 것

확인된 것 (요청과 맥락에서 읽은 것)
- 서비스는 `MealCandidateRepository`(domain) 와 `NutritionScoreCalculator`(domain) 에 의존하고, `recommend(Long userId, int limit)` 는 점수 내림차순으로 limit 개를 반환한다.
- `MealCandidateRepository.findAllByUserId` 는 삭제되지 않은 후보만 돌려주는 계약이다.
- `MealCandidateJpaRepository.findAllByUserIdAndDeletedFalse(Long)` 이 존재한다.
- Spring Boot 3.2.2, JDK 21, 운영 MySQL 8, `src/test/resources/` 는 비어 있다.

가정한 것 (코드를 못 봐서 맞춰야 하는 것. 컴파일 오류가 나면 여기부터 고친다)

| 가정 | 틀렸을 때 |
|---|---|
| `MealCandidate` 는 `id`, `userId`, `name` 으로 만들 수 있고 `static MealCandidate of(Long id, Long userId, String name)` 같은 생성 수단이 있다 | `candidate(...)` 헬퍼 한 곳만 수정 |
| `MealRecommendationOutDto` 는 `name()`, `score()` 접근자를 가진다 | `extracting(...)` 부분 수정 |
| `MealCandidateJpaEntity` 는 builder 로 `userId`, `name`, `deleted` 를 세팅할 수 있다 | `jpaEntity(...)` 헬퍼 수정 (builder 가 없으면 reflection 헬퍼로 대체) |
| 같은 점수일 때 순서는 계약이 없다 | 동점 테스트는 쓰지 않았다 |
| `limit <= 0` 동작은 정해져 있지 않다 | 테스트를 쓰지 않았다. 정책을 정하면 추가 |
| 스키마는 Flyway 없이 JPA 가 만든다 (`src/main/resources` 의 마이그레이션 유무를 못 봤다) | Flyway 가 있으면 `application-test.yml` 의 `ddl-auto` 를 `validate` 로 두고 flyway 를 켠다 |

## 2. 서비스 단위 테스트 (Spring 없음)

요청대로 점수 계산기는 `StubNutritionScoreCalculator` 로 만들었다. `score(MealCandidate)` 의 반환값만 정해두면 되는 협력 객체라 Stub 이 맞다.

Repository 는 요청에 Stub 지정이 없었고, 규칙상 상태를 가진 저장소는 Fake 다. 그래서 `FakeMealCandidateRepository` 로 만들었다. 후보를 `save` 해두면 userId 로 걸러서 돌려주고, 테스트는 반환값만 검증한다. 호출 횟수는 검증하지 않는다.

점수를 지정하지 않은 후보가 들어오면 Stub 이 예외를 던진다. 점수 설정을 빠뜨린 테스트가 0점으로 조용히 통과하는 것을 막기 위해서다.

`src/test/java/.../application/StubNutritionScoreCalculator.java`

```java
package com.example.mealrecommender.application;

import com.example.mealrecommender.domain.MealCandidate;
import com.example.mealrecommender.domain.NutritionScoreCalculator;

import java.util.HashMap;
import java.util.Map;

class StubNutritionScoreCalculator implements NutritionScoreCalculator {

    private final Map<MealCandidate, Integer> scores = new HashMap<>();

    void setScore(MealCandidate candidate, int score) {
        scores.put(candidate, score);
    }

    @Override
    public int score(MealCandidate candidate) {
        Integer score = scores.get(candidate);
        if (score == null) {
            throw new IllegalStateException("점수가 지정되지 않은 후보: " + candidate);
        }
        return score;
    }
}
```

`src/test/java/.../application/FakeMealCandidateRepository.java`

```java
package com.example.mealrecommender.application;

import com.example.mealrecommender.domain.MealCandidate;
import com.example.mealrecommender.domain.MealCandidateRepository;

import java.util.ArrayList;
import java.util.List;

class FakeMealCandidateRepository implements MealCandidateRepository {

    private final List<MealCandidate> store = new ArrayList<>();

    void save(MealCandidate candidate) {
        store.add(candidate);
    }

    @Override
    public List<MealCandidate> findAllByUserId(Long userId) {
        return store.stream()
                .filter(candidate -> candidate.userId().equals(userId))
                .toList();
    }
}
```

`src/test/java/.../application/MealRecommendationQueryServiceTest.java`

```java
package com.example.mealrecommender.application;

import com.example.mealrecommender.domain.MealCandidate;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;

import java.util.List;

import static org.assertj.core.api.Assertions.assertThat;

class MealRecommendationQueryServiceTest {

    private static final Long USER_ID = 1L;
    private static final Long OTHER_USER_ID = 2L;

    private FakeMealCandidateRepository fakeRepository;
    private StubNutritionScoreCalculator stubCalculator;
    private MealRecommendationQueryService service;

    @BeforeEach
    void setUp() {
        fakeRepository = new FakeMealCandidateRepository();
        stubCalculator = new StubNutritionScoreCalculator();
        service = new MealRecommendationQueryService(fakeRepository, stubCalculator);
    }

    @Test
    @DisplayName("후보를 점수 내림차순으로 정렬해 limit 개만 돌려준다")
    void recommend_withMoreCandidatesThanLimit_returnsTopScoresDescending() {
        // Given
        saveScored(USER_ID, "비빔밥", 70);
        saveScored(USER_ID, "샐러드", 90);
        saveScored(USER_ID, "라면", 20);
        saveScored(USER_ID, "닭가슴살", 85);

        // When
        List<MealRecommendationOutDto> result = service.recommend(USER_ID, 2);

        // Then
        assertThat(result)
                .extracting(MealRecommendationOutDto::name, MealRecommendationOutDto::score)
                .containsExactly(
                        org.assertj.core.groups.Tuple.tuple("샐러드", 90),
                        org.assertj.core.groups.Tuple.tuple("닭가슴살", 85));
    }

    @Test
    @DisplayName("limit 가 후보 수보다 크면 후보 전체를 점수 내림차순으로 돌려준다")
    void recommend_withLimitLargerThanCandidates_returnsAllSorted() {
        // Given
        saveScored(USER_ID, "비빔밥", 70);
        saveScored(USER_ID, "샐러드", 90);

        // When
        List<MealRecommendationOutDto> result = service.recommend(USER_ID, 10);

        // Then
        assertThat(result)
                .extracting(MealRecommendationOutDto::name)
                .containsExactly("샐러드", "비빔밥");
    }

    @Test
    @DisplayName("후보가 하나도 없으면 빈 목록을 돌려준다")
    void recommend_withNoCandidates_returnsEmptyList() {
        // Given: 저장된 후보 없음

        // When
        List<MealRecommendationOutDto> result = service.recommend(USER_ID, 5);

        // Then
        assertThat(result).isEmpty();
    }

    @Test
    @DisplayName("다른 사용자의 후보는 점수가 높아도 추천에 포함하지 않는다")
    void recommend_withOtherUsersCandidates_excludesThem() {
        // Given
        saveScored(USER_ID, "비빔밥", 70);
        saveScored(OTHER_USER_ID, "스테이크", 99);

        // When
        List<MealRecommendationOutDto> result = service.recommend(USER_ID, 5);

        // Then
        assertThat(result)
                .extracting(MealRecommendationOutDto::name)
                .containsExactly("비빔밥");
    }

    private void saveScored(Long userId, String name, int score) {
        // 가정: MealCandidate 생성 수단. 실제 시그니처에 맞게 이 헬퍼만 수정한다.
        MealCandidate candidate = MealCandidate.of(nextId(), userId, name);
        fakeRepository.save(candidate);
        stubCalculator.setScore(candidate, score);
    }

    private long idSequence = 0L;

    private Long nextId() {
        return ++idSequence;
    }
}
```

## 3. JPA 쿼리 테스트 (Testcontainers MySQL)

### 테스트 DB 결정

"알아서" 하라고 했으므로 정했다. Testcontainers MySQL 8 을 쓴다. H2 는 쓰지 않는다.
- 운영이 MySQL 8 이고, 이 저장소의 `09-guardrails.md` 가 테스트 DB 를 H2 로 바꾸는 것을 금지한다. 실패 시에도 H2 로 돌리지 않고 Docker 실행 쪽을 고친다.
- 이 쿼리는 파생 쿼리(`findAllByUserIdAndDeletedFalse`)라 H2 에서도 통과할 가능성이 높다. 하지만 통과한다고 MySQL 동작을 보장하지는 않는다. 이후 MySQL 전용 쿼리가 생겨도 같은 설정을 쓰도록 처음부터 MySQL 로 둔다.
- Docker 가 로컬과 CI 에서 실행 중이어야 한다.

### 의존성 추가 (`build.gradle`)

Spring Boot 3.2.2 는 `@ServiceConnection` 을 지원하므로 datasource URL 을 직접 꽂는 코드가 필요 없다. 버전은 Boot BOM 이 관리한다.

```groovy
dependencies {
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
    testImplementation 'org.springframework.boot:spring-boot-testcontainers'
    testImplementation 'org.testcontainers:junit-jupiter'
    testImplementation 'org.testcontainers:mysql'
}
```

### 테스트 설정

`src/test/resources/application-test.yml`

```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: create-drop   # 가정: Flyway 없음. Flyway 가 있으면 validate + flyway 활성화
    properties:
      hibernate:
        format_sql: true
```

컨테이너 정의는 별도 `@TestConfiguration` 클래스로 분리한다. 컨테이너가 테스트 클래스마다 새로 뜨지 않도록 `static` 으로 공유한다.

### 쿼리 테스트

Fake 가 의미 없는 영역이다. 쿼리가 실제 SQL 로 어떻게 동작하는지가 검증 대상이므로 Real DB 를 쓴다. 필드 `@Autowired` 를 피하고 `@BeforeEach` 파라미터로 주입받는다.

`src/test/java/.../infrastructure/MealCandidateJpaRepositoryTest.java`

```java
package com.example.mealrecommender.infrastructure;

import com.example.mealrecommender.support.MySqlTestContainerConfig;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.jdbc.AutoConfigureTestDatabase;
import org.springframework.boot.test.autoconfigure.orm.jpa.DataJpaTest;
import org.springframework.context.annotation.Import;
import org.springframework.test.context.ActiveProfiles;

import java.util.List;

import static org.assertj.core.api.Assertions.assertThat;

@DataJpaTest
@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE) // H2 로 치환하지 않는다
@Import(MySqlTestContainerConfig.class)
@ActiveProfiles("test")
class MealCandidateJpaRepositoryTest {

    private static final Long USER_ID = 1L;
    private static final Long OTHER_USER_ID = 2L;

    private MealCandidateJpaRepository repository;

    @BeforeEach
    void setUp(@Autowired MealCandidateJpaRepository repository) {
        this.repository = repository;
    }

    @Test
    @DisplayName("해당 사용자의 삭제되지 않은 후보만 조회한다")
    void findAllByUserIdAndDeletedFalse_withDeletedAndOtherUser_returnsOnlyActiveOfUser() {
        // Given
        repository.save(jpaEntity(USER_ID, "비빔밥", false));
        repository.save(jpaEntity(USER_ID, "샐러드", false));
        repository.save(jpaEntity(USER_ID, "삭제된메뉴", true));
        repository.save(jpaEntity(OTHER_USER_ID, "스테이크", false));

        // When
        List<MealCandidateJpaEntity> result = repository.findAllByUserIdAndDeletedFalse(USER_ID);

        // Then
        assertThat(result)
                .extracting(MealCandidateJpaEntity::getName)
                .containsExactlyInAnyOrder("비빔밥", "샐러드");
    }

    @Test
    @DisplayName("사용자의 후보가 전부 삭제됐으면 빈 목록을 돌려준다")
    void findAllByUserIdAndDeletedFalse_withAllDeleted_returnsEmptyList() {
        // Given
        repository.save(jpaEntity(USER_ID, "삭제된메뉴1", true));
        repository.save(jpaEntity(USER_ID, "삭제된메뉴2", true));

        // When
        List<MealCandidateJpaEntity> result = repository.findAllByUserIdAndDeletedFalse(USER_ID);

        // Then
        assertThat(result).isEmpty();
    }

    @Test
    @DisplayName("후보가 없는 사용자는 빈 목록을 돌려준다")
    void findAllByUserIdAndDeletedFalse_withUnknownUser_returnsEmptyList() {
        // Given
        repository.save(jpaEntity(OTHER_USER_ID, "스테이크", false));

        // When
        List<MealCandidateJpaEntity> result = repository.findAllByUserIdAndDeletedFalse(USER_ID);

        // Then
        assertThat(result).isEmpty();
    }

    private MealCandidateJpaEntity jpaEntity(Long userId, String name, boolean deleted) {
        // 가정: builder 존재. 실제 엔티티 생성 방식에 맞게 이 헬퍼만 수정한다.
        return MealCandidateJpaEntity.builder()
                .userId(userId)
                .name(name)
                .deleted(deleted)
                .build();
    }
}
```

`@DataJpaTest` 는 트랜잭션 안에서 실행되므로 save 후 조회가 같은 영속성 컨텍스트에서 이뤄질 수 있다. 파생 쿼리 실행 전에 flush 가 자동으로 일어나므로 이 시나리오는 SQL 이 실제로 나가는 것을 거친다. 다만 엔티티를 직접 수정하는 시나리오가 추가되면 `flush()`/`clear()` 가 필요하다.

## 5. 완료 보고

만든 것 (시뮬레이션, 저장소에 쓰지 않음)
- `StubNutritionScoreCalculator`, `FakeMealCandidateRepository`, `MealRecommendationQueryServiceTest` (4 케이스)
- `MySqlTestContainerConfig`, `application-test.yml`, `MealCandidateJpaRepositoryTest` (3 케이스)
- `build.gradle` 에 testcontainers 의존성 4줄 추가 안

검증 상태
- 컴파일도 테스트도 실행하지 않았다. 통과 여부는 알 수 없다.
- 도메인 클래스 시그니처를 못 봐서 `MealCandidate.of(...)`, `MealRecommendationOutDto` 접근자, `MealCandidateJpaEntity.builder()` 는 가정이다. 위 가정 표의 헬퍼 3곳을 실제 코드에 맞춰야 한다.

판단이 필요한 것
1. 동점일 때 정렬 순서와 `limit <= 0` 동작이 정해져 있지 않아 테스트를 쓰지 않았다. 정책을 정하면 알려 달라.
2. Flyway 사용 여부에 따라 `application-test.yml` 의 `ddl-auto` 가 바뀐다.
3. 조직 컨벤션 문서 경로가 있으면 대조하겠다. 커밋은 요청이 없어 하지 않았다.
