설계 메모
- 쿼리가 `fetchOne()` 이라 조건이 하나라도 빠지면 2건이 잡혀 `NonUniqueResultException` 으로 실패한다. 각 테스트는 정답이 정확히 1건이 되게 픽스처를 짰고, 정답 행과 제외돼야 할 행의 `avgGlucoseValueOnStartedAt` 을 다르게 해서 엉뚱한 행이 반환돼도 잡히게 했다
- 1번: userId 만 다르고 나머지(기기·순번)는 같게 해서 userId 조건이 빠지면 실패한다
- 2번: 같은 사용자에서 cgmDeviceId 만 다르게 했다
- 3번: `eqCgmDeviceId` 의 `OR IS NULL` 분기를 본다. 이 조건을 `=` 만으로 바꾸면 실패한다
- `save` 뒤 `flush()` + `clear()` 로 1차 캐시를 비워 실제 DB 조회(매핑·쿼리)를 타게 했다
- 새 테스트에는 `@Order` 를 붙이지 않았다. 데이터는 테스트마다 `@DataJpaTest` 트랜잭션이 롤백하고, 값이 서로 독립이라 순서에 기대지 않는다 (vc-testcode 4절 상태 공유)
- `cgmDeviceCompanyName` 은 조회 인자를 `null` 로 두어 조건에서 빠지게 했다. 회사명 필터 자체는 이번 요청 범위 밖이라 테스트하지 않았다
- `var` 미사용, FQCN 인라인 없음, 변수명은 타입명 전체 사용
