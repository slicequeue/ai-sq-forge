## 테스트 DB 구성

`src/test/resources/` 가 비어 있고 조직 컨벤션 비적용이므로 규칙 09 에 따라 Testcontainers MySQL 을 쓴다. H2 는 쓰지 않는다. 운영이 MySQL 8 이라 방언 차이(함수형 인덱스 등)를 H2 가 가린다.

`build.gradle` (Spring Boot 3.2.2 는 `@ServiceConnection` 지원, 버전은 Boot BOM 이 관리):

```groovy
dependencies {
    testImplementation 'org.springframework.boot:spring-boot-starter-test'
    testImplementation 'org.springframework.boot:spring-boot-testcontainers'
    testImplementation 'org.testcontainers:junit-jupiter'
    testImplementation 'org.testcontainers:mysql'
}
```

별도 `application-test.yml` 은 만들지 않았다. 컨테이너 접속 정보는 `@ServiceConnection` 이 주입하고, 스키마 생성 방식은 테스트 클래스 `properties` 로 둔다. 실행 환경에 Docker 가 떠 있어야 한다.

### 1) Application — `src/test/java/.../application/MealRecommendationQueryServiceTest.java`

```java
package com.example.mealrecommender.application;

import static org.assertj.core.api.Assertions.assertThat;

import com.example.mealrecommender.domain.FakeMealCandidateRepository;
import com.example.mealrecommender.domain.MealCandidate;
import com.example.mealrecommender.domain.StubNutritionScoreCalculator;
import java.util.List;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Nested;
import org.junit.jupiter.api.Test;

class MealRecommendationQueryServiceTest {

    private static final Long USER_ID = 1L;
    private static final Long OTHER_USER_ID = 2L;

    private FakeMealCandidateRepository fakeMealCandidateRepository;
    private StubNutritionScoreCalculator stubNutritionScoreCalculator;
    private MealRecommendationQueryService mealRecommendationQueryService;

    @BeforeEach
    void setUp() {
        fakeMealCandidateRepository = new FakeMealCandidateRepository();
        stubNutritionScoreCalculator = new StubNutritionScoreCalculator();
        mealRecommendationQueryService =
                new MealRecommendationQueryService(fakeMealCandidateRepository, stubNutritionScoreCalculator);
    }

    @Nested
    @DisplayName("recommend")
    class Recommend {

        @Test
        @DisplayName("후보가 limit 보다 많으면 점수 높은 순으로 limit 개만 반환한다")
        void recommend_candidatesExceedLimit_returnsTopScoresDescending() {
            // Given — 입력 순서(10, 90, 50, 70, 30)가 점수 순서와 다르고 limit(3) 을 넘는 5건
            MealCandidate score10Candidate = saveCandidate(USER_ID, 101L, "샐러드", 10);
            MealCandidate score90Candidate = saveCandidate(USER_ID, 102L, "닭가슴살", 90);
            MealCandidate score50Candidate = saveCandidate(USER_ID, 103L, "현미밥", 50);
            MealCandidate score70Candidate = saveCandidate(USER_ID, 104L, "연어", 70);
            MealCandidate score30Candidate = saveCandidate(USER_ID, 105L, "두부", 30);

            // When
            List<MealRecommendationOutDto> mealRecommendationOutDtoList =
                    mealRecommendationQueryService.recommend(USER_ID, 3);

            // Then
            assertThat(mealRecommendationOutDtoList)
                    .extracting(MealRecommendationOutDto::mealName)
                    .containsExactly(
                            score90Candidate.getName(), score70Candidate.getName(), score50Candidate.getName());
        }

        @Test
        @DisplayName("후보가 limit 보다 적으면 후보 전체를 점수 내림차순으로 반환한다")
        void recommend_candidatesFewerThanLimit_returnsAllDescending() {
            // Given
            saveCandidate(USER_ID, 101L, "샐러드", 20);
            saveCandidate(USER_ID, 102L, "닭가슴살", 80);

            // When
            List<MealRecommendationOutDto> mealRecommendationOutDtoList =
                    mealRecommendationQueryService.recommend(USER_ID, 10);

            // Then
            assertThat(mealRecommendationOutDtoList)
                    .extracting(MealRecommendationOutDto::mealName)
                    .containsExactly("닭가슴살", "샐러드");
        }

        @Test
        @DisplayName("다른 사용자의 후보는 점수가 높아도 추천에 포함하지 않는다")
        void recommend_otherUserCandidateHasHigherScore_excludesIt() {
            // Given
            saveCandidate(USER_ID, 101L, "샐러드", 20);
            saveCandidate(OTHER_USER_ID, 201L, "다른 사용자 식단", 100);

            // When
            List<MealRecommendationOutDto> mealRecommendationOutDtoList =
                    mealRecommendationQueryService.recommend(USER_ID, 10);

            // Then
            assertThat(mealRecommendationOutDtoList)
                    .extracting(MealRecommendationOutDto::mealName)
                    .containsExactly("샐러드");
        }

        @Test
        @DisplayName("삭제된 후보는 점수가 높아도 추천에 포함하지 않는다")
        void recommend_deletedCandidateHasHigherScore_excludesIt() {
            // Given
            saveCandidate(USER_ID, 101L, "샐러드", 20);
            MealCandidate deletedCandidate = newCandidate(102L, "삭제된 식단");
            stubNutritionScoreCalculator.scoreOf(deletedCandidate, 100);
            fakeMealCandidateRepository.addDeleted(USER_ID, deletedCandidate);

            // When
            List<MealRecommendationOutDto> mealRecommendationOutDtoList =
                    mealRecommendationQueryService.recommend(USER_ID, 10);

            // Then
            assertThat(mealRecommendationOutDtoList)
                    .extracting(MealRecommendationOutDto::mealName)
                    .containsExactly("샐러드");
        }

        @Test
        @DisplayName("후보가 하나도 없으면 빈 목록을 반환한다")
        void recommend_noCandidates_returnsEmptyList() {
            // When
            List<MealRecommendationOutDto> mealRecommendationOutDtoList =
                    mealRecommendationQueryService.recommend(USER_ID, 3);

            // Then
            assertThat(mealRecommendationOutDtoList).isEmpty();
        }
    }

    private MealCandidate saveCandidate(Long userId, Long mealCandidateId, String mealName, int score) {
        MealCandidate mealCandidate = newCandidate(mealCandidateId, mealName);
        stubNutritionScoreCalculator.scoreOf(mealCandidate, score);
        fakeMealCandidateRepository.add(userId, mealCandidate);
        return mealCandidate;
    }

    // 가정: MealCandidate 생성 방식은 받지 못했다. 실제 팩토리·빌더에 맞춰 이 한 곳만 고친다.
    private MealCandidate newCandidate(Long mealCandidateId, String mealName) {
        return MealCandidate.builder().id(mealCandidateId).name(mealName).build();
    }
}
```

```java
package com.example.mealrecommender.domain;

import java.util.ArrayList;
import java.util.List;
import java.util.Map;
import java.util.HashMap;

// 가정: MealCandidateRepository 가 선언한 메서드는 findAllByUserId 하나다. 더 있으면 구현을 추가해야 컴파일된다.
public class FakeMealCandidateRepository implements MealCandidateRepository {

    private final Map<Long, List<MealCandidate>> activeCandidatesByUserId = new HashMap<>();
    private final Map<Long, List<MealCandidate>> deletedCandidatesByUserId = new HashMap<>();

    public void add(Long userId, MealCandidate mealCandidate) {
        activeCandidatesByUserId.computeIfAbsent(userId, key -> new ArrayList<>()).add(mealCandidate);
    }

    public void addDeleted(Long userId, MealCandidate mealCandidate) {
        deletedCandidatesByUserId.computeIfAbsent(userId, key -> new ArrayList<>()).add(mealCandidate);
    }

    // 실제 계약과 같은 조건: 해당 사용자의 삭제되지 않은 후보만 돌려준다. 삭제분(deletedCandidatesByUserId)은 반환하지 않는다.
    @Override
    public List<MealCandidate> findAllByUserId(Long userId) {
        return new ArrayList<>(activeCandidatesByUserId.getOrDefault(userId, List.of()));
    }
}
```

### 3) Infrastructure — `src/test/java/.../infrastructure/MealCandidateJpaRepositoryTest.java`

```java
package com.example.mealrecommender.infrastructure;

import static org.assertj.core.api.Assertions.assertThat;

import java.util.List;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.boot.test.autoconfigure.jdbc.AutoConfigureTestDatabase;
import org.springframework.boot.test.autoconfigure.orm.jpa.DataJpaTest;
import org.springframework.boot.test.autoconfigure.orm.jpa.TestEntityManager;
import org.springframework.boot.testcontainers.service.connection.ServiceConnection;
import org.testcontainers.containers.MySQLContainer;
import org.testcontainers.junit.jupiter.Container;
import org.testcontainers.junit.jupiter.Testcontainers;

@Testcontainers
@DataJpaTest(properties = "spring.jpa.hibernate.ddl-auto=create-drop")
@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE)
class MealCandidateJpaRepositoryTest {

    private static final Long USER_ID = 1L;
    private static final Long OTHER_USER_ID = 2L;

    @Container
    @ServiceConnection
    static MySQLContainer<?> mySqlContainer = new MySQLContainer<>("mysql:8.0");

    @Autowired private MealCandidateJpaRepository mealCandidateJpaRepository;
    @Autowired private TestEntityManager testEntityManager;

    @Test
    @DisplayName("해당 사용자의 삭제되지 않은 후보만 조회한다")
    void findAllByUserIdAndDeletedFalse_mixedCandidates_returnsOnlyActiveOfUser() {
        // Given
        MealCandidateJpaEntity activeEntity = persist(USER_ID, "닭가슴살", false);
        MealCandidateJpaEntity anotherActiveEntity = persist(USER_ID, "연어", false);
        persist(USER_ID, "삭제된 식단", true);
        persist(OTHER_USER_ID, "다른 사용자 식단", false);
        testEntityManager.clear();

        // When
        List<MealCandidateJpaEntity> mealCandidateJpaEntityList =
                mealCandidateJpaRepository.findAllByUserIdAndDeletedFalse(USER_ID);

        // Then
        assertThat(mealCandidateJpaEntityList)
                .extracting(MealCandidateJpaEntity::getId)
                .containsExactlyInAnyOrder(activeEntity.getId(), anotherActiveEntity.getId());
    }

    @Test
    @DisplayName("삭제된 후보만 있는 사용자는 빈 목록을 받는다")
    void findAllByUserIdAndDeletedFalse_onlyDeletedCandidates_returnsEmptyList() {
        // Given
        persist(USER_ID, "삭제된 식단", true);
        testEntityManager.clear();

        // When
        List<MealCandidateJpaEntity> mealCandidateJpaEntityList =
                mealCandidateJpaRepository.findAllByUserIdAndDeletedFalse(USER_ID);

        // Then
        assertThat(mealCandidateJpaEntityList).isEmpty();
    }

    @Test
    @DisplayName("후보가 없는 사용자는 빈 목록을 받는다")
    void findAllByUserIdAndDeletedFalse_userWithoutCandidates_returnsEmptyList() {
        // Given
        persist(OTHER_USER_ID, "다른 사용자 식단", false);
        testEntityManager.clear();

        // When
        List<MealCandidateJpaEntity> mealCandidateJpaEntityList =
                mealCandidateJpaRepository.findAllByUserIdAndDeletedFalse(USER_ID);

        // Then
        assertThat(mealCandidateJpaEntityList).isEmpty();
    }

    // 가정: 엔티티 필드(userId, name, deleted)와 빌더는 받지 못했다. 실제 엔티티에 맞춰 이 한 곳만 고친다.
    private MealCandidateJpaEntity persist(Long userId, String mealName, boolean deleted) {
        MealCandidateJpaEntity mealCandidateJpaEntity =
                MealCandidateJpaEntity.builder().userId(userId).name(mealName).deleted(deleted).build();
        return testEntityManager.persistAndFlush(mealCandidateJpaEntity);
    }
}
```

설계 메모:
- `deleted=true`·`deleted=false` 를 모두 저장해 본다. 엔티티 기본값이 `false` 라면 `false` 만 넣는 테스트는 `AndDeletedFalse` 조건을 빼도 통과하기 때문이다(RR-12 기본값과 다른 값 검증).
- `testEntityManager.clear()` 로 1차 캐시를 비워 실제 쿼리 결과를 본다.
- 서비스 테스트는 서비스 자체의 필터링 로직이 아니라 Fake 가 재현한 저장소 계약(삭제·타 사용자 제외)과 정렬·limit 를 본다. 삭제 필터의 실제 보장은 위 Repository 테스트가 맡는다.

## 가정과 남은 리스크

- 가정: `MealCandidate`·`MealCandidateJpaEntity` 의 빌더와 필드명, `MealRecommendationOutDto.mealName()` 접근자. 픽스처 생성은 각 클래스의 `newCandidate`·`persist` 한 곳에 모아 두었다. 실제 시그니처와 다르면 컴파일 오류가 나므로 그 두 메서드와 DTO 접근자만 맞추면 된다.
- 점수 동점일 때 정렬 순서와 `limit <= 0` 입력의 동작은 대상 코드 본문이 없어 계약을 알 수 없다. 추측으로 단언하지 않았고 테스트에서 뺐다. 서비스가 `limit` 검증 예외를 던진다면 그 분기 테스트가 비어 있다(RR-14). 본문을 주면 추가한다.
- `ddl-auto=create-drop` 은 엔티티 매핑 기준으로 스키마를 만든다. 운영에서 Flyway 등 마이그레이션 스크립트를 쓰면 스크립트와 엔티티 불일치는 이 테스트로 잡히지 않는다.
- Docker 가 없는 CI·로컬에서는 Repository 테스트가 실행되지 않는다.
