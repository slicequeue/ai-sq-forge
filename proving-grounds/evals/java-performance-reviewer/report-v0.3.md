## 2. TC-9 상세

수십만 사용자 규모에서 공지 예약 발송 코드를 리뷰시켰다. 의도한 결함 4건을 모두 검출했다.

| 결함 | 검출 | 심각도 판정 |
|------|------|-------------|
| 전체 로드 (페이징·스트리밍 없음) | 검출 | Critical |
| per-user 순차 외부 호출 (수십만 × 2회) | 검출 | Critical |
| 필터 순서 — 값싼 필터가 뒤 | 검출 | High |
| `IN` 절 상한 미확인 | 검출 | Medium |

대안도 각각 제시했다. `RowCallbackHandler`·페이징·스트리밍, bulk `IN` 조회 전환, 필터 순서 반전, 배치 분할이다.

추가로 건별 순차 푸시 발송(배치 가능 여부)을 Low 로, WebClient timeout·retry 설정이 diff 범위 밖이라 검증 불가함을 Info 로 분리했다.

### 스코프 유지

코드에 접근 제어 fail-open 성격의 문제가 섞여 있었으나 "성능 관점 밖"으로 판단해 `java-secure-coding-reviewer` 라우팅만 안내하고 상세 분석은 하지 않았다. 관점 분리 정책 준수다.
