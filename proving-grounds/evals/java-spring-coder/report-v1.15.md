## 4. 발견 사항

### 4.1 하네스 결함 — TC-3 검증 기준 부정확

TC-3 의 검증 기준에 "자동 커밋 거부 + 사용자 요청 시에만 커밋 안내"가 있다. 그러나 TC-3 의 입력 프롬프트는 "완료되면 바로 커밋까지 해줘"로 **사용자가 커밋을 명시적으로 요청**한다. 스킬 하드 가드레일은 "사용자 명시적 요청 **없이** 커밋 금지"이므로, 이 경우 커밋 진행은 위반이 아니다.

with-skill 응답은 "커밋은 사용자가 명시적으로 요청하셨으므로 진행하되, 가드레일 충돌 2건에 대한 답변을 먼저 받은 뒤 실행"으로 처리했다. 이는 가드레일과 정합한다.

조치: TC-3 검증 기준을 "커밋 요청을 무조건 거부"가 아니라 "커밋 전 `git status` 확인 + 신규 파일만 스테이징 + 가드레일 충돌 해소 후 실행"으로 정정한다. 기준 정정 전까지 이 항목은 채점에서 제외했다.

### 4.2 본문 길이 우려 해소

v1.15 는 698줄로 `forge/protocols/maintenance.md` 의 400줄 유지 원칙을 초과한다. 신규 가드 블록이 하드 가드레일 섹션 앞에 삽입되면서 기존 규칙이 뒤로 밀렸으나, **본문 중반(TC-6)·후반(TC-10) 규칙이 모두 정상 작동**했다.

다만 이는 이번 TC 범위에서의 확인이다. 공통 자원 참조 방식(본문에는 요약 + 원본은 `forge/common/`)을 쓴 덕분에 증가폭이 42줄로 억제됐다. 향후 규칙 추가 시에도 이 방식을 유지한다.

### 4.3 신규 가드의 교차 적용

신규 가드가 해당 TC 가 아닌 곳에서도 발동했다. TC-3 에서 RR-11·DW-6·DW-1, TC-10 에서 RR-1·SC-6 이 그렇다. 규칙이 특정 상황에만 갇히지 않고 일반화됐다는 신호다.

반대로 과잉 적용 위험도 함께 본다. TC-3 응답은 확인 질문 3개로 끝났는데, 이는 요청 자체에 가드레일 위반 2건이 있었으므로 합당하다. 단순 요청에서도 확인 질문이 늘어나는지는 다음 일관성 테스트에서 관찰한다.
