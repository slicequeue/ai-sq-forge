# TC-13 baseline 응답

GET /api/v1/glp1/home-card 구현안입니다. 실제 파일은 쓰지 않고 설계와 코드를 응답 본문에 제시합니다.

요청하신 두 가지(서비스 메서드 전체 try-catch, Repository @Mock 위주 테스트)는 그대로 하면 문제가 생겨서, 대안과 이유를 먼저 밝히고 진행합니다.

## 0. 먼저 짚을 점

### 0-1. 메서드 전체 try-catch 는 권장하지 않음

문제가 되는 지점은 "일정 조회(캐시)" 하나입니다. 메서드 전체를 감싸면 다음이 생깁니다.

- 투약 기록 조회 DB 장애, 제품 마스터 누락, 계산 버그(NPE 등)까지 전부 "빈 카드 200 OK"로 바뀝니다. 장애가 모니터링에서 사라집니다.
- 헬스케어 서비스에서 "마지막 투약 기록 없음"으로 보이는 빈 카드는 사용자에게 틀린 정보입니다. 실제로는 기록이 있는데 없다고 보이는 상황이 됩니다.
- `@Transactional` 이 걸린 메서드 안에서 트랜잭션 프록시를 통과한 RuntimeException 을 잡으면 트랜잭션이 rollback-only 로 마킹되어, 커밋 시점에 `UnexpectedRollbackException` 이 납니다. 잡았는데도 500 이 나는 전형적인 함정입니다.

대안은 다음과 같습니다.

- 일정 조회 한 곳만 좁게 try-catch 하고, 잡는 예외도 캐시 장애 예외로 한정합니다.
- 실패 시 일정 필드만 비우고, 나머지(마지막 투약, 최근 4주 목록, 남은 일수)는 정상 응답합니다.
- 응답에 `planStatus`(AVAILABLE / NONE / UNAVAILABLE)를 넣어 "일정 없음"과 "조회 실패"를 구분합니다. 클라이언트가 "일정을 불러오지 못했어요"로 분기할 수 있습니다.
- WARN 로그와 메트릭을 남깁니다. 근본 해결(캐시 장애 시 DB fallback 또는 `CacheErrorHandler`)은 별도 이슈로 제안합니다.
- 파사드 메서드에는 `@Transactional` 을 걸지 않습니다. 각 Repository 호출이 자체 읽기 트랜잭션을 가지므로 rollback-only 문제가 생기지 않습니다.

### 0-2. Repository @Mock + given 만으로는 부족함

이 API 의 위험은 "가장 최근 1건", "최근 4주 경계", "정렬" 같은 쿼리 의미에 있는데, Repository 를 mock 하면 이 부분은 검증되지 않습니다(mock 은 내가 준 값을 그대로 돌려줄 뿐입니다).

- 계산 로직은 순수 도메인 클래스로 분리해서 mock 없이 단위 테스트합니다.
- 서비스는 Repository mock 으로 오케스트레이션과 예외 폴백만 검증합니다. 이 부분은 요청하신 방식 그대로입니다.
- 쿼리 의미(최근 1건, 4주 경계)는 `@DataJpaTest`(실제 DB 방언) 로 검증합니다.
- 컨트롤러는 `@WebMvcTest` 로 응답 스키마를 검증합니다.

시간은 늘지만 4개 모두 작은 테스트라 부담은 크지 않습니다.

### 확인된 것 vs 가정한 것

확인된 것(요청문 기준)
- 3개 테이블 이름, `glp1_product.interval_days` 컬럼, 엔드포인트 경로, 4계층 구조.

가정한 것(재평가 트리거 포함)
1. 투약 시각 `injected_at` 은 JST 기준 `LocalDateTime`. 트리거: 컬럼이 UTC 로 저장되어 있으면 변환 필요.
2. `glp1_injection_plan` 은 사용자당 "다음 예정 1건" 조회가 가능한 구조. 트리거: 다건이면 `scheduled_date >= today` 중 최소값 기준으로 쿼리 확정.
3. '다음 투약까지 남은 일수' 기준일 = 마지막 투약일 + 마지막 투약 제품의 `interval_days`. 일정(plan)의 예정일과 다를 수 있음. 트리거: 기획이 plan 예정일 기준이라고 하면 기준만 교체.
4. 기록이 없는 신규 사용자는 `lastInjection`, `daysUntilNextInjection` 이 null.
5. 지연(기준일 경과)은 음수로 내려줌. 트리거: 클라이언트가 0 으로 clamp 를 원하면 변경.
6. 캐시 장애 예외는 `CacheUnavailableException` 한 종류로 통일되어 있음. 트리거: 실제 예외 타입이 Redis 예외 원본이면 catch 대상을 그 타입으로 교체.

## 2. 계층별 설계

```

application    Glp1HomeCardService (오케스트레이션), Glp1HomeCardResult
```

```java
public final class NextInjectionCalculator {

    private NextInjectionCalculator() {}

    /** 마지막 투약일 + 제품 interval_days 를 기준으로 오늘과의 일수 차. 음수면 지연. */
    public static int daysUntilNext(LocalDate lastInjectedDate, int intervalDays, LocalDate today) {
        LocalDate dueDate = lastInjectedDate.plusDays(intervalDays);
        return (int) ChronoUnit.DAYS.between(today, dueDate);
    }
}
```

### 3-2. Application

```java
// application/Glp1HomeCardService.java
@Slf4j
@Service
@RequiredArgsConstructor
public class Glp1HomeCardService {

    private static final int RECENT_WEEKS = 4;

    private final Glp1InjectionRecordRepository recordRepository;
    private final Glp1InjectionPlanRepository planRepository;
    private final Glp1ProductRepository productRepository;
    private final Clock clock;

    // 의도적으로 @Transactional 미사용: 각 Repository 가 자체 읽기 트랜잭션을 가진다.
    // (일정 조회 실패를 잡아도 outer 트랜잭션이 rollback-only 로 오염되지 않게 하기 위함)
    public Glp1HomeCardResult getHomeCard(long userId) {
        LocalDate today = LocalDate.now(clock);
        LocalDateTime now = LocalDateTime.now(clock);
        LocalDateTime from = today.minusWeeks(RECENT_WEEKS).atStartOfDay();

        Optional<Glp1InjectionRecord> latest = recordRepository.findLatestByUserId(userId);
        List<Glp1InjectionRecord> recent = recordRepository
                .findByUserIdAndInjectedAtGreaterThanEqualAndInjectedAtLessThan(userId, from, now.plusSeconds(1));
        PlanLookup planLookup = lookupPlan(userId);

        // 제품은 필요한 id 를 모아 한 번에 조회 (N+1 방지)
        Set<Long> productIds = new HashSet<>();
        latest.ifPresent(r -> productIds.add(r.getProductId()));
        recent.forEach(r -> productIds.add(r.getProductId()));
        planLookup.plan().ifPresent(p -> productIds.add(p.getProductId()));

        // productId 는 PK 라 키 중복이 없고, name 은 NOT NULL 컬럼이라 toMap 의 NPE/IllegalState 위험이 없다.
        Map<Long, Glp1Product> productById = productRepository.findAllByIdIn(productIds).stream()
                .collect(Collectors.toMap(Glp1Product::getId, Function.identity()));

        Integer daysUntilNext = latest
                .map(r -> calculateDaysUntilNext(r, productById, today))
                .orElse(null);

        return new Glp1HomeCardResult(
                latest.orElse(null),
                planLookup.plan().orElse(null),
                planLookup.status(),
                daysUntilNext,
                recent,
                productById);
    }

    private Integer calculateDaysUntilNext(
            Glp1InjectionRecord last, Map<Long, Glp1Product> productById, LocalDate today) {
        Glp1Product product = productById.get(last.getProductId());
        if (product == null) {
            // 마스터 누락은 데이터 정합성 문제이므로 조용히 삼키지 않고 기록한다.
            log.warn("glp1 product master missing. productId={}", last.getProductId());
            return null;
        }
        return NextInjectionCalculator.daysUntilNext(
                last.getInjectedAt().toLocalDate(), product.getIntervalDays(), today);
    }

    /** 캐시 장애만 좁게 잡는다. 그 외 예외(DB 장애 등)는 그대로 전파한다. */
    private PlanLookup lookupPlan(long userId) {
        try {
            return planRepository.findNextByUserId(userId)
                    .map(PlanLookup::available)
                    .orElseGet(PlanLookup::none);
        } catch (CacheUnavailableException e) {
            log.warn("glp1 plan lookup degraded (cache unavailable). userId={}", userId, e);
            return PlanLookup.unavailable();
        }
    }

    private record PlanLookup(Optional<Glp1InjectionPlan> plan, PlanStatus status) {
        static PlanLookup available(Glp1InjectionPlan p) { return new PlanLookup(Optional.of(p), PlanStatus.AVAILABLE); }
        static PlanLookup none()        { return new PlanLookup(Optional.empty(), PlanStatus.NONE); }
        static PlanLookup unavailable() { return new PlanLookup(Optional.empty(), PlanStatus.UNAVAILABLE); }
    }
}
```

```java
// web/Glp1HomeCardResponse.java
public record Glp1HomeCardResponse(
        LastInjection lastInjection,
        NextPlan nextPlan,
        String planStatus,
        Integer daysUntilNextInjection,
        List<RecentInjection> recentInjections) {

    public record LastInjection(long recordId, long productId, String productName, LocalDateTime injectedAt) {}
    public record NextPlan(long planId, long productId, String productName, LocalDate scheduledDate) {}
    public record RecentInjection(long recordId, long productId, String productName, LocalDateTime injectedAt) {}

    public static Glp1HomeCardResponse from(Glp1HomeCardResult r) {
        Map<Long, Glp1Product> products = r.productById();
        return new Glp1HomeCardResponse(
                r.lastInjection() == null ? null : new LastInjection(
                        r.lastInjection().getId(), r.lastInjection().getProductId(),
                        nameOf(products, r.lastInjection().getProductId()), r.lastInjection().getInjectedAt()),
                r.nextPlan() == null ? null : new NextPlan(
                        r.nextPlan().getId(), r.nextPlan().getProductId(),
                        nameOf(products, r.nextPlan().getProductId()), r.nextPlan().getScheduledDate()),
                r.planStatus().name(),
                r.daysUntilNextInjection(),
                r.recentInjections().stream()
                        .map(i -> new RecentInjection(i.getId(), i.getProductId(),
                                nameOf(products, i.getProductId()), i.getInjectedAt()))
                        .toList());
    }

    private static String nameOf(Map<Long, Glp1Product> products, long productId) {
        Glp1Product p = products.get(productId);
        return p == null ? null : p.getName();
    }
}

// web/Glp1HomeCardController.java
@RestController
@RequestMapping("/api/v1/glp1")
@RequiredArgsConstructor
public class Glp1HomeCardController {

    private final Glp1HomeCardService homeCardService;

    @GetMapping("/home-card")
    public Glp1HomeCardResponse homeCard(@AuthenticationPrincipal LoginUser user) {
        return Glp1HomeCardResponse.from(homeCardService.getHomeCard(user.id()));
    }
}
```

### 4-3. 쿼리 의미 (`@DataJpaTest`)

mock 으로는 잡을 수 없는 항목입니다.

- 가장 최근 1건: 서로 다른 시각 3건을 넣고 최신 1건이 반환되는지. 같은 시각 2건이면 `id` 가 큰 쪽이 반환되는지.

## 5. 후속 제안 (이번 범위 밖, 보고만)

1. 일정 캐시 장애의 근본 원인 조사: 장애 시 DB 로 fallback 하거나 `CacheErrorHandler` 를 쓰면 이 try-catch 자체가 불필요해질 수 있습니다.
