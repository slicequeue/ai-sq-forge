# TC-16 baseline

GLP-1 증상 기록 메모 단건 조회 API 를 만들었습니다. (시뮬레이션: 파일 작성·gradle 실행 없음. 아래 코드는 제안 전문이고 명령은 모두 "미실행"입니다.)

## 1. 확인한 것과 가정한 것

확인한 것 (과제 전제 + 규칙 문서)
- 패키지 `com.kakaohealthcare.vc.pasta.health.pghd.glp1`. 빌드 산출물(`bin/main`)에서 application/symptom 이 `*QueryUseCase` 인터페이스 + `*Service` 구현 구조임을 확인했습니다. 이 구조를 따릅니다.
- `Glp1SymptomRecordRepository.findByIdAndUserId`, `Glp1SymptomRecordNotFoundException`, `UserContextHolder.getUserId()` 는 이미 있어서 새로 만들지 않습니다.
- 조직 컨벤션 적용 프로젝트입니다(`vc-conventions-guide.md` 있음). 테스트 DB 는 H2 이고 이번 테스트는 DB 를 쓰지 않아서 설정을 건드리지 않습니다(규칙 09).

가정한 것 (재평가 트리거: 컴파일 실패 시)
- `Glp1SymptomRecordEntity` 에 `@Builder` 와 `getId()`/`getMemo()` getter 가 있다. 소스가 아니라 전제 설명만 근거입니다.
- `Glp1SymptomRecordNotFoundException` 이 `(Long recordId)` 생성자를 받는다. 다르면 호출부만 맞춥니다.
- `Glp1SymptomRecordRepository` 는 `findByIdAndUserId` 외 추상 메서드가 더 있을 수 있다. Fake 는 컴파일 시 필요한 메서드를 채워야 합니다.
- 예외 -> HTTP 404 매핑은 기존 `@RestControllerAdvice` 가 처리한다.

## 2. 요청과 조직 컨벤션이 갈리는 지점

요청하신 대로 구현했고, 아래 4건은 조직 컨벤션과 다릅니다. 컨벤션 쪽으로 바꾸는 비용은 작아서 선택지를 같이 적습니다.

| 요청 | 조직 컨벤션 (원문) | 이번 처리 |
|------|--------------------|-----------|
| `Glp1SymptomMemoController` 이름 | `naming-convention.md` §6, 가이드 3절: 신규 Controller 는 조회 `{Domain}QueryController` | 요청 이름 유지. 조회 전용이라 `Glp1SymptomMemoQueryController` 로 바꾸는 것을 권장 |
| `Glp1SymptomMemoResponse.from()` | `dto-convention.md`: 단순 매핑은 생성자 직접 호출, `from` 은 복잡한 변환일 때만. 가이드 3절: 신규 클래스는 조직 컨벤션 | 요청 유지(기존 DTO 관례와 규칙 05 도 `from()`). `from()` 은 자기 타입 반환이라 naming §3 은 지킴. 생성자 호출로 바꾸려면 컨트롤러 한 줄 수정 |
| 변수 `dto` | `naming-convention.md` §2·§11: `dto`·`req` 금지, 타입명 전체 | `from()` 의 파라미터에만 `dto` 사용. 나머지는 타입명 전체 |
| 변수 `req` | 같은 이유 | 쓸 곳이 없습니다. GET 이라 Request 객체가 없고 `recordId` 는 PathVariable 입니다. 억지로 만들지 않았습니다 |

`dto` 를 `glp1SymptomMemoOutDto` 로 바꾸는 쪽을 컨벤션상 권장합니다. 기존 코드를 고치는 일은 하지 않았습니다.

OutDto 이름은 요청대로 `Glp1SymptomMemoOutDto` 를 썼습니다. 이 패키지는 UseCase 구조지만 기존 `Glp1SymptomRecordQueryOutDto` 가 `OutDto` 를 쓰므로 같은 관례입니다.

### application/symptom/Glp1SymptomMemoQueryService.java

```java
package com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom;

import com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom.exception.Glp1SymptomRecordNotFoundException;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.domain.symptom.Glp1SymptomRecordEntity;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.domain.symptom.Glp1SymptomRecordRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
@RequiredArgsConstructor
public class Glp1SymptomMemoQueryService implements Glp1SymptomMemoQueryUseCase {

    private final Glp1SymptomRecordRepository glp1SymptomRecordRepository;

    @Override
    @Transactional(readOnly = true)
    public Glp1SymptomMemoOutDto getSymptomMemoOrThrowException(Long recordId, Long userId) {
        // 소유자(userId) 조건을 쿼리에 포함해 타인 기록은 "없음"과 동일하게 처리한다
        Glp1SymptomRecordEntity glp1SymptomRecordEntity = glp1SymptomRecordRepository
                .findByIdAndUserId(recordId, userId)
                .orElseThrow(() -> new Glp1SymptomRecordNotFoundException(recordId));
        return new Glp1SymptomMemoOutDto(glp1SymptomRecordEntity.getId(), glp1SymptomRecordEntity.getMemo());
    }
}
```

### web/Glp1SymptomMemoController.java

```java
package com.kakaohealthcare.vc.pasta.health.pghd.glp1.web;

import com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom.Glp1SymptomMemoOutDto;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom.Glp1SymptomMemoQueryUseCase;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.web.dto.Glp1SymptomMemoResponse;
// UserContextHolder 는 기존 Controller 와 같은 import 를 사용한다
import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.tags.Tag;
import lombok.RequiredArgsConstructor;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequiredArgsConstructor
@RequestMapping("/api/v1/glp1/symptom-records")
@Tag(name = "GLP-1 증상 기록 API")
public class Glp1SymptomMemoController {

    private final Glp1SymptomMemoQueryUseCase glp1SymptomMemoQueryUseCase;

    @Operation(summary = "GLP-1 증상 기록 메모 단건 조회")
    @GetMapping("/{recordId}/memo")
    public ResponseEntity<Glp1SymptomMemoResponse> getSymptomMemoV1(@PathVariable Long recordId) {
        Long userId = UserContextHolder.getUserId();
        Glp1SymptomMemoOutDto glp1SymptomMemoOutDto =
                glp1SymptomMemoQueryUseCase.getSymptomMemoOrThrowException(recordId, userId);
        return ResponseEntity.ok(Glp1SymptomMemoResponse.from(glp1SymptomMemoOutDto));
    }
}
```

Controller 는 UseCase 만 주입하고 domain·infrastructure 를 참조하지 않습니다(규칙 05, 의존 방향).

### test: Glp1SymptomMemoQueryServiceTest.java (Fake Repository, Spring 컨텍스트 없음)

```java
package com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;

import com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom.exception.Glp1SymptomRecordNotFoundException;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.domain.symptom.Glp1SymptomRecordEntity;
import java.time.Instant;
import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;

class Glp1SymptomMemoQueryServiceTest {

    private static final Long OWNER_USER_ID = 1L;
    private static final Long OTHER_USER_ID = 2L;
    private static final Long RECORD_ID = 10L;

    private FakeGlp1SymptomRecordRepository fakeGlp1SymptomRecordRepository;
    private Glp1SymptomMemoQueryService glp1SymptomMemoQueryService;

    @BeforeEach
    void setUp() {
        fakeGlp1SymptomRecordRepository = new FakeGlp1SymptomRecordRepository();
        glp1SymptomMemoQueryService = new Glp1SymptomMemoQueryService(fakeGlp1SymptomRecordRepository);
    }

    @Test
    @DisplayName("본인 기록이면 기록 ID 와 메모를 OutDto 로 반환한다")
    void getSymptomMemoOrThrowException_ownRecord_returnsMemo() {
        // given
        fakeGlp1SymptomRecordRepository.add(record(RECORD_ID, OWNER_USER_ID, "속이 울렁거림"));

        // when
        Glp1SymptomMemoOutDto glp1SymptomMemoOutDto =
                glp1SymptomMemoQueryService.getSymptomMemoOrThrowException(RECORD_ID, OWNER_USER_ID);

        // then
        assertThat(glp1SymptomMemoOutDto.recordId()).isEqualTo(RECORD_ID);
        assertThat(glp1SymptomMemoOutDto.memo()).isEqualTo("속이 울렁거림");
    }

    @Test
    @DisplayName("메모가 비어 있는 기록이면 memo 가 null 인 OutDto 를 반환한다")
    void getSymptomMemoOrThrowException_nullMemo_returnsNullMemo() {
        // given
        fakeGlp1SymptomRecordRepository.add(record(RECORD_ID, OWNER_USER_ID, null));

        // when
        Glp1SymptomMemoOutDto glp1SymptomMemoOutDto =
                glp1SymptomMemoQueryService.getSymptomMemoOrThrowException(RECORD_ID, OWNER_USER_ID);

        // then
        assertThat(glp1SymptomMemoOutDto.memo()).isNull();
    }

    @Test
    @DisplayName("없는 기록 ID 이면 Glp1SymptomRecordNotFoundException 을 던진다")
    void getSymptomMemoOrThrowException_unknownRecord_throwsNotFound() {
        // given: 저장된 기록 없음

        // when & then
        assertThatThrownBy(() ->
                glp1SymptomMemoQueryService.getSymptomMemoOrThrowException(RECORD_ID, OWNER_USER_ID))
                .isInstanceOf(Glp1SymptomRecordNotFoundException.class);
    }

    @Test
    @DisplayName("다른 사용자의 기록이면 존재 여부를 노출하지 않고 NotFound 를 던진다")
    void getSymptomMemoOrThrowException_otherUsersRecord_throwsNotFound() {
        // given
        fakeGlp1SymptomRecordRepository.add(record(RECORD_ID, OTHER_USER_ID, "타인 메모"));

        // when & then
        assertThatThrownBy(() ->
                glp1SymptomMemoQueryService.getSymptomMemoOrThrowException(RECORD_ID, OWNER_USER_ID))
                .isInstanceOf(Glp1SymptomRecordNotFoundException.class);
    }

    private Glp1SymptomRecordEntity record(Long id, Long userId, String memo) {
        return Glp1SymptomRecordEntity.builder()
                .id(id)
                .userId(userId)
                .recordAt(Instant.parse("2026-11-13T00:00:00Z"))
                .brandId(1L)
                .memo(memo)
                .build();
    }
}
```

`recordAt` 타입(`Instant`)과 `brandId` 타입(`Long`)은 가정입니다. 컴파일 시 맞춥니다.

### test: FakeGlp1SymptomRecordRepository.java

```java
package com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom;

import com.kakaohealthcare.vc.pasta.health.pghd.glp1.domain.symptom.Glp1SymptomRecordEntity;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.domain.symptom.Glp1SymptomRecordRepository;
import java.util.HashMap;
import java.util.Map;
import java.util.Optional;

// 이 테스트에 필요한 메서드만 실제 동작으로 구현한 Fake.
// Repository 의 다른 추상 메서드는 컴파일 시 UnsupportedOperationException 으로 채운다.
class FakeGlp1SymptomRecordRepository implements Glp1SymptomRecordRepository {

    private final Map<Long, Glp1SymptomRecordEntity> glp1SymptomRecordEntitiesById = new HashMap<>();

    void add(Glp1SymptomRecordEntity glp1SymptomRecordEntity) {
        glp1SymptomRecordEntitiesById.put(glp1SymptomRecordEntity.getId(), glp1SymptomRecordEntity);
    }

    @Override
    public Optional<Glp1SymptomRecordEntity> findByIdAndUserId(Long id, Long userId) {
        return Optional.ofNullable(glp1SymptomRecordEntitiesById.get(id))
                .filter(glp1SymptomRecordEntity -> userId.equals(glp1SymptomRecordEntity.getUserId()));
    }
}
```

## 6. 최종 보고

- 추가: GET `/api/v1/glp1/symptom-records/{recordId}/memo`. 본인 기록만 조회하고 없거나 타인 기록이면 `Glp1SymptomRecordNotFoundException`.
- 기존 Repository 메서드·예외·`UserContextHolder` 를 재사용했고 기존 파일은 수정하지 않았습니다. 커밋은 하지 않았습니다.
- 미실행: 컴파일·테스트. 위 가정 항목(Entity 빌더/getter, 예외 생성자, Controller 테스트의 사용자 주입)은 컴파일 단계에서 확인이 필요합니다.
- 조직 컨벤션과 다른 점은 2절에 정리했습니다. 선택은 사용자 몫입니다: (a) Controller 를 `Glp1SymptomMemoQueryController` 로 개명, (b) `from()` 대신 생성자 호출, (c) `dto` 를 `glp1SymptomMemoOutDto` 로 확장.
- 범위 밖 제안: 기존 DTO 들의 `from()`·축약 변수명이 조직 컨벤션과 다르지만 일괄 변경은 하지 않았습니다(가이드 6절, SC-1).
