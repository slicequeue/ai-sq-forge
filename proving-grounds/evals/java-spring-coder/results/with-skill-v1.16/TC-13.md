# TC-13 with-skill 응답 (v1.16)

대상: pasta-japan-server (Java 21, Spring Boot 4-Tier). 실제 저장소가 없으므로 아래의 탐색·테스트·lint 결과는 전부 "가정 결과"이며, 가정은 9절에 재평가 트리거와 함께 모아 두었다. 코드는 파일에 쓰지 않고 본문에만 제시한다. 커밋하지 않는다.

## 0. 요약

- 모드 B(TDD 문서 없음). `GET /api/v1/glp1/home-card` 를 4-Tier 로 구현한다. 신규 엔드포인트는 요청에 명시돼 있으므로 승인된 것으로 본다. 테이블·컬럼·마이그레이션은 만들지 않는다.
- 요청 4항목은 모두 넣는다. 4번은 요청대로 `Collectors.toMap` 으로 productId -> productName 을 만들되, null 값 한 건이 전체를 깨뜨리지 않게 앞단에서 거른다.
- 요청 중 두 가지는 그대로 따르지 않는다. 사유와 대안은 3절.
  1. 서비스 메서드 전체를 try-catch 로 감싸 빈 카드를 내리는 방식
  2. Repository 를 `@Mock` + `given` 으로 두는 테스트
- 계산 기준처럼 요청만으로 확정되지 않는 부분은 기본값을 정해 구현하고 4절에서 확인을 요청한다.

## 3. 요청 중 그대로 따르지 않는 부분

### 3-1. 메서드 전체 try-catch 로 빈 카드

적용 규칙: RR-13(실패 격리), RR-1(로그 없이 삼키지 않기), SC-5(요청 항목은 임의로 빼지 않고 사유 제시).

- 전체를 감싸면 일정 캐시가 터질 때 마지막 기록과 4주 목록까지 비어, 투약 기록이 있는 사용자에게 "기록 없음" 이라는 틀린 상태를 내려 준다. 예외보다 나쁘다.
- 서비스가 `@Transactional` 이고 일정 조회가 같은 트랜잭션에 참여하면, 호출부에서 catch 해도 rollback-only 가 이미 표시돼 `UnexpectedRollbackException` 으로 전체가 실패한다.
- 대안(구현에 반영)
  1. try-catch 는 일정 조회 한 곳에만 둔다. 잡은 예외는 스택트레이스와 함께 WARN 으로 남긴다(삼키지 않는다).
  2. 일정 조회는 별도 빈에서 `REQUIRES_NEW` + `readOnly` 로 격리한다. 카드 서비스에는 `@Transactional` 을 두지 않는다. 독립된 단건 조회 4개라 스냅샷 일관성이 필요 없고, 나중에 누군가 `@Transactional` 을 붙여도 격리가 유지된다.
  3. `catch (RuntimeException e)` 로 잡는다. 캐시 예외의 실제 타입을 아직 못 봤기 때문이다(1절 16번). 타입이 확인되면 `DataAccessException` 등으로 좁힌다(RR-5 상속 확인 후). 프로그래밍 오류(NPE 등)도 함께 가려질 수 있으나 WARN 스택이 남으므로 은폐되지는 않는다.
- 이 로직은 접근 제어·과금 판정이 아니므로 RR-1 의 열림/닫힘 정책 대상은 아니다.

### 3-2. Repository `@Mock` + `given`

적용 규칙: RR-12, RR-F14, 규칙 08. 상태 저장소를 Mock 으로 정답 주입하면 조회 조건(4주 경계, 미래 기록 제외)이 틀려도 통과한다. Fake 에 `save()` 한 뒤 조회 조건이 적용되게 한다. `review-lint.py` 도 `*Repository`·`*QueryService` 의 `@Mock` 을 위반으로 잡는다. 속도는 Spring 컨텍스트 없는 순수 JUnit + Fake 라 Mock 과 차이가 거의 없다. 일정 실패 시나리오는 Fake 에 `willThrow` 를 둬서 만든다.

```java
// import java.time.LocalDate; import java.time.temporal.ChronoUnit; import java.util.OptionalLong;

// 마스터 한 행의 잘못된 값이 그 제품 사용자 전원의 500 이 되지 않도록 생성자에서 거부하지 않고 빈 값으로 돌려줍니다.
public OptionalLong calculateDaysUntilNextInjection(LocalDate lastInjectedDate, LocalDate currentDate) {
    if (intervalDays <= 0) {
        return OptionalLong.empty();
    }
    LocalDate nextInjectionDate = lastInjectedDate.plusDays(intervalDays);
    return OptionalLong.of(ChronoUnit.DAYS.between(currentDate, nextInjectionDate));
}
```

```java
// pghd/glp1/infrastructure/Glp1InjectionRecordRepositoryImpl.java  (기존 필드명 jpaRepository 를 따름)
@Override
public Optional<Glp1InjectionRecordEntity> findLatestByUserIdAndInjectedAtLessThanEqual(
        long userId, Instant currentAt) {
    return jpaRepository
            .findFirstByUserIdAndInjectedAtLessThanEqualOrderByInjectedAtDescIdDesc(userId, currentAt)
            .map(Glp1InjectionRecordJpaEntity::toEntity);
}

@Override
public List<Glp1InjectionRecordEntity> findAllByUserIdAndInjectedAtBetweenOrderByInjectedAtDescIdDesc(
        long userId, Instant fromAt, Instant toAt) {
    return jpaRepository
            .findAllByUserIdAndInjectedAtBetweenOrderByInjectedAtDescIdDesc(userId, fromAt, toAt)
            .stream()
            .map(Glp1InjectionRecordJpaEntity::toEntity)
            .toList();
}
```

```java
// pghd/glp1/application/Glp1HomeCardQueryService.java
// import java.time.Instant; import java.time.LocalDate; import java.time.ZoneId;
// import java.util.HashSet; import java.util.List; import java.util.Map; import java.util.Objects;
// import java.util.OptionalLong; import java.util.Set; import java.util.stream.Collectors;
// import lombok.RequiredArgsConstructor; import lombok.extern.log4j.Log4j2;
// import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
@Log4j2
public class Glp1HomeCardQueryService {

    private static final int RECENT_WEEKS = 4;

    private final Glp1InjectionRecordRepository glp1InjectionRecordRepository;
    private final Glp1ProductRepository glp1ProductRepository;
    private final Glp1HomeCardPlanLookupService glp1HomeCardPlanLookupService;

    // 독립된 단건 조회 4개라 스냅샷 일관성이 필요 없고, 일정 조회 실패가 이 호출의 트랜잭션을 오염시키지 않도록 트랜잭션을 두지 않습니다.
    public Glp1HomeCardOutDto getHomeCard(Glp1HomeCardInDto glp1HomeCardInDto) {
        long userId = glp1HomeCardInDto.userId();
        ZoneId zoneId = glp1HomeCardInDto.zoneId();
        Instant currentAt = glp1HomeCardInDto.currentAt();
        LocalDate currentDate = currentAt.atZone(zoneId).toLocalDate();
        Instant recentFromAt = currentDate.minusWeeks(RECENT_WEEKS).atStartOfDay(zoneId).toInstant();

        Glp1InjectionRecordEntity lastRecordEntity = glp1InjectionRecordRepository
                .findLatestByUserIdAndInjectedAtLessThanEqual(userId, currentAt)
                .orElse(null);
        List<Glp1InjectionRecordEntity> recentRecordEntityList = glp1InjectionRecordRepository
                .findAllByUserIdAndInjectedAtBetweenOrderByInjectedAtDescIdDesc(userId, recentFromAt, currentAt);
        Glp1InjectionPlanEntity nextPlanEntity = getNextPlanEntityOrNull(userId, currentAt);

        List<Glp1ProductEntity> productEntityList = glp1ProductRepository.findAllByIds(
                mapRecordsToProductIdSet(lastRecordEntity, recentRecordEntityList));
        Map<Long, String> productNameMap = productEntityList.stream()
                .filter(productEntity -> productEntity.getName() != null)
                .collect(Collectors.toMap(Glp1ProductEntity::getId, Glp1ProductEntity::getName));

        Long daysUntilNextInjection = calculateDaysUntilNextInjectionOrNull(
                lastRecordEntity, productEntityList, zoneId, currentDate);

        return Glp1HomeCardOutDto.of(
                lastRecordEntity == null ? null : toRecordOutDto(lastRecordEntity, productNameMap),
                nextPlanEntity == null ? null : Glp1HomeCardPlanOutDto.from(nextPlanEntity),
                daysUntilNextInjection,
                recentRecordEntityList.stream()
                        .map(recordEntity -> toRecordOutDto(recordEntity, productNameMap))
                        .toList());
    }

    private Glp1InjectionPlanEntity getNextPlanEntityOrNull(long userId, Instant currentAt) {
        try {
            return glp1HomeCardPlanLookupService.getNextPlanOrElseNull(userId, currentAt);
        } catch (RuntimeException e) {
            log.warn("[Glp1HomeCardQueryService.getNextPlanEntityOrNull] 다음 투약 일정 조회에 실패해 일정 없이 카드를 내립니다", e);
            return null;
        }
    }

    private Set<Long> mapRecordsToProductIdSet(
            Glp1InjectionRecordEntity lastRecordEntity, List<Glp1InjectionRecordEntity> recentRecordEntityList) {
        Set<Long> productIdSet = recentRecordEntityList.stream()
                .map(Glp1InjectionRecordEntity::getProductId)
                .collect(Collectors.toCollection(HashSet::new));
        if (lastRecordEntity != null) {
            productIdSet.add(lastRecordEntity.getProductId());
        }
        return productIdSet;
    }

    private Long calculateDaysUntilNextInjectionOrNull(
            Glp1InjectionRecordEntity lastRecordEntity,
            List<Glp1ProductEntity> productEntityList,
            ZoneId zoneId,
            LocalDate currentDate) {
        if (lastRecordEntity == null) {
            return null;
        }
        Glp1ProductEntity lastProductEntity = productEntityList.stream()
                .filter(productEntity -> Objects.equals(productEntity.getId(), lastRecordEntity.getProductId()))
                .findFirst()
                .orElse(null);
        if (lastProductEntity == null) {
            log.warn("[Glp1HomeCardQueryService.calculateDaysUntilNextInjectionOrNull] 제품 마스터에 없어 남은 일수를 계산하지 못했습니다: productId={}",
                    lastRecordEntity.getProductId());
            return null;
        }
        LocalDate lastInjectedDate = lastRecordEntity.getInjectedAt().atZone(zoneId).toLocalDate();
        OptionalLong daysUntilNextInjectionOptional =
                lastProductEntity.calculateDaysUntilNextInjection(lastInjectedDate, currentDate);
        if (daysUntilNextInjectionOptional.isEmpty()) {
            log.warn("[Glp1HomeCardQueryService.calculateDaysUntilNextInjectionOrNull] 제품 투약 간격이 유효하지 않아 남은 일수를 계산하지 못했습니다: productId={}",
                    lastProductEntity.getId());
            return null;
        }
        return daysUntilNextInjectionOptional.getAsLong();
    }

    private Glp1HomeCardRecordOutDto toRecordOutDto(
            Glp1InjectionRecordEntity recordEntity, Map<Long, String> productNameMap) {
        return Glp1HomeCardRecordOutDto.from(recordEntity, productNameMap.get(recordEntity.getProductId()));
    }
}
```

`Collectors.toMap` 를 쓴 이유와 안전 조건(`review-lint.py` "확인" 항목에 남길 사유): 키는 제품 PK 라 중복이 없고, 값은 `filter` 로 null 을 먼저 제외하므로 `toMap` 이 던지는 두 경우(중복 키, null 값)가 모두 막혀 있다. 제품명이 없거나 마스터에 없는 기록은 `productNameMap.get` 이 null 을 돌려줘 `productName: null` 로 내려간다. 로그에는 userId 를 넣지 않고 `productId` 만 넣는다.

### 7-6. 실제 프록시 트랜잭션 테스트 (rollback-only 전파 방지)

격리가 정말 동작하는지는 Fake 로 증명되지 않는다. 실제 프록시와 상위 트랜잭션이 필요하다.

```java
@SpringBootTest
@ActiveProfiles("test")
class Glp1HomeCardQueryServiceTransactionTest {

    private static final long USER_ID = 42L;

    @TestConfiguration
    static class FailingPlanConfiguration {
        @Bean
        @Primary
        Glp1InjectionPlanRepository failingGlp1InjectionPlanRepository() {
            FakeGlp1InjectionPlanRepository fakeGlp1InjectionPlanRepository = new FakeGlp1InjectionPlanRepository();
            fakeGlp1InjectionPlanRepository.willThrow(new DataAccessResourceFailureException("cache down"));
            return fakeGlp1InjectionPlanRepository;
        }
    }

    private Glp1HomeCardQueryService glp1HomeCardQueryService;
    private TransactionTemplate transactionTemplate;

    @BeforeEach
    void setUp(@Autowired Glp1HomeCardQueryService glp1HomeCardQueryService,
               @Autowired PlatformTransactionManager platformTransactionManager) {
        this.glp1HomeCardQueryService = glp1HomeCardQueryService;
        this.transactionTemplate = new TransactionTemplate(platformTransactionManager);
        // 상위 트랜잭션을 만들기 위한 의도적 기본값(REQUIRED)입니다.
        this.transactionTemplate.setPropagationBehavior(TransactionDefinition.PROPAGATION_REQUIRED);
        // 제품·기록 시드는 실제 JpaRepository 로 커밋하고 @AfterEach 에서 삭제합니다.
    }

    @Test
    @DisplayName("상위 트랜잭션 안에서 일정 조회가 실패해도 UnexpectedRollbackException 없이 카드가 내려간다")
    void getHomeCard_planLookupFailsInsideOuterTransaction_doesNotMarkOuterRollbackOnly() {
        // Given

        // When
        Glp1HomeCardOutDto glp1HomeCardOutDto = transactionTemplate.execute(
                status -> glp1HomeCardQueryService.getHomeCard(glp1HomeCardInDto));

        // Then
        assertThat(glp1HomeCardOutDto.nextPlan()).isNull();
        assertThat(glp1HomeCardOutDto.lastRecord()).isNotNull();
    }
```

## 9. 확인된 것 vs 가정한 것

이번 시뮬레이션에서 "확인된 것"은 사용자 요청 본문과 스킬·공통 규칙 문서뿐이다. 저장소 상태는 전부 가정이다.

| 가정 | 틀렸을 때 바뀌는 것 (재평가 트리거) |
|------|--------------------------------------|
| 엔티티·필드 이름(`getName`, `getInjectedAt`, `getScheduledAt`, `intervalDays` 가 int 등) | 실제 getter 와 타입에 맞춰 코드·Fixture 수정 |

| 캐시 예외의 실제 타입 | 확인되면 `catch (RuntimeException)` 을 구체 타입으로 좁힌다 |

| Clock 빈 없음 | 있으면 컨트롤러의 `Instant.now()` 대신 Clock 사용 방식을 따른다 |

- 해당 없음: 13(admin), 14~16(OAuth·SecurityContext·외부 API yml), 21(빈 이름 상수), 23~27, 28(mutable 필드 없음), 29~31, 32(`@Entity` 신설 없음), 33(기존 패키지), 34(정책성 캐시 아님, 폴백은 10절로 보고), 35(PII 로그 없음), 36~41(쓰기·캐시·아웃박스 없음).
- 스코프: 요청한 4항목을 모두 포함했고 빼지 않았다. 요청 방식 2건의 변경 사유는 3절에 사전 제시(SC-5). 범위 밖 발견은 10절에 보고만(SC-1).
- `review-lint.py`: 위반 0건 가정, 확인 1건 사유 기재(RR-L).

## 13. 완료 보고 (DW-7)

이 응답은 시뮬레이션이다. 파일을 쓰거나 테스트·lint 를 실제로 실행하지 않았으므로 "반영 완료" 로 단정하지 않는다. 실제 저장소에서는 구현 후 다음으로 결과물을 확인하고, 확인하지 못한 항목은 "반영을 시도했고 확인이 필요하다" 로 보고한다.

```bash
git status --short
git diff --stat
```

커밋하지 않았다. 4절 확인 사항과 10절 질문에 대한 답을 받으면 반영 후 같은 절차로 다시 확인한다.
