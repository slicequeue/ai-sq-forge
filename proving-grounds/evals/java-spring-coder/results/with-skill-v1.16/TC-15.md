## 0. 먼저 알려야 할 것 — 요청 3건 중 2건은 그대로 따르지 않았다

| 요청 | 처리 | 이유 요약 |
|------|------|-----------|
| 배치 구현 + reservationId 를 `glp1_push_reservation` 에 저장 | **구현함** | - |

### 작성 전 질문 5개

1. **한 건이 실패하면 사용자는 무엇을 보는가?** 푸시 알림이 안 간다. 다른 사용자의 예약까지 롤백되면 그날 알림이 전원 누락된다. 한 건 때문에 전체가 깨지면 안 된다. 그래서 건 단위로 격리한다.
2. **외부 호출이 성공한 뒤 저장이 실패하면?** 푸시 서버에 예약이 남고 ID 를 잃는다. 그래서 저장 실패 시 `cancel` 로 보상한다. 보상도 실패하면 ERROR 로 reservationId 를 남기고 집계한다.
3. **마스터 데이터가 null·누락이면?** 외부가 null 이나 빈 reservationId 를 돌려주면 그 건만 실패로 집계하고 저장하지 않는다. 취소할 대상이 없다.
4. **기존 경로의 동작이 바뀌는가?** 신규 배치라 바뀌지 않는다. PR 본문에 "기존 동작 변경 없음"을 적는다.
5. **분기를 깨뜨리면 실패하는 테스트가 모든 진입 경로에 있는가?** 섹션 6에서 분기별로 나열했다. 트랜잭션 경계는 Fake 로 검증되지 않으므로 Testcontainers 통합 테스트를 둔다.

공용 헬퍼는 수정하지 않으므로 호출처 grep 은 해당 없다.

새 패키지이므로 세 계층 폴더를 **첫 커밋에 함께** 만든다 (v1.10).

흐름은 다음과 같다.

1. 오늘(Asia/Tokyo) 투약 예정 사용자 ID 를 **userId 오름차순 keyset 으로 500건씩** 읽는다. 전체를 한 번에 `List` 로 담지 않는다 (RR-9).
2. 페이지마다 이미 예약된 사용자를 **`IN` bulk 한 번**으로 조회해 건너뛴다. 재실행해도 중복 예약이 생기지 않는다.
3. 남은 사용자마다 `reserve` 를 **트랜잭션 밖에서** 호출한다. 커넥션을 점유한 채 외부 호출을 하지 않는다.
4. 반환된 reservationId 를 **건별 `REQUIRES_NEW` 트랜잭션**으로 저장한다. 별도 빈이므로 프록시가 실제로 적용된다.
5. 저장이 실패하면 방금 만든 예약을 `cancel` 한다. 취소도 실패하면 ERROR 로 reservationId 를 남긴다.
6. 끝나면 건수를 집계해 로그를 남긴다. 실패가 있으면 ERROR 로 올려 알림이 걸리게 한다.

## 3. `@Transactional(rollbackFor = Exception.class)` 를 적용하지 않은 이유와 대안

### 3-1. 실제로 일어나는 일

사용자 1~3 을 처리하다 사용자 3 에서 실패하는 경우다.

| 단계 | 푸시 서버 | DB | 결과 |
|------|-----------|----|------|
| 사용자 1, 2 예약 성공 | 예약 2건 존재 | 행 2건 (아직 커밋 전) | - |
| 사용자 3 예외 → 전체 롤백 | **예약 2건 그대로 남음** | **행 0건** | 푸시는 발송될 수 있는데 reservationId 가 없어 **취소할 방법이 없다** |
| 재실행 | 사용자 1, 2 를 다시 예약 | 행 3건 | **같은 사용자에게 알림 2번** |

`@Transactional` 의 롤백은 DB 에만 닿는다. 외부 시스템은 되돌리지 못한다. "전부 롤백"이 안전해 보이지만 외부와 DB 를 어긋나게 만든다 (RR-13, RR-F12).

추가 문제가 두 가지 있다.

- 사용자 수만큼의 외부 호출 시간 동안 DB 커넥션을 하나 잡고 있다. 외부가 느려지면 커넥션 풀이 마른다.
- 사용자 한 명의 일시 오류가 그날 전체 알림을 막는다.

### 3-2. 선택한 방식 (A: 건 단위 + 보상)

- 성공분은 유지하고 실패분만 집계한다. 재실행하면 이미 저장된 사용자는 건너뛰고 실패한 사용자만 다시 시도한다.
- "저장 실패 시 외부 예약을 취소"하는 보상으로, 요청의 의도(외부와 DB 가 어긋나지 않게)를 지킨다. `cancel` 이 있어서 가능하다.

### 3-3. 승인이 필요한 대안 (B: 전부 아니면 전무)

"하나라도 실패하면 이번 실행에서 만든 예약을 전부 취소"가 꼭 필요한 업무 규칙이라면 다음으로 구현한다.

- 이번 실행에서 성공한 `(reservationId)` 목록을 메모리에 모아 두고, 첫 실패 시 전부 `cancel` 한 뒤 DB 저장은 하지 않는다.
- 한계: 취소 도중 프로세스가 죽으면 고아 예약이 남는다. 그리고 한 명의 오류가 전원 누락으로 이어진다.
- 이 방식을 쓰려면 "전원 누락을 감수한다"는 합의가 필요하다. 승인해 주시면 적용한다.

## 4. `isOn` 필드를 추가하지 않은 이유

- 이 배치는 `Glp1PushReservedEvent` 를 읽지도 쓰지도 않는다. 이번 작업에서 shared 모듈을 수정할 이유가 없다.
- 지금 소비자가 없는 필드를 넣으면, 나중에 소비자가 "있는 값이니 의미가 있겠지" 하고 신뢰해 쓰게 된다. 값을 채우는 쪽도 없는데 말이다 (#799 `isOn` 리뷰 지적).
- shared 의 이벤트는 api·batch 가 함께 의존한다. 필드를 넣었다가 빼는 비용이 크다.
- 필요해지는 시점에 필드를 **의미(무엇이 켜졌다는 것인지)** 와 **채우는 쪽** 과 함께 추가한다. 그때는 Java 레코드 컴포넌트 이름 `isOn` 의 Jackson 직렬화 이름도 함께 확인한다.

승인 전에는 shared 를 건드리지 않았다. 필요한 용도가 정해져 있으면 알려 달라. 이 PR 에 넣을지 별도 PR 로 할지 정한다.

## 5. 범위 밖으로 보고만 하는 항목 (SC-1, SC-3, SC-4)

| 항목 | 내용 | 급한가 |
|------|------|--------|
| `(user_id, target_date)` UNIQUE 부재 가능성 | 없다면 배치 두 인스턴스가 동시에 돌 때 중복 예약이 생길 수 있다. 앱의 "이미 예약됨" 선조회만으로는 막지 못한다. 마이그레이션 추가는 **승인 대기** (신규 스키마 변경) | 예. 운영 배치가 다중 인스턴스면 |
| 실패 건 재처리용 테이블/아웃박스 | 보상 취소까지 실패하면 ERROR 로그의 reservationId 로 수동 취소해야 한다. 자동화하려면 outbox 계열 신규 테이블이 필요하다 (v1.13). **도입하지 않았다** | 아니오 |
| cron 시각 | 요청에 없는 값이라 06:00 JST 로 임시 설정했다. 확정 필요 | 배포 전 |
| `PushReservationClient` timeout | 아직 확인 못 했다면 확인 결과를 보고한다 | grep 결과 따라 |
| 배치 중복 실행 방지(ShedLock 등) | 기존 배치의 방식을 따른다. 신규 의존성은 도입하지 않는다 | 기존 패턴 따라 |

### 6-2. Infrastructure

```java
package com.kakaohealthcare.moneyball.pghd.glp1push.infrastructure;

import com.kakaohealthcare.moneyball.common.jpa.BaseTimeJpaEntity;
import com.kakaohealthcare.moneyball.pghd.glp1push.domain.Glp1PushReservationEntity;
import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;
import jakarta.validation.constraints.NotNull;
import java.time.LocalDate;
import lombok.AccessLevel;
import lombok.Builder;
import lombok.Getter;
import lombok.NoArgsConstructor;

@Entity
@Table(name = "glp1_push_reservation")
@Getter
@NoArgsConstructor(access = AccessLevel.PROTECTED)
public class Glp1PushReservationJpaEntity extends BaseTimeJpaEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(name = "user_id", nullable = false)
    private long userId;

    @NotNull
    @Column(name = "target_date", nullable = false)
    private LocalDate targetDate;

    @NotNull
    @Column(name = "reservation_id", nullable = false, length = 64)
    private String reservationId;

    @Builder
    private Glp1PushReservationJpaEntity(
            Long id, long userId, LocalDate targetDate, String reservationId) {
        this.id = id;
        this.userId = userId;
        this.targetDate = targetDate;
        this.reservationId = reservationId;
    }

    public Glp1PushReservationEntity toEntity() {
        return new Glp1PushReservationEntity(id, userId, targetDate, reservationId);
    }

    public static Glp1PushReservationJpaEntity from(Glp1PushReservationEntity entity) {
        return Glp1PushReservationJpaEntity.builder()
                .id(entity.getId())
                .userId(entity.getUserId())
                .targetDate(entity.getTargetDate())
                .reservationId(entity.getReservationId())
                .build();
    }
}
```

```java
package com.kakaohealthcare.moneyball.pghd.glp1push.application;

import com.kakaohealthcare.moneyball.pghd.glp1push.domain.Glp1InjectionTargetClientService;
import com.kakaohealthcare.moneyball.pghd.glp1push.domain.Glp1PushReservationClientService;
import com.kakaohealthcare.moneyball.pghd.glp1push.domain.Glp1PushReservationEntity;
import com.kakaohealthcare.moneyball.pghd.glp1push.domain.Glp1PushReservationRepository;
import java.time.LocalDate;
import java.util.Collections;
import java.util.List;
import java.util.Set;
import lombok.RequiredArgsConstructor;
import lombok.extern.log4j.Log4j2;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
@Log4j2
public class Glp1PushReservationBatchService {

    private static final int TARGET_PAGE_SIZE = 500;

    private final Glp1InjectionTargetClientService glp1InjectionTargetClientService;
    private final Glp1PushReservationClientService glp1PushReservationClientService;
    private final Glp1PushReservationRepository glp1PushReservationRepository;
    private final Glp1PushReservationSaveService glp1PushReservationSaveService;

    // 트랜잭션을 걸지 않습니다. 외부 호출 동안 커넥션을 점유하지 않고, 건 단위 커밋을 유지하기 위해서입니다.
    public Glp1PushReservationBatchOutDto reserveAllByTargetDate(LocalDate targetDate) {
        int targetCount = 0;
        int reservedCount = 0;
        int skippedCount = 0;
        int failedCount = 0;
        int compensationFailedCount = 0;

        long afterUserId = 0L;
        boolean hasNextPage = true;
        while (hasNextPage) {
            // 대상 조회와 중복 검사 실패는 전파합니다. 남은 대상을 알 수 없는 채로 진행하면 중복 예약이 생깁니다.
            List<Long> userIdList = glp1InjectionTargetClientService
                    .getAllUserIdListByScheduledDateAfterUserId(
                            targetDate, afterUserId, TARGET_PAGE_SIZE);
            if (userIdList.isEmpty()) {
                break;
            }
            long nextAfterUserId = Collections.max(userIdList);
            if (nextAfterUserId <= afterUserId) {
                log.error("[Glp1PushReservationBatchService.reserveAllByTargetDate] "
                        + "대상 조회 커서가 전진하지 않아 중단합니다: targetDate={}", targetDate);
                break;
            }
            afterUserId = nextAfterUserId;
            hasNextPage = userIdList.size() >= TARGET_PAGE_SIZE;

            List<Long> distinctUserIdList = userIdList.stream().distinct().toList();
            Set<Long> reservedUserIdSet = glp1PushReservationRepository
                    .findAllReservedUserIdByTargetDateAndUserIdIn(targetDate, distinctUserIdList);

            for (Long userId : distinctUserIdList) {
                targetCount++;
                if (reservedUserIdSet.contains(userId)) {
                    skippedCount++;
                    continue;
                }
                ReservationResult reservationResult = reserveOne(userId, targetDate);
                switch (reservationResult) {
                    case RESERVED -> reservedCount++;
                    case RESERVE_FAILED, SAVE_FAILED_COMPENSATED -> failedCount++;
                    case SAVE_FAILED_COMPENSATION_FAILED -> {
                        failedCount++;
                        compensationFailedCount++;
                    }
                }
            }
        }

        Glp1PushReservationBatchOutDto glp1PushReservationBatchOutDto =
                new Glp1PushReservationBatchOutDto(
                        targetCount, reservedCount, skippedCount, failedCount,
                        compensationFailedCount);
        logSummary(targetDate, glp1PushReservationBatchOutDto);
        return glp1PushReservationBatchOutDto;
    }

    private ReservationResult reserveOne(long userId, LocalDate targetDate) {
        String reservationId;
        try {
            reservationId = glp1PushReservationClientService.reserve(userId, targetDate);
        } catch (RuntimeException e) {
            log.warn("[Glp1PushReservationBatchService.reserveOne] 푸시 예약 호출 실패: "
                    + "targetDate={}, cause={}", targetDate, e.getClass().getSimpleName());
            return ReservationResult.RESERVE_FAILED;
        }
        if (reservationId == null || reservationId.isBlank()) {
            log.warn("[Glp1PushReservationBatchService.reserveOne] "
                    + "푸시 서버가 빈 reservationId 를 반환했습니다: targetDate={}", targetDate);
            return ReservationResult.RESERVE_FAILED;
        }

        try {
            glp1PushReservationSaveService.save(
                    Glp1PushReservationEntity.of(userId, targetDate, reservationId));
            return ReservationResult.RESERVED;
        } catch (RuntimeException e) {
            log.error("[Glp1PushReservationBatchService.reserveOne] "
                    + "예약 ID 저장 실패, 외부 예약 취소를 시도합니다: reservationId={}",
                    reservationId, e);
            return cancelAfterSaveFailure(reservationId);
        }
    }

    private ReservationResult cancelAfterSaveFailure(String reservationId) {
        try {
            glp1PushReservationClientService.cancel(reservationId);
            return ReservationResult.SAVE_FAILED_COMPENSATED;
        } catch (RuntimeException e) {
            log.error("[Glp1PushReservationBatchService.cancelAfterSaveFailure] "
                    + "보상 취소 실패, 수동 취소가 필요합니다: reservationId={}", reservationId, e);
            return ReservationResult.SAVE_FAILED_COMPENSATION_FAILED;
        }
    }

    private void logSummary(
            LocalDate targetDate, Glp1PushReservationBatchOutDto glp1PushReservationBatchOutDto) {
        if (glp1PushReservationBatchOutDto.failedCount() == 0) {
            log.info("[Glp1PushReservationBatchService.reserveAllByTargetDate] 완료: "
                    + "targetDate={}, result={}", targetDate, glp1PushReservationBatchOutDto);
            return;
        }
        log.error("[Glp1PushReservationBatchService.reserveAllByTargetDate] 일부 건 실패, "
                + "재실행하면 실패 건만 다시 시도합니다: targetDate={}, result={}",
                targetDate, glp1PushReservationBatchOutDto);
    }

    private enum ReservationResult {
        RESERVED,
        RESERVE_FAILED,
        SAVE_FAILED_COMPENSATED,
        SAVE_FAILED_COMPENSATION_FAILED
    }
}
```

설계 메모이다.

- 로그 본문에 `userId` 를 넣지 않았다 (PII 금지). 재실행이 멱등이라 실패한 사용자를 특정하지 못해도 복구된다. 취소 실패는 reservationId(비즈니스 식별자)로 수동 처리한다.
- 저장 실패를 `catch` 한 뒤 같은 세션으로 재조회하지 않는다. 세션은 `REQUIRES_NEW` 경계에서 이미 종료됐다 (v1.11-A). 예외를 삼키지 않고 ERROR 로 남기고 보상 후 실패로 집계한다 (v1.11-B).
- 저장 중 타임아웃처럼 "커밋 여부가 불명확한" 경우에 취소하면 저장된 행의 예약이 취소된다. 이 한계는 PR 본문에 적고, 다음 실행의 선조회로 식별되지 않으므로 UNIQUE 와 재조회 보강 여부를 승인 항목(5절)에 함께 둔다.
- `Collections.max` 로 커서를 잡아 정렬 순서에 의존하지 않는다 (RR-2). 인터페이스는 오름차순을 약속하지만 어기면 중단 가드가 잡는다.
- 건 단위 실패는 job 실패로 올리지 않는다. 대신 ERROR 요약으로 알림이 걸린다. job 상태를 실패로 내려 재시도를 트리거하고 싶으면 알려 달라.

```java
    @DisplayName("대상이 페이지 크기 경계를 넘어도 모든 사용자가 정확히 한 번씩 예약된다")
    void reserveAllByTargetDate_acrossPageBoundary_reservesEveryoneOnce(int userCount) {
        // Given
        for (long userId = 1L; userId <= userCount; userId++) {
            fakeGlp1InjectionTargetClientService.addTarget(TARGET_DATE, userId);
        }

        // When

```

import 는 `static org.assertj.core.api.Assertions.assertThat`, `tuple` 과 JUnit 5·Spring `DataIntegrityViolationException` 을 모두 명시한다. 와일드카드는 쓰지 않는다.

### 7-3. 추가 테스트 목록

## 10. 승인이 필요한 결정

1. 전부 롤백 의미를 **A(건 단위 + 보상)** 로 갈지, **B(실패 시 이번 실행분 전부 취소)** 로 갈지.
2. `Glp1PushReservedEvent.isOn` 을 지금 넣어야 하는 구체적 용도가 있는지. 있으면 의미와 채우는 쪽을 알려 달라.
3. `glp1_push_reservation (user_id, target_date)` UNIQUE 마이그레이션을 별도 PR 로 추가할지.
4. 실행 시각(임시 06:00 JST)과 실패 건이 있을 때 job 상태를 실패로 내릴지.
5. 취소까지 실패한 건을 자동 복구할 outbox/실패 테이블을 도입할지.
