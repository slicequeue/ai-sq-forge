## 0. 먼저 알려야 할 것: 요청 3건 중 2건은 그대로 구현하지 않는다

요청 항목을 빼는 것이므로 사유를 먼저 밝힌다 (SC-5). 아래 구현은 "안 A" 기준이다. 안 B 를 원하면 알려 달라.

### 0-1. `@Transactional(rollbackFor = Exception.class)` 로 전체 롤백: 적용하지 않음

| 구분 | 내용 |
|------|------|
| 의도 | 하나라도 실패하면 전부 되돌려 외부와 DB 가 일치하게 한다 |
| 실제 동작 | 롤백은 DB 행만 되돌린다. 이미 푸시 서버에 만들어진 예약은 남는다. 앞서 성공한 건의 reservationId 는 롤백으로 사라지므로 `cancel(reservationId)` 도 호출할 수 없다. 푸시는 나가는데 DB 에는 기록이 없는 상태가 된다 |
| 트랜잭션 길이 | 사용자 수만큼 외부 호출이 한 트랜잭션 안에서 돈다. 외부 지연이 곧 DB 커넥션 점유 시간이다. 스킬 v1.13 은 트랜잭션 안 외부 API 호출을 금지한다 |
| 한 건의 영향 | 1건 실패로 나머지 전원의 알림이 사라진다 (RR-13 / RR-F12) |

안 A (구현함): 메서드에 `@Transactional` 을 붙이지 않는다. 사용자 한 건 단위로 "예약 → 저장"을 하고, 저장이 실패하면 방금 만든 예약을 `cancel` 로 보상한다. 한 건이 실패해도 나머지는 계속 진행하고, 마지막에 실패 건수를 ERROR 로 남긴다.

안 B (원하면 변경): 정말 all-or-nothing 이 필요하면 "하나라도 실패 시 이번 실행에서 성공한 예약을 전부 `cancel`" 하는 보상 방식으로 만든다. 트랜잭션 롤백으로는 만들 수 없다. 단, 푸시 서버 장애 시 전원 미발송이므로 비즈니스가 받아들이는지 확인이 필요하다.

### 0-2. `Glp1PushReservedEvent` 에 `isOn` 필드 선반영: 하지 않음

- 소비자가 없는 필드를 shared 이벤트에 미리 두면, 나중 소비자가 그 값을 신뢰해 쓴다. 채우는 쪽이 항상 같은 값을 넣으면 거짓 정보가 된다 (YAGNI 필드, #799 `isOn`).
- 이번 요청의 본 기능(예약 + 저장)은 이벤트를 발행하지 않는다. 이벤트 파일은 건드리지 않는다 (SC-1, SC-3).
- `isOn` 이 실제로 필요해지는 시점(소비자 PR)에 의미 정의(무엇이 on 인가)와 함께 추가하면 된다. shared 변경이라 api·batch 양쪽 컴파일에 영향이 있다.

```java
// pghd/glp1/application/Glp1PushReservationBatchOutDto.java
public record Glp1PushReservationBatchOutDto(
        int targetCount,
        int reservedCount,
        int skippedCount,
        int reserveFailedCount,
        int compensatedCount,
        List<String> orphanReservationIdList
) {
    public boolean hasFailure() {
        return reserveFailedCount > 0 || compensatedCount > 0 || !orphanReservationIdList.isEmpty();
    }
}
```

```java
// pghd/glp1/application/Glp1PushReservationBatchService.java
import java.time.LocalDate;
import java.util.ArrayList;
import java.util.HashSet;
import java.util.List;
import java.util.Set;
import lombok.RequiredArgsConstructor;
import lombok.extern.log4j.Log4j2;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
@Log4j2
public class Glp1PushReservationBatchService {

    private static final int PLAN_PAGE_SIZE = 500;

    private final Glp1InjectionPlanRepository glp1InjectionPlanRepository;
    private final Glp1PushReservationRepository glp1PushReservationRepository;
    private final Glp1PushReservationClientService glp1PushReservationClientService;

    // 외부 호출이 있으므로 메서드 전체에 트랜잭션을 걸지 않습니다
    public Glp1PushReservationBatchOutDto reserveAllByInjectionDate(LocalDate targetDate) {
        List<String> orphanReservationIdList = new ArrayList<>();
        int targetCount = 0;
        int reservedCount = 0;
        int skippedCount = 0;
        int reserveFailedCount = 0;
        int compensatedCount = 0;
        long lastPlanId = 0L;

        while (true) {
            List<Glp1InjectionPlanEntity> glp1InjectionPlanEntityList =
                    glp1InjectionPlanRepository.getAllByInjectionDateAfterId(targetDate, lastPlanId, PLAN_PAGE_SIZE);
            if (glp1InjectionPlanEntityList.isEmpty()) {
                break;
            }

            List<Long> userIdList = glp1InjectionPlanEntityList.stream()
                    .map(Glp1InjectionPlanEntity::getUserId)
                    .distinct()
                    .toList();
            Set<Long> reservedUserIdSet = new HashSet<>(
                    glp1PushReservationRepository.getAllReservedUserIdListByScheduledDateAndUserIdList(
                            targetDate, userIdList));

            for (Glp1InjectionPlanEntity glp1InjectionPlanEntity : glp1InjectionPlanEntityList) {
                lastPlanId = glp1InjectionPlanEntity.getId();
                targetCount++;
                long userId = glp1InjectionPlanEntity.getUserId();

                if (!reservedUserIdSet.add(userId)) {
                    skippedCount++;
                    continue;
                }

                ReserveOutcome reserveOutcome = reserveAndSave(targetDate, glp1InjectionPlanEntity, orphanReservationIdList);
                switch (reserveOutcome) {
                    case RESERVED -> reservedCount++;
                    case RESERVE_FAILED -> reserveFailedCount++;
                    case SAVE_FAILED_COMPENSATED -> compensatedCount++;
                    case SAVE_FAILED_ORPHAN -> { }
                }
            }
        }

        Glp1PushReservationBatchOutDto glp1PushReservationBatchOutDto = new Glp1PushReservationBatchOutDto(
                targetCount, reservedCount, skippedCount, reserveFailedCount, compensatedCount,
                List.copyOf(orphanReservationIdList));
        log.info("[Glp1PushReservationBatchService.reserveAllByInjectionDate] 완료: {}", glp1PushReservationBatchOutDto);
        return glp1PushReservationBatchOutDto;
    }

    private ReserveOutcome reserveAndSave(
            LocalDate targetDate,
            Glp1InjectionPlanEntity glp1InjectionPlanEntity,
            List<String> orphanReservationIdList) {
        String reservationId;
        try {
            reservationId = glp1PushReservationClientService.reserve(glp1InjectionPlanEntity.getUserId(), targetDate);
        } catch (RuntimeException e) {
            log.error("[Glp1PushReservationBatchService.reserveAndSave] 푸시 예약 실패: planId={}",
                    glp1InjectionPlanEntity.getId(), e);
            return ReserveOutcome.RESERVE_FAILED;
        }

        try {
            glp1PushReservationRepository.save(Glp1PushReservationEntity.of(
                    glp1InjectionPlanEntity.getUserId(), targetDate, reservationId));
            return ReserveOutcome.RESERVED;
        } catch (RuntimeException saveException) {
            log.error("[Glp1PushReservationBatchService.reserveAndSave] 예약 저장 실패, 보상 취소 시도: planId={}, reservationId={}",
                    glp1InjectionPlanEntity.getId(), reservationId, saveException);
            return cancelOrRecordOrphan(reservationId, orphanReservationIdList);
        }
    }

    private ReserveOutcome cancelOrRecordOrphan(String reservationId, List<String> orphanReservationIdList) {
        try {
            glp1PushReservationClientService.cancel(reservationId);
            return ReserveOutcome.SAVE_FAILED_COMPENSATED;
        } catch (RuntimeException cancelException) {
            log.error("[Glp1PushReservationBatchService.cancelOrRecordOrphan] 보상 취소 실패, 수동 취소 필요: reservationId={}",
                    reservationId, cancelException);
            orphanReservationIdList.add(reservationId);
            return ReserveOutcome.SAVE_FAILED_ORPHAN;
        }
    }

    private enum ReserveOutcome {
        RESERVED,
        RESERVE_FAILED,
        SAVE_FAILED_COMPENSATED,
        SAVE_FAILED_ORPHAN
    }
}
```

설계 근거

- 건 단위 예약 후 저장, 저장 실패 시 보상. 한 건의 실패가 앞선 성공분과 뒤따르는 건을 깨지 않는다 (RR-13).
- `userId` 로 조회·저장하므로 로그 본문에 `userId` 를 넣지 않았다. 식별자는 `planId`, `reservationId` 만 쓴다.
- 재실행 멱등성: 이미 예약된 사용자는 건너뛴다. 예약 전 `exists` 를 건별로 부르지 않고 페이지 단위 `IN` 조회 1회로 처리한다 (RR-9, 페이지 500 이라 `IN` 상한도 충족).
- 동시 실행(인스턴스 2대)으로 UNIQUE 위반이 나면 `save` 가 실패해 방금 만든 예약을 보상 취소한다. 먼저 저장한 쪽의 예약이 유효하므로 올바른 동작이다. 위반 예외를 삼켜 세션을 재조회하는 코드는 없다 (v1.11-A, B 해당 없음).
- `catch (RuntimeException)`: reserve/cancel 이 던지는 예외 계층이 `RuntimeException` 하위라는 가정. 검사 예외를 던지면 컴파일 오류로 드러난다 (RR-5).
- 정렬: 계획 조회는 `ORDER BY id ASC` + id 커서라 순서가 결정적이고 `OFFSET` 누적 비용이 없다 (RR-2, RR-9).

## 9. 코드 주석 문체 확인 (v1.17)

코드 블록 안 `//` 주석 줄은 다음 4건뿐이다. 모두 존댓말이고 평서형 끝맺음(`한다.`, `된다.`, `이다.`, `않는다.`)은 0건이다.

4. `// pghd/...`, `// Glp1InjectionPlanJpaRepository 에 추가` 같은 파일 위치 표시 (문장 아님)
