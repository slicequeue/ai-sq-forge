# TC-16 with-skill

GLP-1 증상 기록 메모 단건 조회 API 구현 완료 (로컬, 커밋 전, 테스트 미실행)
- `GET /api/v1/glp1/symptom-records/{recordId}/memo` 추가. UseCase/Service, OutDto, Response, Controller 신규
- 단위 테스트 2종 작성 (Service는 Fake Repository, Controller는 `@WebMvcTest`)
- 미확인: gradle 테스트, spotlessApply, review-lint 실행 전. 아래 "실행 예정" 명령으로 확인 필요

조직 컨벤션 적용 판정: 적용 (`vc-conventions-guide.md` 있음). 원문 naming·dto·pkg-structure·lombok·testcode 확인.

## 요청과 다르게 구현한 항목 (조직 컨벤션 우선)

| 요청 | 구현 | 근거 |
|------|------|------|
| `from()` 팩토리로 `Glp1SymptomMemoOutDto`·`Glp1SymptomMemoResponse` 생성 | 생성자 직접 호출. 변환은 Service(`Entity → OutDto`)와 Controller(`OutDto → Response`)가 한다 | 가이드 3절 정적 팩토리 행. 신규 클래스는 조직 컨벤션, 같은 패키지의 `from()` 관례(우선순위 4)는 그 아래. 이미 `from()` 이 있는 기존 클래스를 고치는 작업이 아니라 신규 클래스다 |
| 변수명 `dto`, `req` | `glp1SymptomMemoOutDto`, `glp1SymptomMemoResponse` 등 타입명 전체. `req` 는 이 API 에 요청 본문이 없어 쓰는 곳이 없다 | naming 원문, 가이드 4-1절 `req`·`dto` 금지 |
| 새 컨트롤러 `Glp1SymptomMemoController` | `Glp1SymptomMemoQueryController` (새 컨트롤러로 분리는 요청대로 유지) | 가이드 3절 Controller 이름 행. 조회 전용 신규 Controller 는 `{Domain}QueryController` |

## 확인한 것과 가정한 것

확인한 것
- 4-Tier 위치, `Glp1SymptomRecordRepository`, `Glp1SymptomRecordEntity`(`getId()`, `getMemo()`), `FakeGlp1SymptomRecordRepository` 가 읽은 저장소에 있다
- 읽은 저장소의 기존 Controller 는 `UseCase` 인터페이스 + `*Service` 구현 구조이고 Controller 는 `ResponseEntity` 없이 Response 를 바로 반환한다. 이 구조에 맞췄다
- 읽은 저장소의 테스트 `application.yml` 은 H2. 이번 작업은 Infrastructure 변경이 없어 DB 설정을 건드리지 않는다

가정한 것 (재평가 트리거 포함)
- `Glp1SymptomRecordNotFoundException(long recordId)` 생성자 시그니처. 과제 전제로는 존재하지만 내가 읽은 저장소 체크아웃에서는 이 클래스와 `UserContextHolder` 를 찾지 못했고 기존 코드는 `NotFoundException` + `@AuthenticationPrincipal Long userId` 를 쓴다. 전제 쪽 브랜치가 다를 수 있다. 컴파일이 안 되면 두 import·호출을 실제 시그니처에 맞춘다
- `UserContextHolder` 의 패키지 (아래 코드의 import 는 자리표시). 컴파일 시 정정
- 요청 경로는 사용자가 준 `/api/v1/glp1` 을 그대로 썼다. 기존 Controller 는 `/pghd/v1/glp1` 아래에 있으므로 어느 쪽이 맞는지 확인이 필요하다
- 새 엔드포인트의 인증 허용 목록 등록 여부(SecurityConstants/SecurityMatcher). 인증이 필요한 일반 API 면 등록할 것이 없다. 코드는 건드리지 않았다

```java
// Copyright 2026 Kakao Healthcare Corp. All Rights Reserved.
package com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom.dto.Glp1SymptomMemoOutDto;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom.exception.Glp1SymptomRecordNotFoundException;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.domain.symptom.Glp1SymptomRecordEntity;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.domain.symptom.Glp1SymptomRecordRepository;

import lombok.RequiredArgsConstructor;

@Service
@RequiredArgsConstructor
@Transactional(readOnly = true)
public class Glp1SymptomMemoQueryService implements Glp1SymptomMemoQueryUseCase {

  private final Glp1SymptomRecordRepository glp1SymptomRecordRepository;

  @Override
  public Glp1SymptomMemoOutDto getSymptomMemoOrThrowException(long recordId, long userId) {
    // 다른 사용자의 기록은 조회되지 않으므로 존재 여부가 노출되지 않습니다
    Glp1SymptomRecordEntity glp1SymptomRecordEntity =
        glp1SymptomRecordRepository
            .findByIdAndUserId(recordId, userId)
            .orElseThrow(() -> new Glp1SymptomRecordNotFoundException(recordId));

    return new Glp1SymptomMemoOutDto(
        glp1SymptomRecordEntity.getId(), glp1SymptomRecordEntity.getMemo());
  }
}
```

```java
// Copyright 2026 Kakao Healthcare Corp. All Rights Reserved.
package com.kakaohealthcare.vc.pasta.health.pghd.glp1.web;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom.Glp1SymptomMemoQueryUseCase;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom.dto.Glp1SymptomMemoOutDto;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.web.dto.Glp1SymptomMemoResponse;
// 미확인: UserContextHolder 의 실제 패키지로 정정
import com.kakaohealthcare.vc.pasta.common.security.UserContextHolder;

import io.swagger.v3.oas.annotations.Operation;
import io.swagger.v3.oas.annotations.media.Schema;
import io.swagger.v3.oas.annotations.tags.Tag;
import lombok.RequiredArgsConstructor;

@Tag(name = "PGHD - GLP1", description = "GLP-1 관련 API 모음")
@RestController
@RequestMapping("/api/v1/glp1")
@RequiredArgsConstructor
public class Glp1SymptomMemoQueryController {

  private final Glp1SymptomMemoQueryUseCase glp1SymptomMemoQueryUseCase;

  @Operation(summary = "GLP-1 증상 기록 메모 단건 조회 API")
  @GetMapping("/symptom-records/{recordId}/memo")
  public ResponseEntity<Glp1SymptomMemoResponse> getGlp1SymptomMemo(
      @Schema(description = "증상 기록 ID", example = "123", requiredMode = Schema.RequiredMode.REQUIRED)
          @PathVariable
          Long recordId) {
    Glp1SymptomMemoOutDto glp1SymptomMemoOutDto =
        glp1SymptomMemoQueryUseCase.getSymptomMemoOrThrowException(
            recordId, UserContextHolder.getUserId());

    Glp1SymptomMemoResponse glp1SymptomMemoResponse =
        new Glp1SymptomMemoResponse(
            glp1SymptomMemoOutDto.recordId(), glp1SymptomMemoOutDto.memo());
    return ResponseEntity.ok(glp1SymptomMemoResponse);
  }
}
```

```java
package com.kakaohealthcare.vc.pasta.health.pghd.glp1.application.symptom;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;

import java.time.Instant;

import org.junit.jupiter.api.BeforeEach;
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;

@DisplayName("Glp1SymptomMemoQueryService 테스트")
class Glp1SymptomMemoQueryServiceTest {

  private static final long OWNER_USER_ID = 10L;
  private static final long OTHER_USER_ID = 20L;

  private FakeGlp1SymptomRecordRepository fakeGlp1SymptomRecordRepository;
  private Glp1SymptomMemoQueryService glp1SymptomMemoQueryService;

  @BeforeEach
  void setUp() {
    fakeGlp1SymptomRecordRepository = new FakeGlp1SymptomRecordRepository();
    glp1SymptomMemoQueryService =
        new Glp1SymptomMemoQueryService(fakeGlp1SymptomRecordRepository);
  }

  @Test
  @DisplayName("본인 기록의 ID 와 메모가 반환된다")
  void getSymptomMemoOrThrowException_ownRecord_returnsIdAndMemo() {
    // Given
    Glp1SymptomRecordEntity savedGlp1SymptomRecordEntity =
        fakeGlp1SymptomRecordRepository.save(createRecordEntity(OWNER_USER_ID, "저녁 식사 후 메스꺼움"));

    // When
    Glp1SymptomMemoOutDto glp1SymptomMemoOutDto =
        glp1SymptomMemoQueryService.getSymptomMemoOrThrowException(
            savedGlp1SymptomRecordEntity.getId(), OWNER_USER_ID);

    // Then
    assertThat(glp1SymptomMemoOutDto)
        .isEqualTo(
            new Glp1SymptomMemoOutDto(savedGlp1SymptomRecordEntity.getId(), "저녁 식사 후 메스꺼움"));
  }

  @Test
  @DisplayName("메모를 작성하지 않은 기록은 메모가 null 로 반환된다")
  void getSymptomMemoOrThrowException_recordWithoutMemo_returnsNullMemo() {
    // Given
    Glp1SymptomRecordEntity savedGlp1SymptomRecordEntity =
        fakeGlp1SymptomRecordRepository.save(createRecordEntity(OWNER_USER_ID, null));

    // When
    Glp1SymptomMemoOutDto glp1SymptomMemoOutDto =
        glp1SymptomMemoQueryService.getSymptomMemoOrThrowException(
            savedGlp1SymptomRecordEntity.getId(), OWNER_USER_ID);

    // Then
    assertThat(glp1SymptomMemoOutDto.memo()).isNull();
  }

  @Test
  @DisplayName("존재하지 않는 기록을 조회하면 Glp1SymptomRecordNotFoundException 이 발생한다")
  void getSymptomMemoOrThrowException_unknownRecord_throwsNotFoundException() {
    // Given
    long unknownRecordId = 999L;

    // When, Then
    assertThatThrownBy(
            () ->
                glp1SymptomMemoQueryService.getSymptomMemoOrThrowException(
                    unknownRecordId, OWNER_USER_ID))
        .isInstanceOf(Glp1SymptomRecordNotFoundException.class);

  @Test
  @DisplayName("다른 사용자의 기록을 조회하면 Glp1SymptomRecordNotFoundException 이 발생한다")
```

## 판단 기록

- 작성 전 질문: 존재하지 않거나 다른 사용자의 기록이면 404 계열 예외로 같은 응답(존재 여부 비노출). 메모가 null 이면 `memo: null` 로 응답. 기존 경로 동작 변경 없음(신규 클래스만 추가). 진입 경로는 Controller 1개이고 Service·Controller 테스트가 각각 있다
- `Glp1SymptomMemoQueryUseCase` 를 기존 `Glp1SymptomRecordQueryUseCase` 에 합치지 않고 새로 만들었다. 기존 인터페이스를 구현한 다른 클래스와 테스트를 건드리지 않기 위해서다
- 코드 주석은 존댓말이며 평서형 끝맺음 줄은 코드 블록 주석을 훑어 0건 확인했다
- Infrastructure 변경이 없어 테스트 DB 설정(H2)은 그대로다

## 범위 밖 제안

- `FakeGlp1SymptomRecordRepository` 의 `findProjectionByIdAndUserId` 등이 `UnsupportedOperationException` 이다. 이번 작업은 `findByIdAndUserId`·`save` 만 써서 영향이 없다
- 기존 `Glp1SymptomQueryControllerV1` 은 `@AuthenticationPrincipal Long userId` 를 쓰는데 이번 요청 전제는 `UserContextHolder.getUserId()` 다. 두 방식이 섞여 있어 통일 여부를 팀에서 정하면 좋다
