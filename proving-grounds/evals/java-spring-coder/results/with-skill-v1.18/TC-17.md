- `MenuController` 를 새로 만들고 `GET /api/menus/{menuId}` 를 추가했습니다. 없는 id 는 404 + `MR-003` 입니다.
- `MenuDetailOutDto.from(Menu)`, `MenuDetailResponse.from(MenuDetailOutDto)` 를 기존 `MealRecommendResponse.from` 과 같은 방식으로 만들었습니다.

- 테스트 3종(서비스, 컨트롤러, 저장소 findById)을 작성했습니다. gradle 은 아직 실행하지 않았습니다.

## 작성 전 질문 5개 (RR-13·14)

1. 이 조회가 실패하면: 없는 id → 404 JSON(`ErrorResponse`). 서버 내부 오류는 기존 `handleAny` 500.
2. 외부 호출 후 저장 실패: 해당 없음 (조회 전용, 외부 호출 없음).
3. 마스터 데이터 이상: `imageFile` 이 null/blank 이면 `Menu.imageUrl()` 이 null 을 반환하고 응답의 `imageUrl` 도 null 입니다. `Menu` 생성자가 id·kcal 을 검증하므로 그 외 이상값은 로드 시점에 실패합니다.
4. 기존 동작 변경: 없음. 신규 엔드포인트 + 인터페이스 메서드 추가뿐이며 기존 경로는 건드리지 않았습니다.
5. 모든 진입 경로 테스트: 정상 / 없는 id / 이미지 없음 / 저장소 findById 존재·부재를 테스트로 덮습니다.

## 요청과 다르게 한 부분 / 맞춘 부분

- 변수 이름: `dto` 를 요청대로 썼습니다 (`MenuDetailResponse.from(MenuDetailOutDto dto)`, 컨트롤러·테스트의 OutDto 지역 변수). `req` 는 GET 에 요청 바디/객체가 없어 쓸 자리가 없었습니다 (`menuId` 는 `@PathVariable` 값입니다). 기존 코드는 `outDto`, `request` 를 쓰므로 통일을 원하시면 이름만 바꾸면 됩니다.
- 컨트롤러 이름: 스킬 기본 패턴은 `{Domain}{Action}Controller` 지만 `MenuController` 로 명시하셔서 그대로 썼습니다.
- 응답 변환: 프로젝트 규칙 05 ("DTO 는 `of()`/`from()`")에 따라 `from()` 을 썼습니다. 조직 컨벤션 비적용이라 이 규칙을 뒤집지 않았습니다.

### 7. application — `application/MenuDetailService.java` (신규)

```java
package com.kakaohealthcare.pasta.mealrecommender.application;

import com.kakaohealthcare.pasta.mealrecommender.application.exception.MenuNotFoundException;
import com.kakaohealthcare.pasta.mealrecommender.domain.Menu;
import com.kakaohealthcare.pasta.mealrecommender.domain.MenuRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class MenuDetailService {

    private final MenuRepository menuRepository;

    public MenuDetailOutDto getMenuDetail(long menuId) {
        Menu menu = menuRepository.findById(menuId)
                .orElseThrow(() -> new MenuNotFoundException(menuId));
        return MenuDetailOutDto.from(menu);
    }
}
```

```java
package com.kakaohealthcare.pasta.mealrecommender.web;

import com.kakaohealthcare.pasta.mealrecommender.application.MenuDetailOutDto;
import com.kakaohealthcare.pasta.mealrecommender.application.MenuDetailService;
import com.kakaohealthcare.pasta.mealrecommender.web.dto.MenuDetailResponse;
import lombok.RequiredArgsConstructor;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequiredArgsConstructor
@RequestMapping("/api/menus")
public class MenuController {

    private final MenuDetailService menuDetailService;

    @GetMapping("/{menuId}")
    public ResponseEntity<MenuDetailResponse> detail(@PathVariable long menuId) {
        MenuDetailOutDto dto = menuDetailService.getMenuDetail(menuId);
        return ResponseEntity.ok(MenuDetailResponse.from(dto));
    }
}
```

## 범위 밖 제안 (고치지 않음)

- `GlobalExceptionHandler.handleAny` 가 `Exception` 전체를 500 으로 처리합니다. 그래서 `GET /api/menus/abc` 처럼 숫자가 아닌 `menuId` 는 `MethodArgumentTypeMismatchException` 이 500 으로 응답될 가능성이 큽니다. 이 새 엔드포인트가 만드는 첫 path variable 이므로 400 으로 받는 핸들러 추가를 권합니다. 요청 범위 밖이라 이번에는 넣지 않았고, 그 케이스의 테스트도 쓰지 않았습니다.
- 기존 `MealRecommendResponse` 는 web 에서 domain `Menu` 를 import 합니다 (`MealRecommendationOutDto` 가 `Menu` 를 들고 있음). 이번 DTO 는 평탄 필드로 만들어 그 방식을 따라가지 않았습니다.
- 기존 `RecommendControllerTest` 와 이번 `MenuControllerTest` 는 규칙 08 의 "`@MockBean` 최소화" 보다 기존 테스트 형태를 따랐습니다. 컨트롤러 테스트를 `@TestConfiguration` + Fake 로 바꾸는 것은 별도 작업 제안입니다.
