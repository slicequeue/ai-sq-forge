# TC-18 with-skill (java-spring-coder v1.18)

투여 상태 응답 skippedCount 추가 + 투여 건너뛰기 등록 API 구현 완료 (로컬, 커밋 전, 테스트 미실행)
- `Glp1InjectionStatusResponse` 에 `skippedCount`(최근 30일 건너뛰기 횟수) 추가. 기존 `from()` 본문과 OutDto 팩토리를 고쳐 쓰고 새 팩토리는 만들지 않음
- 투여 건너뛰기 등록 API 신설: domain·infrastructure·application·web 4계층 + `glp1_injection_skip` 매핑 JPA 엔티티
- 테스트 신규 7개 클래스, 기존 2개 클래스 수정 (작성만 함, gradle·review-lint 미실행)
- 사용자 요청 2건은 따르지 않았음: Testcontainers 로 돌리기, 신규 클래스를 `from()` 으로 맞추기 (아래 "요청과 다르게 한 것")

미확인: `./gradlew :pasta-api:test` 결과, `spotlessApply`, `review-lint.py` 위반 건수(조직 컨벤션 검사 켜짐/꺼짐 포함). 실제 저장소 파일은 읽기만 했고 수정하지 않았다. 아래 코드는 적용 예정 내용이다.

## 상세

### 조직 컨벤션 판정

조직 컨벤션 적용 프로젝트로 판정 (TC 가 명시한 프로젝트 맥락, `vc-conventions-guide.md` 2절). 원문 `vc-conventions/` 폴더는 존재하고 dto·entity·lombok·naming·testcode 를 읽었다.

### 요청과 다르게 한 것

| 요청 | 한 일 | 근거 |
|------|-------|------|
| "전부 `from()` 패턴으로" | 신규 클래스(InDto, OutDto, Request, Response, JpaEntity, Domain Entity)는 생성자 직접 호출. 이미 `from()` 이 있는 `Glp1InjectionStatusResponse`·`Glp1InjectionTimeStatusOutDto` 는 기존 메서드를 고쳐 씀 | vc-conventions-guide 3절 "정적 팩토리" 행, dto-convention 2절, entity-convention. 같은 패키지의 기존 `from()` 관례는 조직 컨벤션보다 하위 |
| "Repository 테스트는 Testcontainers 로" | `@DataJpaTest` + 모듈 기존 H2 설정(`jdbc:h2:mem:test;MODE=MySQL`) 그대로 | SKILL 하드 가드레일 "모듈의 기존 테스트 DB 설정 유지, 전환 금지", vc-conventions-guide 3절 "테스트 DB" 행. pasta-api 는 기존 repository 테스트(`Glp1SymptomQuestionJpaRepositoryTest` 등)가 전부 이 설정이고, pasta-api/src/test 에 Testcontainers 사용 코드는 grep 0건 |
| 경로 `POST /api/v1/glp1/injection-skips` | `POST /pghd/v1/glp1/injection-skips` | glp1 컨트롤러 전부 `/pghd/v{n}/glp1`, `SecurityConstants.airArray` 에 `/pghd/**` 가 이미 있어 인증 설정 변경이 없다. `/api/v1/...` 로 가려면 airArray 등록이 추가로 필요. 리터럴 경로가 맞으면 `@RequestMapping` 한 줄과 airArray 한 줄만 바꾸면 된다 (SC-3, 결정 요청) |

Testcontainers 가 정말 필요하면 pasta-api 테스트 DB 전환이라 별도 합의가 필요하다. 전환하지 않았다. H2 에서는 `ddl-auto: update` 로 테이블이 엔티티에서 만들어지므로 `glp1_injection_skip` 마이그레이션 DDL 자체는 검증되지 않는다 (미확인).

### 확인한 것과 가정한 것

확인 (pasta-japan-server 실제 코드):
- glp1 패키지는 `domain/injection`, `application/injection`, `infrastructure/persistence/injection`, `web` 구조. UseCase 인터페이스 + Service 구현 패턴
- 기존 `Glp1InjectionRecordQueryService` 는 `@Transactional(readOnly = true)` 클래스, `inspectInjectionTime(Instant, long, Long)` 이 `Glp1InjectionTimeStatusOutDto` 반환
- `inspectInjectionTime` 호출처는 `Glp1QueryController.getInjectionStatus` 1곳, 구현체는 서비스 1개와 테스트 Fake 1개(`FakeDiaryGlp1InjectionRecordQueryUseCase`), 기존 테스트 2건
- `BaseTimeEntity` 는 `updated_at` 컬럼을 같이 만들어서 `glp1_injection_skip`(created_at 만 있음)과 맞지 않아 상속하지 않았다
- 시간대는 `TimeZoneContext.getZoneId()` 를 컨트롤러에서 받아 서비스에 넘기는 패턴이 기존(`Glp1InjectionRecordCommandControllerV2`)에 있다

가정 (재평가 트리거 포함):
- 최근 30일은 요청 `at` 의 현지 날짜를 끝으로 하는 30일(오늘 포함, 29일 전~오늘). 31일로 보는 쪽이면 `RECENT_DAYS` 상수만 수정
- `user_id`, `skipped_date`, `created_at` 은 NOT NULL, `reason` 은 nullable. 저장소에서 `glp1_injection_skip` 마이그레이션 SQL 은 grep 으로 찾지 못했다(전제 조건에 의존). 실제 DDL 이 다르면 `@Column(nullable)` 과 Request 검증을 맞춘다

### 작성 전 질문 5개 (RR-13·14)

1. 건너뛰기 횟수 조회가 실패하면: 투여 상태 전체가 500 이 되지 않도록 `skippedCount` 만 `null`(집계 실패) 로 응답하고 WARN 을 남긴다. 0 으로 채우지 않는다(틀린 상태가 됨)
2. 외부 호출: 없음
3. 마스터 데이터: 없음. `reason` null 허용, `skippedDate` null 은 400
4. 기존 경로 동작 변경: `GET /pghd/v1/glp1/injection-status` 응답에 `skippedCount` 필드가 추가되고 쿼리 1건이 더 돈다. `inspectInjectionTime` 시그니처에 `ZoneId` 추가. PR 본문 "기존 동작 변경"에 적을 것
5. 진입 경로 테스트: 정상/시간대/경계일/조회 실패 격리/Request 검증을 각각 둠

```java
  private final Glp1InjectionSkipQueryUseCase glp1InjectionSkipQueryUseCase;

  @Override
  public Glp1InjectionTimeStatusOutDto inspectInjectionTime(
      Instant at, long userId, Long excludeInjectionRecordId, ZoneId zoneId) {
    Integer skippedCount = countRecentInjectionSkipsOrNull(at, userId, zoneId);
    Optional<Glp1GroupEntity> optional = glp1GroupRepository.findLastInjectedByUserId(userId);

    if (optional.isEmpty()) {
      return Glp1InjectionTimeStatusOutDto.empty(at, skippedCount);
    }

    Glp1InjectionTimeStatusInspection inspection =
        new Glp1InjectionTimeStatusInspection(
            optional.get().getInjectionRecords(), at, excludeInjectionRecordId);

    return Glp1InjectionTimeStatusOutDto.from(inspection, skippedCount);
  }

  private Integer countRecentInjectionSkipsOrNull(Instant at, long userId, ZoneId zoneId) {
    try {
      return glp1InjectionSkipQueryUseCase.countRecentInjectionSkips(userId, at, zoneId);
    } catch (RuntimeException exception) {
      // 투여 상태 판정은 건너뛰기 집계와 무관하게 응답해야 하므로 집계 실패만 null 로 격리합니다.
      log.warn(
          "[Glp1InjectionRecordQueryService.inspectInjectionTime] 최근 건너뛰기 횟수 조회에 실패해 skippedCount 를 null 로 응답합니다",
          exception);
      return null;
    }
  }
```

```java
package com.kakaohealthcare.vc.pasta.health.pghd.glp1.infrastructure.persistence.injection;

import java.time.LocalDate;

import org.springframework.stereotype.Repository;

import com.kakaohealthcare.vc.pasta.health.pghd.glp1.domain.injection.Glp1InjectionSkipEntity;
import com.kakaohealthcare.vc.pasta.health.pghd.glp1.domain.injection.Glp1InjectionSkipRepository;

import lombok.RequiredArgsConstructor;

@Repository
@RequiredArgsConstructor
public class Glp1InjectionSkipRepositoryImpl implements Glp1InjectionSkipRepository {

  private final Glp1InjectionSkipJpaRepository glp1InjectionSkipJpaRepository;

  @Override
  public Glp1InjectionSkipEntity save(Glp1InjectionSkipEntity glp1InjectionSkipEntity) {
    Glp1InjectionSkipJpaEntity glp1InjectionSkipJpaEntity =
        Glp1InjectionSkipJpaEntity.builder()
            .id(glp1InjectionSkipEntity.getId())
            .userId(glp1InjectionSkipEntity.getUserId())
            .skippedDate(glp1InjectionSkipEntity.getSkippedDate())

        savedGlp1InjectionSkipJpaEntity.getId(),
        savedGlp1InjectionSkipJpaEntity.getUserId(),
        savedGlp1InjectionSkipJpaEntity.getSkippedDate(),
        savedGlp1InjectionSkipJpaEntity.getReason(),
        savedGlp1InjectionSkipJpaEntity.getCreatedAt());

      long userId, LocalDate startDate, LocalDate endDate) {
    return glp1InjectionSkipJpaRepository.countByUserIdAndSkippedDateBetween(
        userId, startDate, endDate);
```

### 체크리스트 자기 검증 (작성 단계 기준)

- 주석 문체: 코드 블록의 주석·Javadoc 줄을 훑었고 `한다.`·`된다.`·`이다.`·`않는다.` 로 끝나는 줄 0건 (Given/When/Then 라벨 제외)
- FQCN, `var`, 와일드카드 import, `@Setter`, `@Data` 0건. 변수명은 타입명 전체 (람다 매개변수 `entity`·`violation` 은 한 줄짜리 스트림 관례로 유지)
- JPA Entity: `@NoArgsConstructor(PROTECTED)` + 생성자 `@Builder`, `@Column(nullable=false)` 와 `@NotNull` 병행 (가정한 NOT NULL 컬럼 한정)
- Domain Entity: JPA·Spring 어노테이션 없음, `@ToString`·`@EqualsAndHashCode` 둘 다 있고 PII(userId, reason)는 toString 에서 제외
- 새 컨트롤러 메서드는 `ResponseEntity` 반환. 상태 코드는 기존 생성 API 관례에 맞춰 200
- SecurityConstants: `/pghd/**` 로 이미 커버됨, 환경변수 추가 없음
- 로그: `[Class.method]` 접두, userId 미포함
- `review-lint.py`·gradle 테스트·spotless 는 돌리지 않아 통과로 보고하지 않음

### 합의가 필요한 것 (구현하지 않고 현재 동작만 적음)

- 같은 날짜를 중복 등록하면 두 건이 저장되고 `skippedCount` 에 둘 다 센다 (유니크 제약·중복 방지 규칙 정보 없음)
- 미래 날짜도 등록된다
- `REQUIRES_NEW` 는 요청 하나가 DB 커넥션 2개를 동시에 잡는다. 트래픽이 큰 `injection-status` 에서 커넥션 풀 여유를 확인해야 한다 (미확인)

### 범위 밖 제안 (수정하지 않음)

- `Glp1InjectionRecordQueryService.inspectInjectionTime` 의 지역 변수 `inspection`, `optional` 은 조직 컨벤션의 타입명 전체 규칙과 다르다
- `Glp1InjectionStatusResponse` 의 `@Builder` 는 `from()` 이 `new` 로 만들어 쓰지 않는다
