# TC-17 with-skill-v1.18b

메뉴 단건 조회 API(GET /api/menus/{menuId}) 구현 완료 (로컬, 커밋 전, 테스트 미실행)

- 새 `MenuController` 와 `MenuDetailService`, `MenuDetailOutDto`·`MenuDetailResponse`(`from()` 팩토리)를 추가했고, 없는 menuId 는 404(`MR-003`)로 응답합니다.
- `MenuRepository.findById` 를 domain 인터페이스·`InMemoryMenuRepositoryImpl`·`FakeMenuRepository` 에 추가했습니다.
- 서비스·컨트롤러(MockMvc)·저장소·E2E 테스트와 응답 매핑 테스트 5개 파일을 작성했습니다.
- 조직 컨벤션 비적용 프로젝트로 판정했습니다(`.claude/shared/` 에 `vc-conventions-guide.md` 없음). 프로젝트 규칙 05 의 `from()` 팩토리를 그대로 따랐습니다.

미확인: `./gradlew test`, `spotlessApply`, `python3 forge/common/review-lint.py` 는 시뮬레이션이라 실행하지 않았습니다. 실행 후 위반 0건과 조직 컨벤션 검사 "꺼짐" 이 판정과 맞는지 확인이 필요합니다.

## 요청과 다르게 한 부분

- 변수명 `dto`·`req`: 쓰지 않았습니다. 스킬 변수 네이밍 규칙(대상·결과 변수는 타입이 드러나게, 조직 컨벤션과 무관한 기본 규칙)에 따라 `menuDetailOutDto`, `menuDetailResponse` 로 썼습니다. 이 API 에는 요청 body 가 없어 `req` 에 해당하는 변수는 없고 경로 변수는 `menuId` 입니다.
- `from()` 팩토리: 요청대로 썼습니다. 비적용 프로젝트라 규칙 05 가 정한 방식과 일치합니다.
- `MenuController` 이름: 요청대로 썼습니다. 스킬 기본 패턴은 `{Domain}{Action}Controller` 이지만 컨트롤러 이름은 외부 계약이 아니고, 기존 `RecommendController` 도 Action 접미사가 없어 요청을 우선했습니다.
- 경로 `GET /api/menus/{menuId}`: 변경하지 않았습니다. 기존 접두사 `/api/recommend` 와 같은 `/api/{리소스}` 형태라 불일치도 없습니다.

## 사전 확인 (읽기만 수행)

- 확인된 것: `.claude/rules/05`(DTO 는 `of()`/`from()`, Controller 는 `ResponseEntity`), `.claude/shared/` 가드 4종, `MenuRepository`(findById 없음), `MenuRepository` 구현체는 `InMemoryMenuRepositoryImpl` 과 테스트의 `FakeMenuRepository` 두 곳뿐(grep), 예외 코드 `MR-001`·`MR-002`·`MR-400`·`MR-500`, `messages.properties` 에 `error.menu.*` 키 2개.
- 확인된 것: 수정 대상 기존 파일(MenuRepository, InMemoryMenuRepositoryImpl, FakeMenuRepository, ExceptionConstants, messages.properties)의 `git status --short` 출력이 비어 있어 미커밋 변경 없음(DW-1).
- DB 가 없어 테스트 DB 설정 전환 문제 없음. SecurityConstants·환경변수 4곳 해당 없음(이 프로젝트에 없음).
- 모드 B(TDD 문서 없음, 코드+테스트 요청). `docs/plans`·`docs/tdd` 탐색 결과는 이 시뮬레이션에서 미확인입니다.

작성 전 질문 5개 답변:
1. 조회가 실패하면: 없는 id 는 404 + `MR-003`. 서버 오류는 기존 `GlobalExceptionHandler` 의 500.
2. 외부 호출 없음.
3. 마스터 데이터: `Menu` 생성자가 id·baseKcal 양수와 nameJa·mealTime non-null 을 검증하므로 null 값은 들어오지 않습니다. `imageFile` 이 없으면 `imageUrl()` 이 null 이라 응답의 `imageUrl` 도 null 입니다(테스트로 고정).
4. 기존 경로 동작 변경 없음. `MenuRepository` 에 메서드가 추가되어 구현체 두 곳을 함께 고쳤습니다.
5. 분기(존재/부재)마다 서비스·컨트롤러·저장소 테스트를 두었습니다.

### 7. application/MenuDetailService.java (신규)

```java
package com.kakaohealthcare.pasta.mealrecommender.application;

import com.kakaohealthcare.pasta.mealrecommender.application.exception.MenuNotFoundException;
import com.kakaohealthcare.pasta.mealrecommender.domain.Menu;
import com.kakaohealthcare.pasta.mealrecommender.domain.MenuRepository;
import lombok.RequiredArgsConstructor;
import org.springframework.stereotype.Service;

@Service
@RequiredArgsConstructor
public class MenuDetailService {

    private final MenuRepository menuRepository;

    /**
     * 메뉴가 없으면 {@link MenuNotFoundException} 을 던집니다.
     */
    public MenuDetailOutDto getMenuDetailById(long menuId) {
        Menu menu = menuRepository.findById(menuId)
                .orElseThrow(() -> new MenuNotFoundException(menuId));
        return MenuDetailOutDto.from(menu);
    }
}
```

package com.kakaohealthcare.pasta.mealrecommender.web;

import com.kakaohealthcare.pasta.mealrecommender.application.MenuDetailOutDto;

import static org.assertj.core.api.Assertions.assertThat;

## 자기 검증 (스킬 체크리스트 중 해당 항목)

- 패키지·의존성: Web 은 `MenuDetailOutDto` 만 참조하고 `Menu` 를 직접 참조하지 않습니다. 기존 `MealRecommendResponse` 는 outDto 안의 `Menu` 를 꺼내 쓰는데, 신규 DTO 는 그 방식을 따르지 않고 원시값·String 으로 담았습니다.
- 예외 클래스는 `application/exception` 에 두었습니다(domain 이 `ExceptionConstants` 를 참조하지 않음).
- 컨트롤러 메서드는 `ResponseEntity` 반환, Swagger 어노테이션은 기존 `RecommendController` 에 없어 붙이지 않았습니다.
- `var`·와일드카드 import·FQCN·`@Data` 없음. 테스트는 AssertJ, `@DisplayName` 한글, 메서드명 영어.
- 코드 주석은 Javadoc 1건이며 존댓말("던집니다")입니다. 코드 블록 주석 줄을 따로 훑어 평서형 끝맺음 0건을 확인했습니다.
- 로깅: 신규 코드에서 직접 로그를 남기지 않습니다. 404 는 기존 `MealRecommenderExceptionHandler` 가 WARN 으로 기록합니다.
- Service 에는 판단 로직이 없고 조회와 변환만 합니다.

## 범위 밖 제안 (고치지 않았습니다)

- `GET /api/menus/abc` 처럼 숫자가 아닌 menuId 는 `MethodArgumentTypeMismatchException` 이 되어, 기존 `GlobalExceptionHandler.handleAny` 에서 500 으로 나갑니다. 400(`MR-400`)이 맞아 보이지만 공용 예외 핸들러 수정이라 승인 후 진행하겠습니다. 이 동작은 테스트로 고정하지 않았습니다.
- 응답에 `source`·`imageFile` 은 넣지 않았습니다(소비자 불명, YAGNI). 필요하면 알려 주세요.
- Swagger(`@Tag`·`@Operation`)는 이 프로젝트에 적용 사례가 없어 생략했습니다.
