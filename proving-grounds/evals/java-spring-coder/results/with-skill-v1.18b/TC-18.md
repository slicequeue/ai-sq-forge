# TC-18 with-skill (v1.18b)

투여 상태 응답 skippedCount 추가, 투여 건너뛰기 등록 API 구현 완료 (로컬, 커밋 전, 테스트 미실행)
- `Glp1InjectionStatusResponse`·`Glp1InjectionTimeStatusOutDto` 의 기존 `from()`/`empty()` 본문에 `skippedCount` 를 더했습니다. 새 팩토리는 만들지 않았습니다
- `POST /api/v1/glp1/injection-skips` 를 요청하신 경로 그대로 신규 4-Tier(domain·infrastructure·application·web)로 만들었습니다
- Repository 테스트는 Testcontainers 로 만들지 않고 pasta-api 모듈의 기존 H2 `@DataJpaTest` 로 작성했습니다
- 조직 컨벤션 적용 프로젝트로 판정했습니다 (TC 맥락). gradle·review-lint·spotless 는 실행하지 않았습니다

미확인: 위 테스트·lint 결과 전부, `SecurityMatcherContainer` 등록 위치(아래 결정 요청 2)

## 요청과 다르게 구현한 3건 (먼저 읽어 주세요)

| 요청 | 구현 | 근거 |
|------|------|------|
| 신규 클래스도 전부 `from()` | 신규 InDto·OutDto·Request·Response·Entity·JpaEntity 는 생성자 직접 호출(JpaEntity 는 생성자 `@Builder`). 변환은 Controller(Request→InDto, OutDto→Response)·Service(Entity→OutDto)·RepositoryImpl 이 합니다. 기존 `Glp1InjectionStatusResponse.from` 만 본문 수정 | `vc-conventions-guide.md` 3절 "정적 팩토리" 행: 신규 클래스는 조직 컨벤션, 이미 `from()` 이 있는 클래스는 기존 메서드를 고쳐 씀. 사용자 요청이어도 신규 클래스는 생성자 (org-conventions 2절) |
| Repository 테스트는 Testcontainers | `pasta-api/src/test/resources/application.yml` 이 H2(`jdbc:h2:mem:test;MODE=MySQL`)이고 기존 `@DataJpaTest`(`Glp1InjectionPlanScheduleJpaRepositoryTest`)도 H2 라서, 그 설정으로 `@DataJpaTest` 를 씁니다. Testcontainers 로 전환하지 않았습니다 | SKILL 하드 가드레일 "모듈의 기존 테스트 DB 설정 유지, 전환 금지", 가이드 3절 "테스트 DB" 행. 사용자가 명시했으므로 전환이 필요하면 별도 작업으로 합의가 필요합니다 (SC-3) |
| 변수명 짧게 쓰는 관례(`dto`) | 신규·수정 줄은 타입명 전체(`glp1InjectionTimeStatusOutDto`). 기존 `from(... dto)` 의 매개변수명은 이번 줄을 바꾸지 않는 한 두었는데, 본문을 고치므로 매개변수를 `glp1InjectionTimeStatusOutDto` 로 바꿨습니다 | SKILL 변수 네이밍 (축약 금지, 적용·비적용 공통) |

## 사전 확인 결과

확인한 것 (pasta-japan-server 읽기 전용 조회, 2026-11-13)
- 조직 컨벤션 적용 프로젝트. 이 프로젝트 맥락은 TC 가 명시했습니다
- 작업 계획서(`docs/plans`, `docs/tdd`)는 요청에 없어 모드 B 로 진행했습니다
- 기존 `Glp1QueryController` 는 `@RequestMapping("/pghd/v1/glp1")`, 응답은 DTO 직접 반환입니다. 기존 Command 컨트롤러는 `Glp1InjectionRecordCommandControllerV2`, `Glp1InjectionPlanCommandControllerV1` 등 `{Domain}CommandController` + 버전 접미사 패턴입니다
- 기존 repository 구현은 `glp1/infrastructure/persistence/{하위}/` 아래에 `*JpaEntity`·`*JpaRepository`·`*RepositoryImpl` 이 같이 있습니다
- 기존 예외는 `com.kakaohealthcare.moneyball.shared.exception.BadRequestException`/`NotFoundException` 입니다
- 코드 파일 첫 줄은 `// Copyright 2026 Kakao Healthcare Corp. All Rights Reserved.` 형식입니다 (최근 파일 연도 2026)

가정한 것 (재평가 트리거 포함)
- "최근 30일"은 요청 시각 `at` 을 사용자 타임존(`TimeZoneContext.getZoneId()`)으로 바꾼 날짜 기준 오늘 포함 30일(`at 날짜 - 29일 ~ at 날짜`)로 정했습니다. 트리거: 기획이 "오늘 제외 30일" 또는 서버 현재 시각 기준을 원하면 윈도우 계산 한 줄만 바꿉니다
- `reason` 은 선택 입력, 최대 200자로 했습니다(테이블 `VARCHAR(200)`, NOT NULL 여부는 마이그레이션 원문을 이번 세션에서 열지 못했습니다. 트리거: 컬럼이 NOT NULL 이면 Request 에 `@NotBlank`, JpaEntity 에 `@NotNull` 추가)
- 같은 날 중복 건너뛰기 등록은 막지 않았습니다(요청에 정책 없음, 테이블에 UNIQUE 언급 없음)
- 응답은 기존 create API 관례에 맞춰 200 으로 했습니다. 201 이 필요하면 `ResponseEntity.status(CREATED)` 한 줄입니다

## 작성 전 질문 5개 (RR-13·14)

1. `skippedCount` 조회가 실패하면 → 상태 조회 전체가 500 입니다. 같은 `@Transactional(readOnly = true)` 안의 조회라 `try/catch` 로 삼키면 rollback-only 가 전파돼 커밋 시점에 `UnexpectedRollbackException` 이 납니다. 격리하려면 `REQUIRES_NEW` 경계가 필요해 이번에는 하지 않았습니다. 인덱스 `COUNT` 단건이라 기존 투여 조회와 같은 위험 수준으로 봤습니다
2. 외부 호출 없음. 해당 없음
3. 마스터 데이터 없음. 건너뛰기 0건이면 `skippedCount = 0` 입니다
4. 기존 `GET /pghd/v1/glp1/injection-status` 응답에 필드가 하나 늘고 쿼리가 1건 추가됩니다. 공용 `OutDto.from`·`empty` 시그니처가 바뀌므로 호출처를 grep 해야 합니다(아래 "호출처" 참고). PR 본문 "기존 동작 변경"에 적어야 합니다
5. 분기 테스트: 서비스(0건·경계일 포함/제외), Response 매핑, Repository count 쿼리를 각각 만들었습니다

호출처
- `Glp1InjectionTimeStatusOutDto.from`·`empty` 의 모든 호출처를 `grep -rn "Glp1InjectionTimeStatusOutDto\.\(from\|empty\)" pasta-api/src` 로 확인하고 인자를 맞춰야 합니다(미실행). `inspectInjectionTime` 외 호출처가 나오면 그곳도 같은 방식으로 갱신합니다

```java

  private final Glp1InjectionSkipRepository glp1InjectionSkipRepository;

  // inspectInjectionTime 안에서, 기존 from(inspection) / empty(at) 호출 직전
  long skippedCount = countRecentSkips(at, userId);
  // ... Glp1InjectionTimeStatusOutDto.from(inspection, skippedCount)
  // ... Glp1InjectionTimeStatusOutDto.empty(at, skippedCount)

  private long countRecentSkips(Instant at, long userId) {
    LocalDate endDate = at.atZone(TimeZoneContext.getZoneId()).toLocalDate();
    LocalDate startDate = endDate.minusDays(RECENT_SKIP_DAYS - 1);
    return glp1InjectionSkipRepository.countByUserIdAndSkippedDateRange(
        userId, startDate, endDate);
  }
```

## 자기 점검 결과

- 주석 줄 확인: 이번 코드의 주석은 `// Given`·`// When`·`// Then`·Copyright 뿐이며 평서형 끝맺음 0건. 설명 주석은 넣지 않았습니다(RR-10)
- FQCN 없음, `var` 없음, `@Setter`·`@Data` 없음, 와일드카드 import 없음
- 변수명: 신규 코드에 `dto`·`req`·`saved`·`e`·`count`(단독) 없음. `Map` 은 `glp1InjectionSkipEntitiesById`
- 로그에 userId 없음, `[ClassName.methodName]` 접두사 있음
- 계층: domain 에 JPA·Spring 어노테이션 없음(`jakarta.annotation.Nullable` 만). application 이 infrastructure 를 import 하지 않음. web 이 domain 을 직접 참조하지 않음
- 새 컨트롤러 메서드는 `ResponseEntity` 반환. 신규 Controller 이름은 `Glp1InjectionSkipCommandController`(조직 컨벤션 `{Domain}CommandController`, 기존 Command 컨트롤러의 `V1` 접미사 관례와 다름 — 기존 관례는 버전 파생 컨트롤러용이라 신규에는 붙이지 않았습니다)
- 마이그레이션은 이미 적용돼 있어 건드리지 않았습니다
- 미확인: 체크리스트 중 gradle 결과가 필요한 항목(테스트 통과, spotless, review-lint 0건, 조직 컨벤션 검사 켜짐/꺼짐)

## 결정 요청

1. API 경로: 요청하신 `/api/v1/glp1/injection-skips` 로 구현했습니다. 같은 도메인의 기존 API 는 `/pghd/v1/glp1/...`, `/pghd/v2/glp1/...` 입니다. 경로를 바꾸지는 않았습니다(SC-3). `/pghd/v1/glp1/injection-skips` 로 맞출지 결정이 필요합니다. 앱이 이미 `/api/v1` 로 호출한다면 그대로 두면 됩니다
2. 보안 등록: 신규 엔드포인트는 인증·허용 목록 등록이 필요합니다. 이번 세션에서 `SecurityConstants airArray` 를 찾지 못했고(grep 결과 `SecurityMatcherContainer`·`SecurityConfiguration` 만 확인), `/api/**` 경로가 기존 필터 체인에 걸리는지는 확인하지 못했습니다. 등록 위치 확인 전에는 이 API 가 동작한다고 단정하지 않습니다(미확인)
3. Testcontainers 전환: 이 모듈 테스트를 Testcontainers 로 옮기는 것은 모듈 전체 설정 변경이라 이번 범위에서 제외했습니다. 필요하면 별도 작업으로 범위·Docker CI 영향을 먼저 합의하겠습니다

## 범위 밖 제안 (고치지 않음)

- `Glp1QueryController.getInjectionStatus` 는 `ResponseEntity` 없이 Response 를 직접 반환합니다(조직 컨벤션과 다름). 이번에는 건드리지 않았습니다
