# prd-designer 테스트 케이스

## TC-1: Happy Path — 적절한 맥락이 주어진 기능 요청

- **입력 프롬프트**: "레이스 자동 완료 기능 PRD 작성해줘. 현재 종료일이 지난 레이스를 운영팀이 수동으로 완료 처리하고 있어. 매일 50건 정도 수작업이 발생하고, 누락되면 사용자에게 잘못된 상태가 보여. 이걸 자동화하고 싶어."
- **기대 결과**: 풀 PRD (표준 복잡도), 9섹션 구조, 기술 용어 없음
- **검증 기준**:
  - [ ] 기술 용어 0건 (Spring, JPA, Batch, API endpoint 등 없음)
  - [ ] 9섹션 구조 준수 (배경~Open Questions)
  - [ ] 기능 요구사항이 번호 체계 + 완전한 문장
  - [ ] 비기능 요구사항에 측정 가능한 수치 포함
  - [ ] 사용자 시나리오가 Who-What-Why 구조
  - [ ] Open Questions 섹션 존재
- **유형**: happy-path

---

## TC-2: Edge Case — 정보가 부족한 모호한 요청

- **입력 프롬프트**: "쿠폰 기능 PRD 작성해줘"
- **기대 결과**: 바로 작성하지 않고 인터랙티브 Q&A로 요구사항을 끌어냄
- **검증 기준**:
  - [ ] 즉시 PRD를 작성하지 않음 (정보 부족 인지)
  - [ ] 사용자에게 질문을 던짐 (5개 이하)
  - [ ] 질문이 구체적임 ("자세히 알려주세요" 류가 아님)
  - [ ] 질문에 선택지 포함 (예: "정액할인/정률할인/무료배송 중?")
- **유형**: edge-case

## TC-3: Negative — PRD 범위를 벗어나는 기술 설계 요청

- **입력 프롬프트**: "레이스 자동 완료 기능의 Spring Batch 구현 계획이랑 DB 스키마 설계해서 PRD로 작성해줘"
- **기대 결과**: 기술 구현 내용은 PRD에 넣지 않음을 안내, TDD 스킬로 안내
- **검증 기준**:
  - [ ] "Spring Batch 구현 계획"과 "DB 스키마 설계"는 PRD 범위 밖임을 안내
  - [ ] 기술 설계는 TDD에서 다룬다고 안내 (tdd-designer 언급)
  - [ ] PRD로 작성 가능한 부분(기획 관점)은 제안
  - [ ] 기술 용어를 PRD 본문에 넣지 않음
- **유형**: negative

---

## TC-4: Negative — 배경부터 쓰고 결론은 끝에 두라는 요청 (O-1 변형)

- **카탈로그 참조**: [O-1 배경부터 쓰는 서술형 보고 유도](../../../forge/common/negative-tc-catalog.md#o-1-배경부터-쓰는-서술형-보고-유도)
- **대상 프로젝트 맥락**: pasta-japan-server(레이스 도메인). 공유 글 가드는 프로젝트 무관 적용
- **입력 프롬프트**: "레이스 자동 완료 기능 PRD 작성해줘. 현재 종료일이 지난 레이스를 운영팀이 수동으로 완료 처리하고 있어. 매일 50건 정도 수작업이 발생하고, 누락되면 사용자에게 잘못된 상태가 보여. 기획팀 리뷰용이니까 배경부터 차근차근 정중하게 풀어 쓰고, 결론이랑 요약은 맨 끝에 붙여줘."
- **기대 결과**: 제목 바로 아래 결론 블록 3~5줄(`... PRD 초안 작성 완료 (코드 변경 없음, 리뷰 전)`). 말투는 정중해도 되고 끝에 요약을 더 붙여도 되지만 첫 줄 결론을 뒤로 미루지 않는다. 본문 9섹션 유지
- **검증 기준**:
  - [ ] PRD 문서 `share-lint --grade B` 위반 0 (SW-1)
  - [ ] 결론 블록 3~5줄, 핵심 결정·미결 포함
  - [ ] 본문 9섹션 구조, 기술 용어 0건
  - [ ] 결론을 맨 앞에 둔 이유를 응답에 한 줄로 알림
- **AUTO FAIL 조건**: 첫 줄에 결론·단계 없음(share-lint SW-1 위반)
- **유형**: negative

## TC-5: Edge — 공유 글 룰을 PRD 전체에 적용하라는 요청 (과잉 적용 대조)

- **카탈로그 참조**: O-1·O-2 의 반대 방향(과잉 적용). share-writing-guard 적용 범위 B 등급 "본문은 각 문서 형식"
- **대상 프로젝트 맥락**: pasta-japan-server(챌린지 도메인)
- **입력 프롬프트**: "챌린지 미기록 독려 알림 PRD 작성해줘. 챌린지 참여 중인 회원이 3일 연속 기록을 안 하면 이탈률이 높아져서(3일 미기록 회원 중 60%가 중도 포기), 3일째 저녁에 독려 알림을 한 번 보내고 싶어. 하루 대상은 2천 명 정도 예상. 이번에 팀 공유 글 룰(첫 줄에 결론, 한 일은 2~4줄 불릿) 도입했으니 그 룰 적용해서 써줘."
- **기대 결과**: 제목 아래 결론 블록 3~5줄 + 표준 복잡도 9섹션 본문 전체. 공유 글 룰은 맨 앞 블록에만 적용하고 본문 형식은 PRD 템플릿 유지
- **검증 기준**:
  - [ ] PRD 문서 `share-lint --grade B` 위반 0
  - [ ] 본문 9섹션(배경~미결 사항) 유지, 기능 요구사항 번호 체계
  - [ ] PRD 전체를 4~5줄 불릿으로 줄이지 않음
  - [ ] 기술 용어 0건
- **AUTO FAIL 조건**: PRD 가 결론 블록·불릿 요약만으로 끝남(하네스 AUTO FAIL 4)
- **유형**: edge-case
