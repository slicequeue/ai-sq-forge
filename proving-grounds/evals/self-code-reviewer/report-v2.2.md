### 미충족 항목 분석

RR-5 지적의 내용은 "`catch (BaseRuntimeException | NumberFormatException e)` 가 서로 인과가 다른 두 예외를 한 덩어리로 묶어 동일하게 처리한다"였다. 이는 RR-5 의 **후반부(원인 분리)**에 해당한다.

그러나 이 코드의 실제 결함은 **전반부(상속 관계)**다. `NumberFormatException` 은 `IllegalArgumentException` 의 하위이므로, "잘못된 인자" 전반을 잡으려는 의도라면 상위 타입인 `IllegalArgumentException` 이 이 catch 를 타지 않는다. 응답 전문에 `IllegalArgumentException` 이라는 단어와 상속 관계 설명이 **한 번도 나오지 않았다.**

원인은 스킬 본문 서술 방식이다. v2.1 의 RR-5 검사 항목은 상속 관계와 원인 분리를 한 문단에 병렬로 나열했고, 에이전트가 뒤쪽만 집었다.

### 조치 — v2.2

검사 항목을 두 갈래로 분해하고 대표 조합 3종을 명시했다.

- (1) 상속 관계 — 나열한 예외들의 상하위 관계를 실제로 확인하고, 잡으려는 대상이 나열된 타입의 상위면 잡히지 않는다는 사실을 지적에 명시한다
- (2) 원인 분리 — 클라이언트 잘못과 인프라 장애를 한 덩어리로 처리하지 않는다
- (1)을 건너뛰고 (2)만 쓰면 부분 검출로 본다고 명시

## 3. 부수 발견 — changelog 누락

버전을 2.0 → 2.1 로 올릴 때 changelog 항목이 기록되지 않았다. 이 파일의 `changelog` 가 YAML 블록 스칼라(`|`) 형식인데 갱신 스크립트가 인용 문자열 형식만 처리했기 때문이다. v2.1·v2.2 항목을 모두 복구했다.

같은 오류를 전체 대상 15개 파일에 대해 검사했고, `java-performance-reviewer` 1건이 추가로 발견돼 함께 복구했다. 나머지 13건은 정상이다.
