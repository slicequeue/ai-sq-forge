### 실패·회귀 한 줄 답 (RR-13·RR-12)

- **실패 시 사용자가 보는 것 (홈 카드)**
  - 일정이 없는 사용자는 마지막 주사 기록이 있어도 카드가 `NO_RECORD` 로 나옵니다. 정상 상태인 "일정 없음"이 장애와 같은 응답이 됩니다.
  - 트랜잭션 상황에서는 이 try-catch 로도 500 을 못 막을 가능성이 높습니다(필수 수정 #1).
  - `getMaxDoseByBrand` 는 try 밖이라 `max_dose_mg` 가 null 인 브랜드가 하나만 있어도 홈 피드 카드 계산이 전부 500 입니다.
- **실패 시 사용자가 보는 것 (푸시 예약)**
  - 3번째 플랜에서 실패하면 DB 는 전부 롤백되고 예외가 호출자로 전파됩니다. 앞선 2건은 외부 푸시 서버에는 예약이 살아 있는데 DB 에는 `reservationId` 가 없습니다.
  - 재시도하면 같은 사용자에게 푸시가 중복 예약됩니다.
- **깨뜨리면 실패할 테스트**: 이번 변경에는 테스트가 보이지 않아 지목할 수 없습니다. 바뀐 분기 중 `PlanNotFoundException` 처리를 지우거나 바꿔도 실패할 테스트가 없다는 뜻입니다. 필요한 테스트는 필수 수정 #1 에 적었습니다.
