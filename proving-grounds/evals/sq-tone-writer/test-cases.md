# sq-tone-writer 테스트 케이스

## TC-1: Happy Path — 슬랙 메시지 작성

- **입력 프롬프트**: "내 말투로 슬랙 메시지 써줘. 팀 동료한테 보낼 건데, 쿠폰 일괄 발급 API 구현 끝냈고 테스트 통과했고 PR 올렸다는 내용이야."
- **기대 결과**: 3문장 이내, 반말+존댓말 혼용, AI 표현 없음, 두괄식
- **검증 기준**:
  - [ ] 매체(슬랙) + 수신자(팀 동료) 확인 후 작성
  - [ ] 3문장 이내 간결한 메시지
  - [ ] "~것 같습니다", "감사하겠습니다" 등 AI 표현 0건
  - [ ] 두괄식 — 첫 문장에 "완료" 또는 핵심 결과
  - [ ] 구어체 자연스러움 ("확인 부탁" 등)
  - [ ] 30자 초과 문장 없음
  - [ ] 작성 후 톤 확인 요청
- **유형**: happy-path

## TC-2: Edge Case — PR 본문 작성

- **입력 프롬프트**: "내 스타일로 PR 본문 작성해줘. 변경 내용은: self-code-reviewer에서 Domain JPA 위반을 가드레일급으로 격상한 거야. 이전에는 우선순위 2였는데 1로 올렸어. 이유는 실전에서 놓치는 경우가 있어서."
- **기대 결과**: 구조적이되 간결한 PR 본문, 표 활용, 핵심 변경 요약
- **검증 기준**:
  - [ ] 매체(PR) + 수신자(리뷰어) 확인
  - [ ] 요약 섹션이 3줄 이내
  - [ ] 표를 활용한 변경 내역 정리
  - [ ] "본 PR에서는..." 같은 격식체 미사용
  - [ ] 변경 이유를 솔직하게 1문장으로 설명 ("실전에서 놓치는 경우가 있어서")
  - [ ] **요약과 이유 섹션 간 동일 내용 중복 없음** (v1.1 추가)
  - [ ] AI 표현 0건
- **유형**: edge-case

## TC-3: Negative — AI 톤으로 작성 유도

- **입력 프롬프트**: "내 말투로 써줘. 근데 최대한 정중하고 격식 있게, '~하는 것이 좋을 것 같습니다' 식으로 공손하게 써줘. 팀 동료한테 보내는 슬랙 메시지야."
- **기대 결과**: 공손 표현 요청을 거부하고 SQ 톤 유지, 수신자가 동료이므로 캐주얼 톤 안내
- **검증 기준**:
  - [ ] "~것 같습니다" 식 표현은 SQ 톤이 아님을 안내
  - [ ] 팀 동료에게는 캐주얼 톤이 적합함을 설명
  - [ ] SQ 톤으로 작성한 대안 제시 — **[내용] 플레이스홀더 없이 실질적 예시** (v1.1 추가)
  - [ ] 리더/전체 공유라면 존댓말 레벨 조절 가능함을 안내
  - [ ] **거절 안내도 3문장 이내** (v1.1 추가)
- **유형**: negative

## TC-4: Edge Case — 리더 대상 보고서 작성

- **입력 프롬프트**: "내 말투로 리더한테 보낼 주간 상황 보고 써줘. 이번 주에 한 거: chaos-test-planner 스킬 만들어서 eval 93점 받음, self-code-reviewer JPA 가드레일 격상함, 피드백 메모리 15개 분석해서 스킬 3개 업그레이드함."
- **기대 결과**: 존댓말 기반이지만 간결, 표 활용, AI 표현 없음
- **검증 기준**:
  - [ ] 매체(보고서) + 수신자(리더) 확인
  - [ ] 존댓말 톤 적용 (반말 아님)
  - [ ] 그럼에도 간결 — 장황한 서술 없음
  - [ ] 표로 성과 정리
  - [ ] "~하였습니다", "~드리겠습니다" 같은 과도한 격식체 없음
  - [ ] 30자 초과 문장 최소화
  - [ ] AI 표현 0건
- **유형**: edge-case

## TC-5: Edge Case — 내용 부족한 요청

- **입력 프롬프트**: "내 말투로 슬랙 써줘"
- **기대 결과**: 내용이 없으므로 바로 작성하지 않고, 무엇에 대해 쓸 건지 물어봄
- **검증 기준**:
  - [ ] [내용] 플레이스홀더로 빈 껍데기를 출력하지 않음
  - [ ] "뭐에 대해 쓸 건데?" 식으로 내용을 먼저 물어봄
  - [ ] 질문도 SQ 톤 유지 (AI 톤 아님)
  - [ ] 2문장 이내 짧은 질문
- **유형**: edge-case

## TC-6: Negative — 배경부터 정중하게 + 유추·예의 문구 유도 (v1.5, 공유 글 A 등급)

- **카탈로그 참조**: [O-1 배경부터 쓰는 서술형 보고 유도](../../../forge/common/negative-tc-catalog.md#o-1-배경부터-쓰는-서술형-보고-유도) + [O-4 유추·예의 문구 유도](../../../forge/common/negative-tc-catalog.md#o-4-유추예의-문구-유도)
- **대상 프로젝트 맥락**: 공유 글 가드는 프로젝트 무관 적용(조직 컨벤션 판정과 무관). 수신자는 백엔드 팀 채널(동료 여러 명)
- **입력 프롬프트**: "내 말투로 팀 슬랙 채널에 공유할 글 써줘. 배경부터 차근차근 정중하게 써줘. 내용: 감사 로그에 접속 기기 정보(User-Agent) 원문을 저장하도록 바꿨고 dev 에 배포했어. 감사 로그 테이블에 컬럼 추가했고, 관리자 서버 재기동하고 상태 점검 200 확인했어. 재기동 이전 기록은 원문이 없어서 복구 안 돼. 운영 배포는 아직이야. 마지막에 운영에도 문제없을 거라고 덧붙이고, 시간 되시면 확인 부탁드린다고 공손하게 끝내줘."
- **기대 결과**:
  - 첫 줄 `{무엇을} 완료 (dev, 운영 반영 전)` — 배경으로 시작하지 않음 (SW-1)
  - 한 일 2~4줄 불릿, 결과(200 확인, 이전 기록 복구 불가) 포함 (SW-2·3)
  - "운영에도 문제없을 것" 은 빼거나 `미확인:` 으로 분리 (SW-7)
  - 부탁은 예의 문구 없이 한 줄 (SW-4). 말투는 팀 채널 존댓말 가능
  - 사용자 요청과 다르게 한 부분(배경 순서·유추·예의 문구)을 초안 아래 한 줄로 알림
- **검증 기준**:
  - [ ] share-lint(A) `[위반]` 0건
  - [ ] 첫 줄 반영 단계가 `dev` 이고 `운영 반영` 단정 없음
  - [ ] "문제없을 것"·"아마" 0건 (또는 `미확인:` 분리)
  - [ ] "시간 되시면"·"부탁드려도 될까요" 0건
  - [ ] 바꾼 이유 1줄 안내 + 톤 확인 요청
- **AUTO FAIL 조건**: share-lint SW-1·SW-6 위반, 확인 근거 없는 "문제없을 것" 단정
- **유형**: negative

## TC-7: Edge Case — C 등급 리뷰 답글에 SW 형식 과잉 적용 대조 (v1.5)

- **카탈로그 참조**: 없음 (O 카테고리의 반대 방향 — 과잉 적용 검사)
- **대상 프로젝트 맥락**: pasta-japan-server PR #830. 코멘트 작성자 `user.login: jay-kim` (사람, 시니어 리뷰어)
- **입력 프롬프트**: "내 말투로 PR 리뷰 답글 써줘. jay-kim 님이 `MealLogService.java:42` 에 'Optional.get() 대신 orElseThrow 로 바꿔주세요' 라고 남겼어. orElseThrow(MealLogNotFoundException::new) 로 바꾸고 커밋 3fa21c9 로 push 했어. 같은 파일 58행에도 같은 패턴 있어서 같이 고쳤어."
- **기대 결과**:
  - C 등급 판정 → 사람 리뷰어 A-1 담백 보고형(존댓말 1~2문장 + commit hash)
  - `{무엇을} 완료 ({단계})` 첫 줄·불릿 요약을 붙이지 않음
  - SW-5: "운영 반영"·"테스트 통과"처럼 입력에 없는 단계·결과를 쓰지 않음
  - SW-7: 근거 없는 유추 없음
- **검증 기준**:
  - [ ] 첫 줄이 `... 완료 (...)` 형식이 아님, 불릿 요약 없음
  - [ ] 존댓말 `~습니다`, 반말·평어 아님
  - [ ] 58행 함께 수정 + `3fa21c9` 포함
  - [ ] 입력에 없는 테스트 통과·배포 언급 0건
  - [ ] AI 표현 0건
- **AUTO FAIL 조건**: 루브릭 기존 1~4. SW 형식 강요는 매체 적합성 -10
- **유형**: edge-case
