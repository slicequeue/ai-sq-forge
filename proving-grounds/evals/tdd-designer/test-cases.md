# tdd-designer 테스트 케이스

## TC-1: Happy Path — PRD 기반 TDD 작성 요청

- **입력 프롬프트**: "아래 PRD를 기반으로 TDD를 작성해줘.\n\n## PRD 요약: 레이스 자동 완료\n- 배경: 종료일 지난 레이스를 운영팀이 수동 완료 처리 중 (일 50건)\n- 목표: 자동화하여 수작업 0건 달성\n- FR-1: 매일 자정, 종료일이 지난 진행 중 레이스를 자동 완료 처리\n- FR-2: 완료 처리된 레이스 참여자에게 알림 발송\n- FR-3: 이미 완료/취소 상태 레이스는 제외\n- NFR-1: 처리는 서비스 피크 외 시간에 실행\n- NFR-2: 10,000건 이상도 30분 내 처리"
- **기대 결과**: 풀 TDD (표준 복잡도), Phase별 TODO에 패키지 경로/클래스명 포함
- **검증 기준**:
  - [ ] PRD 소스가 문서 내 명시됨
  - [ ] Phase TODO에 패키지 경로 + 클래스명 있음
  - [ ] 아키텍처 적합성 분석 포함
  - [ ] 테스트 전략 (계층별) 포함
  - [ ] 커밋 계획 + 대상 파일 목록 포함
  - [ ] 구현 워크플로 명시
- **유형**: happy-path

---

## TC-2: Edge Case — PRD 없이 TDD 요청

- **입력 프롬프트**: "쿠폰 기능 TDD 작성해줘"
- **기대 결과**: PRD 소스 부재를 인지하고 대안 제시 (PRD 먼저 작성 안내 또는 코드 분석 제안)
- **검증 기준**:
  - [ ] PRD 없음을 인지
  - [ ] 대안 제시 (prd-designer 안내 또는 코드 분석 제안)
  - [ ] PRD 소스 없이 추측으로 TDD를 작성하지 않음
- **유형**: edge-case

---

## TC-3: Negative — 가드레일 위반 유도 (H2 사용 제안)

- **입력 프롬프트**: "레이스 자동 완료 TDD 작성해줘. 테스트는 H2 인메모리 DB로 빠르게 돌리는 게 좋겠어. PRD는 docs/prd/race-auto-completion-prd.md에 있어."
- **기대 결과**: H2 사용 요청을 거부하고 Testcontainers(MySQL) 원칙 안내
- **검증 기준**:
  - [ ] H2 사용을 거부 또는 Testcontainers 원칙 안내
  - [ ] Testcontainers(MySQL) 사용을 TDD에 반영
  - [ ] 가드레일 위반 없이 TDD 작성 (또는 안내 후 진행)
- **유형**: negative
