## 평가 모드

**시뮬레이션 입력 평가.** 실제 `gcloud logging read` 는 호출하지 않는다. 테스트 케이스가 제공하는 집계 결과(로거별 건수, message 시그니처, 시각 분포, 단건 스택, revision_name)를 조회 산출물로 간주하고, 스킬이 산출하는 **조회·집계 명령 + 판정 근거 + 보고서 본문 + 사용자 응답 텍스트**를 평가한다.

파일 쓰기도 하지 않는다. 보고서 본문은 응답 내에 제시된 것을 대상으로 채점하며, 파일명 규약은 스킬이 선언한 이름으로 검증한다.

## AUTO FAIL 규칙

| # | 규칙 | 감지 기준 |
|---|------|-----------|
| 1 | 로그 없이 보고서 작성 | 인증 차단·데이터 미제공 상태에서 유형별 상세·집계표 본문을 작성 |
| 2 | 집계 기준 미명시 | 개요에 `jsonPayload.level`(앱) vs `severity`(인프라) 표기 없음 |
| 3 | 시각 변환 오류·단독 표기 | UTC↔KST 환산 방향 오류, 또는 한쪽 타임존만 표기 |
| 4 | 로그 건수 = 실패 이벤트 수 단정 | 중복 로깅 확인 없이 로그 줄 수를 장애 건수로 서술 |
| 5 | 카탈로그 미대조 전건 신규 | 카탈로그 제공됐는데 대조 없이 전부 "신규"로 판정 |
| 6 | 근거 링크 전무 | 유형별 딥링크·재현 쿼리가 0건 |
| 7 | 사실·판단 혼재 | 실측·검증 없는 추정을 확정 서술 |
| 8 | 장식 기호 잔존 | 이모지·★·✅ 등 1개 이상 |
| 9 | PII 과다 노출 | 이메일·전화번호·이름 포함, 또는 식별자 대량 나열 |
| 10 | 후처리 실패를 데이터 유실로 보고 | `AFTER_COMMIT` 후처리 실패를 원본 유실로 서술 |

## 6축 평가 기준

### 축 1. 가드레일 준수 (GATE)

- AUTO FAIL 10건 모두 0
- 위반 시 즉시 FAIL 판정 (다른 축 점수 무관)

### 축 2. 기능 정확도 (100점 만점, evaluation-rubric.md 기반)

| 항목 | 배점 |
|------|------|
| Phase 0 파라미터 확정 | 15 |
| 시각 변환·병기 정확도 | 15 |
| 로그 건수 vs 실패 이벤트 수 분리 | 15 |
| 카탈로그 대조 판정 | 15 |
| 사실·판단 분리 + 근거 링크 | 15 |
| 보고서 구조·서식 | 15 |
| 판정 원칙 준수 | 10 |

### 축 3. 행동 패턴

| 항목 | 확인 내용 |
|------|-----------|
| Phase 0 파라미터 확정 | 프로젝트·리전·서비스·집계 기준·구간·카탈로그 6개 |
| Phase 0.5 인증 확인 | 조회 전 인증 점검 명령 제시. 차단 시 사용자 유도 |
| 구간 환산 | UTC RFC3339 고정 + KST 병기 |
| 중복 로깅 판별 | 초 단위 시각 × 로거 조합 분석 |
| 카탈로그 대조 | 시그니처 표 대조 + 신규 유형 추가 제안 |
| 상세 조회 | 신규·사용자 대면 유형에 대해 스택·리비전 확인 |
| 딥링크 | 유형별 자기설명형 링크 |
| 검수 스캔 | `formal-doc-ko` grep 3종 실행 보고 |
| 자기 검증 | 12항목 체크리스트 수행 |

### 축 4. Baseline 비교

- Baseline (스킬 미사용): 로거별 건수를 그대로 나열, 로그 줄 수 = 장애 건수로 보고, 시각은 한쪽 타임존, 기존/신규 구분 없음, 딥링크 없음, 이모지 섹션 헤더
- With-Skill: 파라미터 확정 + 중복 로깅 분리 + 카탈로그 대조 + 딥링크 + 7섹션 + 사실·판단 분리
- 합격: With-Skill > Baseline + 20점

### 축 5. 일관성

- TC-1 `--repeat 3` 권장
- 편차 ≤ 15점

### 축 6. 효율성

- 기록용 (합격 조건 아님)
- 토큰 사용량 / 응답 시간
